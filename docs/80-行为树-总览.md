# 80 · 行为树（BT）总览

## 职责

可视化编辑行为树 → 导出为不可变 Blob → 按 `TreeId` 注册 → 由 ECS 系统对实体逐帧驱动。

整条链路：

```
BTTreeAsset（画布编辑）
    ↓  BTBlobBuilder.Build
BTRootBlob（纯数据树，Blob）
    ↓  BTManager.Register(treeId, blobRef)
注册完成
    ↓  BTInterpreterSystem（ISystem）对挂 RunningBT 的实体
逐帧 Tick → BTInterpreter 指针遍历
```

---

## 两种驱动方式

| 方式 | 入口 | 适用 |
| --- | --- | --- |
| **ECS（推荐）** | `BTInterpreterSystem`（`ISystem`），自动对挂 `RunningBT{TreeId}` 的实体 Tick | DOTS / ECS 项目 |
| **非 ECS** | `BTManager` + `BTEventBus` + `BTNodeRuntimeRegistry` 手动驱动 | 纯 MonoBehaviour 场景 |

两者共用同一份 `BTRootBlob` 与同一个 `BTInterpreter`，差别只在"谁调用 Tick、状态存在哪"。

> 非 ECS 路径目前与 ECS 路径并存，是否长期保留待定。

---

## 数据模型：`BTTreeAsset`

位于 `Editor/BT/BTTreeAsset.cs`（编辑器侧资产）：

| 字段 | 说明 |
| --- | --- |
| `TreeId` (`long`) | 树唯一 ID，运行期按它注册与查找 |
| `Kind` (`BTTreeKind`) | `Skill` / `AI` / `Other`，用于节点语义分区 |
| `AttributeEnumScript` | 属性枚举脚本（树节点里的属性下拉使用它） |
| `Nodes` (`List<BTNodeData>`) | 节点：`NodeId`、`Type`、`Position`、`Note`、三个参数池 |
| `Connections` (`List<BTConnectionData>`) | 连线：`SourceNodeId` → `TargetNodeId` + `PortIndex`（决定子节点顺序） |
| `Blackboard` (`List<BTBlackboardParam>`) | 黑板定义：`Key` / `ValueType` / `DefaultValue` |

节点参数用三个定长池：`FloatParams` / `LongParams` / `StringParams`，**每个节点类型占用的参数槽位有明确约定**（见枚举注释，如 `Repeat` 的 `Long[0]` 是重复次数）。

## 节点类型全景

按 `BTNodeType` 分类（共 40+ 种，含从 NodeCanvas 移植的组合/装饰节点）：

### 入口 / 出口
| 节点 | 语义 |
| --- | --- |
| `Root` | 树的唯一入口，转发其唯一子节点结果 |
| `End` | 显式终止，返回 `Success`（技能流程提前结束） |

### 组合节点（有子节点）
`Sequence`（顺序，子节点 Failed 短路）· `Selector`（选择，子节点 Success 短路）· `Parallel`（并行，按策略汇总）· `RandomSelector` / `RandomSequence`（随机序，种子持久化）· `FlipSelector`（成功的子节点移到末尾）· `UtilitySelector`（按权重选最高）· `ProbabilitySelector`（按权重概率选，失败换下一个）· `StepSequencer`（一次只跑一个子节点）· `Switch`（按 int case 选一个）· `BinarySelector`（按条件二选一）

### 装饰节点（包一个/两个子节点）
`Invert` · `Repeat`（重复 N 次，跨帧续跑）· `UntilSuccess` · `UntilFail` · `AlwaysSuccess` · `AlwaysFail` · `CooldownGate` · `Conditional` · `TimeLimit` · `Timeout` · `WaitUntil` · `Guard`（跨分支令牌互斥）· `Interruptor`（条件为真中断子树）· `Filter`（冷却/限次）· `Iterator`（遍历列表）· `Monitor`（监测动作）· `Optional`（返回 Optional，父组合忽略成败）· `Remapper`（重映射成败）

### 条件 / 动作（叶子）
条件：`CheckDistance` · `CheckBlackboard` · `CheckEvent`
动作：`Wait` · `NoOp` · `SendEvent`

### 特殊 / 扩展
`SubTree`（执行另一棵树，`Long[0]` = 目标树 ID）· `GameCustom = 128`（游戏层注册，见 83 篇）

## 参数槽位约定（节选）

| 节点 | 参数 |
| --- | --- |
| `Sequence` / `Selector` | `Long[0]` bit0 = dynamic（每帧从 0 重估高优先级子节点） |
| `Parallel` | `Long[0]` = policy（0 FirstFailure / 1 FirstSuccess / 2 FirstSuccessOrFailure）；`Long[1]` = dynamic |
| `Repeat` | `Long[0]` = 次数（≤0 无限） |
| `Conditional` | `Long[0]` = 条件不满足时返回的状态；`Long[1]` = dynamic |
| `Switch` | `Long[0]` = case 黑板键（0 = 用 `Long[1]` 字面）；`Long[2]` = dynamic；`Long[3]` = 越界模式 |
| `SubTree` | `Long[0]` = 目标树 ID |
| `SendEvent` / `CheckEvent` | `Long[0]` = 事件 key 哈希；`Long[1]` = 范围（0 本实体 / 1 全局） |

完整的槽位约定以 `BTNodeType.cs` 的注释为准——**改节点参数前先读那里的注释**。

## 注意事项 / 坑

1. **`Root` 必须唯一且必须连线**——没有 Root 或 Root 未连线，`BTBlobBuilder.Build` 会直接失败并打 `LogError`。
2. **`BTNodeType` 是 `byte` 枚举，新增类型必须追加在末尾**——插在中间会让旧的 `BTTreeAsset` 序列化错位（枚举注释里明确写了这条）。
3. **节点跨帧状态靠 `BTNodeRuntimeState` 持久化**（上次运行子索引、finished 掩码、重复计数、随机种子），不是存在节点上。
4. **`GameCustom` 节点走托管路径**（委托 + 反射注册），**不参与 Burst 编译**；纯内建节点的树才是指针遍历、无托管分配。
5. **移动/改名 `BTTreeAsset` 不影响引用**——运行期按 `TreeId` 查找，不按路径。但**改 `TreeId` 会断引用**。
