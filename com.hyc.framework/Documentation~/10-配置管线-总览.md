# 10 · 配置管线（Config）总览

## 职责

把 Excel / 模板定义的配置表，在**生成期**烘焙成不可变 Blob，**运行期**以世界无关的静态表提供无分配查询。

一句话：**编辑期是 ScriptableObject + 生成的代码，运行期只有一个 Blob 指针。**

---

## 全链路

```
① 配置模板 ConfigTemplate        定义表结构与字段
        ↓  （Editor：代码生成）
② 生成的 C# 类 [CfgAsset]        blittable struct，命名空间 {root}.config（root 见 HYC Settings → CodeGen）
        ↓  （Editor：数据编辑器填数据）
③ 配置资产 .asset                每行一个数据条目
        ↓  （Editor：导出）
④ BlobAssetReference<BlobRoot<TRow>>
        ↓  （Bootstrap：注册）
⑤ ConfigManager 静态表
        ↓  （运行期：查询）
⑥ 玩法系统 / UI 直接 Get<T>(id)
```

---

## 核心类

| 类 | 位置 | 职责 |
| --- | --- | --- |
| `ConfigTemplate` | Runtime | 表结构模板（本身也是一个配置资产 `模板/配置模板`，可在数据编辑器里重新打开再生成） |
| `ConfigTemplateField` | Runtime | 单个字段定义：类型、列表、导出目标、检查规则、客户端/服务端导出设置 |
| `ConfigManager` | Runtime | 运行期静态表，按行类型注册与查询 |
| `ConfigBlobTable<TRow>` | Runtime | 单张表（内部持有 `BlobArray<TRow>`） |
| `BlobTable` | Runtime | Blob 构建/读取辅助 |
| `IConfigIdProvider` | Runtime | ID 分配策略（`LocalConfigIdProvider` / `NetworkConfigIdProvider`） |
| `ConfigGenerator` | Editor | 由模板生成 C# 类 |
| `ConfigExportService` | Editor | 把数据烘焙成 Blob 并导出（客户端/服务端可分开） |
| `ConfigValidator` | Editor | 校验（`HYC Framework/Config/Validate Config`） |

## 运行期查询 API

```csharp
// 注册（Bootstrap / A1 阶段做一次）
ConfigManager.Register(myTable);                 // ConfigBlobTable<TRow>

// 查询
if (ConfigManager.TryGet<FashionRow>(1001, out var row)) { /* ... */ }
var row2 = ConfigManager.Get<FashionRow>(1001);  // 找不到返回 default
bool exist = ConfigManager.Contains<FashionRow>(1001);
var all = ConfigManager.GetAllRows<FashionRow>();   // BlobArray<TRow>，表未注册返回 default
bool has = ConfigManager.Has<FashionRow>();

// 物化托管包装（带缓存，避免重复装箱/构造）
var vm = ConfigManager.Materialize<FashionVM, FashionRow>(1001, r => new FashionVM(r));

// 清空（切场景/重进游戏时）
ConfigManager.Clear();   // 会对 IDisposable 的表调用 Dispose
```

### 要点

- **泛型参数是行类型 `TRow`，约束 `unmanaged`**——行必须是 blittable 结构体。
- **`Get` 找不到不抛异常**，返回 `default`；需要区分"没这条"时用 `TryGet` / `Contains`。
- **`Materialize` 有对象缓存**，`Register` 时会 `Clear()` 掉——注册全部完成后再开始查询，避免缓存被中途清掉。
- **不需要 World 句柄**，UI 层可以直接查。

## 模板（ConfigTemplate）字段

| 字段 | 说明 |
| --- | --- |
| `displayName` | 显示名，支持 `分类/名称`，如 `装备/时装` |
| `className` | 生成的 C# 类名，如 `FashionConfig` |
| `lastGeneratedClassName` | 上次生成时的类名，用于检测改名并触发改名处理（`HideInInspector`） |
| `baseTemplate` | 基类模板，生成的类继承它；基类字段以只读展示 |
| `iconBuiltInName` | 内置图标名（`EditorGUIUtility.IconContent`） |
| `iconCustom` | 自定义图标（项目内 `Texture2D`），优先级更高 |
| `fields` | 字段列表 |

**图标传播**（`Editor/DataEditor/ConfigIconApplier.cs`）：模板图标会同步到 Unity 原生 Project 窗口的**生成类型 MonoScript（类级）**——该模板生成的全部配置资产经类图标继承显示。注意 `EditorGUIUtility.SetIconForObject` 只接受 GameObject / MonoScript，传 ScriptableObject 实例时图标会记到该实例的类上、同类全部资产共享，因此**单个模板资产自身的原生窗口图标通道不存在**；模板自身的图标仅由框架自绘界面消费（数据树行 / 检查器缩略图读模板字段，逐模板生效）。持久化分两层：自定义纹理经 `MonoImporter.SetIcon` + `SaveAndReimport` 写进生成类 `.cs.meta`（跨会话 / 换机 / 进 VCS 有效）；内置图标（内置纹理无 GUID 写不进 meta）为 session 级，打开工程时自动验证式同步（不一致才设，已生效零操作）。即时生效点：保存模板 / 选完图标、工厂创建 / 复制资产、生成代码；手动兜底菜单 `HYC Framework/Config/Apply Template Icons`。**框架/基类模板（`generateCode=false`，如 `ConfigBase`）不参与传播**——无生成类型与配置资产，传播无意义；基类模板的 icon 字段仍可在模板编辑器内查看 / 修改（只影响数据树与检查器的自家显示）。

字段细节（类型、导出设置、检查规则）见 [11-字段类型与导出设置](./11-字段类型与导出设置.md)。

## 配置实例基数（Cardinality）

一个配置类型在工程中能同时存在几个资产实例，称为它的**实例基数（Cardinality）**。框架只支持两种：

| 基数 | 含义 | 声明方式 |
| --- | --- | --- |
| `Multiple`（默认） | 该类型可存在任意多个资产实例 | 不标 `Unique`（即 `CfgAsset(name, order)`） |
| `Single` | 全工程唯一，整个工程只应有一个该类型的资产 | `[CfgAsset(name, order, unique: true)]` |

> 概念层用 `Multiple` / `Single` 这对词汇描述意图；**代码层就是 `CfgAssetAttribute.Unique` 这一个布尔**——`Single` 投影成 `Unique=true`，`Multiple` 投影成 `Unique=false`（默认值）。目前没有第三种基数；若未来需要（如「每场景一个」），再把它升级为枚举，不要现在提前抽象。

### Single 的强制点

`Single` 不是只靠约定，而是在多个入口被强制，确保「全工程唯一」不被绕过：

| 入口 | 强制行为 | 位置 |
| --- | --- | --- |
| 类型声明 | `CfgAssetAttribute.Unique` 字段（`Inherited = true`） | `Runtime/CfgAssetAttribute.cs` |
| 创建 | 唯一类型已存在即抛 `InvalidOperationException`（"禁止重复创建"） | `ConfigAssetFactory.Create` |
| 批量创建 | 唯一类型直接抛「不支持批量创建」 | `ConfigAssetFactory.CreateMany` |
| 创建器 UI | 显示唯一标记，已存在类型不提供二次创建 | `ConfigCreateWindow` / `ConfigDataTree` |
| 导出去重 | `ConfigIdService.EnsureUniqueBeforeExport` 拦 `id == 0` / 重复项 | `ConfigExportService` 链路 |

### 要点

- **`Single` 的拦截发生在创建期**：`ConfigAssetFactory` 用 `IsUniqueType` + `HasExistingUnique`（`AssetDatabase.FindAssets` 按类型扫目标文件夹）判断。存量资产或外部拷贝若绕过创建器直接放进工程，创建期拦截拦不到——导出期的 `EnsureUniqueBeforeExport` 是第二道闸门。
- **`Hide` 与 `Unique` 正交**：`Hide` 只决定类型是否出现在「配置创建器」列表（框架基础设施类型如模板 / 基类 / 音频总览），与「是否唯一」无关；两者可在同一 `[CfgAsset]` 上同时设置。
- **声明示例**：

```csharp
// 全工程唯一的音频总览
[CfgAsset("音频/音频总览", 60, unique: true)]
public class AudioCatalogOverview : ConfigBase { /* ... */ }

// 可多个的角色配置（默认，不写 unique）
[CfgAsset("角色/角色配置", 10)]
public class CharacterConfig : ConfigBase { /* ... */ }
```

交叉引用：创建 / 导出去重的实现细节见 [12-数据编辑与校验](./12-数据编辑与校验.md)（「配置创建」与「导出前查重」）；`[CfgAsset]` 特性字段速查见 [99-Blob-与数据约定](./99-Blob-与数据约定.md) 第七节。

## 注意事项 / 坑

1. **`TRow` 必须 blittable**——字符串字段要选 `BlobString` 或 `FixedString` 导出模式（见 11 篇），否则烘焙会失败。
2. **`Materialize` 缓存会被 `Register` 清空**——引导期注册完所有表之后再开始查询。
3. **`GetAllRows` 返回 `BlobArray<T>` 引用**，不要长期持有跨 Blob 生命周期；表未注册时返回 `default`（`Length` 为 0，遍历前先 `Has<T>()`）。
4. **改了模板的 `className` 再生成**会走改名处理流程，原有数据资产要确认是否跟着迁移。
5. **导出目标**（Client / Server / Both）决定字段进哪一侧产物，改字段的 `exportTarget` 后需要重新导出。
