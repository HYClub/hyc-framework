# 32 · 组件绑定（UI Binder）

## 职责

把预制体上的节点/组件，在开发期登记下来，生成**强类型 Binder 类**，窗口代码里用 `Binder.CloseButton` 直接访问——告别 `transform.Find("...")` 字符串。

三件套：

| 件 | 位置 | 作用 |
| --- | --- | --- |
| `ComponentBinderTable` | Runtime | 挂在预制体上的 authoring MonoBehaviour，存 `Name / Target / Component / Desc` |
| `ComponentBinderCodeGenerator` | Editor | 读表生成 C# 类 |
| `IComponentBinder` + `BinderEngine` | Runtime | 运行时协议 + 路径解析工具 |

菜单：`HYC Framework/UI/Generate UI Binders`

---

## 一、在预制体上登记

1. 选中预制体根节点（或任意子节点）→ `Add Component` → **`HYC Framework/UI/UI 元素绑定`**。
2. 在 `Items` 数组里逐条填：

| 字段 | 说明 |
| --- | --- |
| `Name` | 生成代码里的属性名，必须合法标识符（`^[a-zA-Z_][a-zA-Z0-9_]*$`）且不重复 |
| `Target` | 目标 GameObject |
| `Component` | 目标上的组件（**必须挂在 Target 上**，否则报错跳过） |
| `Desc` | 可选注释，会生成 `/// <summary>` |

3. 类名 / 命名空间：

| 设置 | 默认 | 覆写开关 |
| --- | --- | --- |
| 命名空间 | 项目设置里的 `CodeOutputPackageName` | `CustomPackageName` + `PackageName` |
| 类名 | **`component.gameObject.name`**（绑表所在节点名） | `CustomClassName` + `ClassName` |

最终类名还会套上项目设置的 `ClassNamePrefix` / `ClassNameSuffix`。

⚠️ 默认类名 = **GameObject 名**，所以节点名要能当类名（不能有空格、中文、不能以数字开头）。

---

## 二、嵌套绑定

如果某条 Item 的 `Component` 本身是另一个 `ComponentBinderTable`，生成器会把它当成**内嵌 Binder**：

```csharp
// 字段
private UI.BagItemBinder m_Item__;
// 构造
m_Item__ = new UI.BagItemBinder(m_table != null ? m_table.GetComponentAt(2) : null);
// 属性
public UI.BagItemBinder Item => m_Item__;
```

这样父 Binder 可以直接 `Binder.Item.Icon`，适合列表项、复用组件。

## 三、生成结果

```csharp
// ComponentBinder
// AUTO-GENERATED. Do not edit.
// Prefab: Assets/UI/BagWindow.prefab
// Hierarchy: /BagWindow

namespace Game.UI
{
    public class BagBinder : HYC.Framework.UI.IComponentBinder
    {
        private HYC.Framework.UI.ComponentBinderTable m_table;

        public BagBinder(HYC.Framework.UI.ComponentBinderTable component) { m_table = component; }
        public BagBinder(UnityEngine.GameObject gameObject) { m_table = gameObject.GetComponent<...>(); }
        public BagBinder(UnityEngine.Component component) { m_table = component.gameObject.GetComponent<...>(); }
        public void Reset(UnityEngine.GameObject gameObject) { m_table = gameObject.GetComponent<...>(); }

        private UnityEngine.Component GetComponentAt(int index) => m_table != null ? m_table.GetComponentAt(index) : null;
        public UnityEngine.GameObject gameObject => m_table != null ? m_table.gameObject : null;

        /// <summary> 关闭按钮 </summary>
        public UnityEngine.UI.Button CloseButton => GetComponentAt(0) as UnityEngine.UI.Button;
    }
}
```

要点：

- 属性是**每次访问都 `GetComponentAt(i) as T`**——不缓存，节点被销毁后再访问会拿到 null 而不是野引用。
- `Reset(GameObject)` 就是重新指向另一个 `ComponentBinderTable`，**让 Binder 能跨场景/重开窗口复用**。
- 找不到的组件返回 `null`（`as` 转换失败），不报错。

## 四、生成设置

`ComponentBinderSetting`（存在 **`ProjectSettings/ComponentBinder.asset`**，不在 Assets 里，不会进包）。

| 字段 | 说明 |
| --- | --- |
| `FindAllPrefab` | true = `AssetDatabase.FindAssets("t:Prefab")` 全工程扫；false = 只在 `PrefabFolder` 下扫 |
| `PrefabFolder` | `DefaultAsset`，`FindAllPrefab == false` 时必填 |
| `CodeOutputMethod` | true = 输出到工程内文件夹资源；false = 输出绝对路径 |
| `CodeOutputFolder` / `CodeOutputFolderPath` | 对应上面两种模式的输出位置 |
| `CodeOutputPackageName` | 默认命名空间 |
| `ClassNamePrefix` / `ClassNameSuffix` | 类名前后缀 |

设置 UI 在 `ComponentBinderSettingProvider`（Project Settings 面板里）。

---

## 五、生成流程（GenerateAll）

```
1. 读设置，校验输出目录（缺失会弹窗 "Output folder not set"）
2. CleanFolder(saveFolder)   ← 删除所有以 "// ComponentBinder" 开头的 .cs（幂等）
3. FindAssets("t:Prefab")    → 每个预制体递归 CollectBinder(transform) 收集所有 ComponentBinderTable
4. 过滤：PrefabUtility.GetOutermostPrefabInstanceRoot(binder.gameObject) == null 才生成
   （即跳过场景里的嵌套预制体实例，只处理预制体资源本身）
5. 逐个 Generate()
6. 错误统一 Debug.LogError
```

单条生成：Inspector 上的 **Generate** 按钮 → `GenerateOne(binder)`（不清理目录）。

---

## 六、常见生成错误

全部以 `Debug.LogError` 输出，带 `Hierarchy: /Root/.../Node` 定位：

| 错误 | 原因 |
| --- | --- |
| `Invalid namespace 'xxx'` | 命名空间不是点分标识符 |
| `Class name cannot be empty` | 节点名为空且没开 `CustomClassName` |
| `Invalid class name 'xxx'` | 类名不合法（含空格/中文/数字开头） |
| `Invalid class-name prefix/suffix` | 前后缀不是合法标识符 |
| `'xxx' is not a valid field name` | Item.Name 不合法 |
| `Duplicate field name 'xxx'` | 同表内重名 |
| `Empty node` | `Item.Target == null` |
| `Empty component` | `Item.Component == null` |
| `Component does not sit on target` | 组件不在 Target 上 |

这些是**逐条跳过**（`continue`），其它 Item 仍会生成。

## 七、运行时引擎（BinderEngine）

生成的代码不依赖它，但手写绑定时可以用：

```csharp
using HYC.Framework.UI;

// 按路径取组件（path 为空则取 root 自身）
var btn = BinderEngine.Get<Button>(root, "Panel/Left/Close");

// 约定式：下划线转斜杠
var icon = BinderEngine.FindBySeralized<Image>(root, "Panel_Left_Icon");
// 等价于 Get<Image>(root, "Panel/Left/Icon")

// 直接实例化并绑定一个 Binder
var binder = BinderEngine.Bind<BagBinder>(rootGameObject);
```

⚠️ `Require<T>` 目前**只是 `Get<T>` 的别名，不会报错**（名字有误导性，别指望它抛异常）。
⚠️ `FindBySeralized` 的拼写是源码里的（Seralized），调用时注意。

## 八、在窗口里用

```csharp
public class BagWindow : BaseWindowSystem<BagBinder>
{
    public override string PrefabKey => "UI/BagWindow.prefab";

    public override void OnViewOpen(params object[] args)
    {
        base.OnViewOpen();
        Binder.CloseButton.onClick.AddListener(() => UIManager.Close<BagWindow>());
        Binder.Title.SetKey("ui/bag/title");
    }

    public override void OnViewUpdate()
    {
        Binder.Coin.text = PlayerData.Coin.ToString();
    }
}
```

带 Binder 的基类一览（都提供 `Binder` 属性 + 关闭时置空）：

| 基类 | Focusable |
| --- | --- |
| `BaseWindowSystem<T>` | true |
| `BaseDialogSystem<T>` | true |
| `BaseHudSystem<T>` | false |
| `BaseLoadingSystem<T>` | false |
| `AbsParentBaseWindowSystem<T>` | true（继承 BaseWindowSystem） |
| `BaseWindowPart<T>` | —（`BaseWindowPart` 不可聚焦） |

泛型约束：`where T : IComponentBinder, new()`

## 九、注意事项 / 坑

1. **默认类名取 GameObject 名**——中文/空格节点名会生成失败（`Invalid class name`）。给绑表所在节点起个英文名字，或开 `CustomClassName`。
2. **每次 GenerateAll 会清空输出目录里所有带标记的文件**：`CleanFolder` 按首行 `// ComponentBinder` 判断，**不要把手写代码放进这个目录**。
3. **`ComponentBinderTable` 是运行时无害的数据组件**，但会随预制体进包；条目多会增加序列化体积，按需登记。
4. **属性不缓存**，高频访问（每帧）的组件建议自己在 `OnViewOpen` 里缓存到字段。
5. **实例化的预制体必须带 `ComponentBinderTable`**——`Reset(View)` 用的是 `gameObject.GetComponent<ComponentBinderTable>()`，绑表在子节点上也会往父级找吗？**不会**，只在传入的那个 GameObject 自身找。绑表挂的位置要和 `Reset(root)` 的 root 一致（框架传的是 `View`，即预制体根）。
6. **嵌套 Binder 的构造在四个构造函数里都会执行**，包括 `Reset`——所以重新绑定时子 Binder 也会重建。
7. **`GetComponentAt(i)` 里的 `i` 是编译期写死的数组下标**——**不要在 Inspector 里删除/重排 Items 中间项而不重新生成**，否则属性会指向错误的组件。改表后必须重新 Generate。
