# 90 · 编辑器工具链

> 编辑器代码量约为运行时的 1.8 倍——这个框架的价值大半在工具链。

## 菜单分档与 priority（改菜单前必读）

菜单**不是字母序，而是按使用频率与语义分三档**：

```
HYC Framework/
├── ① 内容制作（高频）Config / BT / UI / Localization / Attributes / Talent
│─────────────────── 分隔线 ───────────────────
├── ② 通用工具      Tools / Assets
│─────────────────── 分隔线 ───────────────────
└── ③ 项目级（低频）Settings / Samples
```

**分隔线不是画出来的**，是 priority 差 ≥ 11 自动生成的：
`Talent(50) → Tools(100)` 差 50、`Tools(101) → Settings(200)` 差 99 ⇒ 恰好两处。
档内相邻差均 ≤ 10 ⇒ 档内不画线。

⚠️ **Unity 菜单的硬限制**：菜单**不支持自定义分组标题**，只能画分隔线。
所以"分级"只能靠**位置语义**表达——这正是**排序比命名更重要**的原因。

⚠️ **不能只给父菜单首项写 priority**：排序作用于每个叶子菜单项，
未写 priority 的默认 0、会全部挤到最前面把分组打乱。
故当前 **20 个菜单项逐个**都标了 priority（见上表右侧）。

<details>
<summary>priority 的官方规则（两次踩坑记录）</summary>

Unity `MenuItem(itemName, isValidateFunction, priority)` 的 `priority` **不只是排序**，
它还隐式控制**分隔线**：

> **相邻两项的 priority 差值 ≥ 11 时，Unity 会在它们之间画一条分隔线。**
> （官方文档示例用 100 与 111；改成 110 差 10 就**没有**线）

- **第一次错**：`BT/导出 Blob(打包用)` 写了 `priority = 30`，与前一项（0）差 30
  ⇒ BT 子菜单上方凭空多出一条线，视觉上像"HYC Framework 标题"与"BT"分属两组。
- **第二次对**：为做分档给每项显式标 priority。**父菜单排序由它首个子菜单的 priority 决定**，
  所以父菜单顺序也靠首项控制；新增/删除菜单时必须重新核算整套数值。

完整约定见 [`com.hyc.framework/Editor/MenuLayout.md`](../com.hyc.framework/Editor/MenuLayout.md)。

</details>

## ⚠️ MenuItem priority 会画出莫名分隔线（踩坑记录）

Unity 的 `MenuItem` 第三个参数 `priority` **不只是排序**，还隐式控制分隔线：

> **相邻两项 priority 差值 ≥ 11 时，Unity 会在它们之间画一条分隔线。**
> （官方文档示例用 100 与 111；改成 110 差 10 就**没有**线）

本框架踩过一次：`HYC Framework/BT/导出 Blob(打包用)`<!-- 历史名称，勿删；2.0.6 起改名 -->
曾写 `priority = 30`，
与前一项（priority 0）差值 30 ⇒ **BT 子菜单上方凭空多出一条线**，
视觉上像是"HYC Framework 标题"与"BT"分属两个分组。

**现行约定（2026-10-07 菜单三档重组后，与 `Editor/MenuLayout.md` 一致）**：
**每个 `[MenuItem]` 都显式写 priority**，值落在三档区间内——内容制作 0–81 / 通用工具 100–102 / 项目级 200–210。
没写 priority 的项默认为 0，会全部挤到最前面打乱分组（这是重组时踩过的第二个坑）。
另注意**父菜单排序由其第一个子菜单的 priority 决定**，所以调大类顺序得改子项 priority。
档间差 ≥ 11 自动生成分隔线（如 `Cinemachine(81) → Tools(100)`），档内差 ≤ 10 不画线。
完整结构图与数值见 `Editor/MenuLayout.md`。

## 各工具要点

### 数据编辑器（Data Editor）

`DataEditor/` 是整个工具链最大的一块（48 个文件），涵盖：
配置数据树、字段抽屉（Bool/Enum/List/Line/File/Folder/Multiline/ReadOnly/Position/Size/Max/TextureSize…）、ID 分配（`LocalConfigIdProvider` / `NetworkConfigIdProvider`）、导出服务、模板编辑器、枚举编辑器、预览窗口、图标选择器、错误窗口。

### 导出：保存并导出 / 全量清理后全量导出

| 入口 | 位置 | 实现 | 行为 |
| --- | --- | --- | --- |
| 保存并导出 | 数据编辑器：配置文件右键 / 文件夹右键「1 导出所有配置」 | `ConfigDataTree.SaveAndExportSingleAsset` / `SaveAndExportFolderAll` | 先 `ConfigExportService.SaveFolder(folder)` 递归存盘，再 `Export*(…, client:true, server:true)` |
| 保存导出所有枚举 | 数据编辑器：文件夹右键「2 保存导出所有枚举」 | `ConfigDataTree.SaveAndExportFolderEnums` | 逐个枚举定义先 `SaveAssetIfDirty` 再 `ConfigEnumCodeGen.Export(…, true, true)` |
| 保存并生成所有模板代码 | 数据编辑器：文件夹右键「3 保存并生成所有模板代码」 | `ConfigDataTree.GenerateFolderTemplateCode` | 逐个模板先落盘再 `WriteFile`（与单个生成流程一致：生成后再落盘消 `*` 标记） |
| 全量导出 | 数据编辑器：根目录右键 + 工具栏按钮 | `ConfigDataTree.CleanAndExportAll` | `ConfigExportService.CleanAndExportAll(true, true)` |
| 保存并导出 | BT 编辑器：单棵树右键 / 文件夹右键 | `BTBlobExporter.ExportTrees` / `ExportFolder` | 先存盘再导出**这批**（不清空目录），导出后 `SyncManifest` 重建清单 |
| 全量清理后全量导出 | BT 编辑器：File 菜单 | `BTBlobExporter.ExportAll()` | **先清空 `BTBlob/` 再全量导出** |

要点：

- **文件夹右键的导出项按内容动态列出**：集中在「导出」**真子菜单**里（GenericMenu 路径按 `/` 拆子菜单）——每种可导出配置类型一项「短名（N 个）」+ 子菜单内分隔线 + 「导出全部」；枚举 / 模板作为顶级动态项单列（模板是生成代码不是导出）。N 与 `ExportFolder` 同一过滤规则实时统计，三类皆无时列禁用提示。模板文件夹不再出现不适用的「保存并导出内部所有」。详见 [12 篇](./12-数据编辑与校验.md)。
- **按类型导出必须整类型导**：`ConfigBaseExport.ExportCore`（单资产）对 Blob 格式只写这一个资产，逐资产循环调会互相覆盖；按类型/文件夹导出走 `ExportAllCore`（一类型一个产物文件）。
- **「全量清理后全量导出」会删文件**：配置侧清空 `ClientExportDir` / `ServerExportDir` 下的 `*.blob`，
  BT 侧清空整个 `StreamingAssets/BTBlob/`。用于「删了表 / 改了名之后残留幽灵产物」的场合，
  **日常增量不要用**。
- **局部导出不删旧产物**：`ExportTrees` / `ExportFolder` 只覆盖这批 blob，
  再 `SyncManifest` 重扫目录重建清单，保证 manifest 与实际文件一致，真机读得到。
- **导出前必须先存盘**：配置侧的 `SaveFolder` 与 BT 侧的存盘步骤都不能省，
  否则导出的是内存里尚未落盘的数据。

### 组件绑定代码生成

`ComponentBinderCodeGenerator` 依据 `ComponentBinderTable` 生成 `class X : IComponentBinder`，解决**跨场景后引用失效**——视图（重）显示时 `Reset` 重新绑定。

### 资源工具（AssetTools）

- **Show Dependents of Selection**：反查引用，改公共配置/资源前先看影响面
- **Clean Missing Asset References**：清理丢失引用（**会改资产，执行前先提交/备份**）

## 注意事项 / 坑

1. **`Clean Missing Asset References` 会直接改资产文件**——跑之前确保工作区干净，方便回滚。
2. **NPOI 只在编辑器可用**——别在运行时代码里引用 `LocalizedExcelReader` 或 NPOI 类型。
3. **`DataEditor/` 大量字段抽屉依赖 `ConfigFieldType`**——加新字段类型时，抽屉渲染要同步加分支，否则新类型在编辑器里显示不出来。
4. **BT 编辑器是纯 IMGUI**，没有 UXML/USS；改界面直接改 `BTGraphIMGUI.cs` 的绘制代码。
5. **画布不做 GUIClip 裁剪**——新增任何面板/浮层都要画在画布之后，否则会被节点盖住或反过来盖住节点。
