## 一、写一个窗口

```csharp
using HYC.Framework.UI;

public class BagWindow : BaseWindowSystem<BagBinder>   // 泛型参数 = 生成的绑定类
{
    // Addressables 预制体 key（必填，abstract）
    public override string PrefabKey => "UI/BagWindow.prefab";

    // 可选：需要先加itively 加载的 UI 场景
    public override string SceneKey => "Scene_UIBag";

    // 可选：层内排序（默认 0，升序）
    public override int Order => 10;

    // 可选：是否参与焦点（BaseWindowSystem 默认 true）
    public override bool Focusable => true;

    // 视图加载完成后调用（异步！）
    public override void OnViewOpen(params object[] args)
    {
        base.OnViewOpen();
        Binder.CloseButton.onClick.AddListener(OnClose);   // Binder 在这里才可用
    }

    public override void OnViewUpdate() { /* 每帧 */ }

    public override void OnViewClose()
    {
        UnregisterHotkey(mHotkey);
        base.OnViewClose();
    }
}
```

打开：

```csharp
UIManager.OpenWindow<BagWindow>(1001, "equip");   // params 会透传到 OnViewOpen(args)
UIManager.Close<BagWindow>();
bool open = UIManager.IsOpen<BagWindow>();
```

## 二、可重写的成员

| 成员 | 类型 | 说明 |
| --- | --- | --- |
| `PrefabKey` | `abstract string` | **必填**，Addressables key |
| `SceneKey` | `virtual string` | 默认 `string.Empty`；非空则先加itively 加载该场景 |
| `Order` | `virtual int` | 层内排序，默认 0 |
| `Focusable` | `virtual bool` | 默认 `true`；`BaseHudSystem`/`BaseLoadingSystem` 覆写成 `false` |
| `OnSceneOpen(Scene)` / `OnSceneOpen(Scene, args)` | virtual | UI 场景加载完成（仅 `SceneKey` 非空） |
| `OnViewOpen(args)` / `OnViewOpen()` | virtual | **视图就绪**，初始化写这里 |
| `OnViewUpdate()` | virtual | 每帧（`View != null` 时） |
| `OnViewClose()` | virtual | 关闭时；基类会 `Disable()` + 注销热键 + 关闭所有 Part |
| `OnViewFocus()` / `OnViewLost()` | virtual | 焦点变化；基类负责热键静默开关 |
| `OnViewLayerChanged(int sortingOrder)` | virtual | 层级重算后回调，值存进 `ViewSortingOrder` |
| `OnAnimationEvent(string key)` | virtual | 动画事件；`"Enter"` / `"Exit"` 由框架自动发 |
| `Hide()` / `Show()` | virtual | 只改 `_targetAlpha`（0/1） |

### 可用的属性

| 属性 | 说明 |
| --- | --- |
| `View` | 实例化的预制体根（未加载完为 null） |
| `Canvas` | 运行时创建的 WorldSpace Canvas |
| `Camera` | `Canvas.worldCamera` |
| `CanvasGroup` | 需自行赋值，框架不自动加 |
| `ViewSortingOrder` | 最近一次 `OnViewLayerChanged` 给的 sortingOrder |
| `UISystemType` | `Normal` / `Single`，由 `UIManager.Open` 写入 |
| `Focused` | `protected`，`Focusable && UIManager.FocusedWindow == this` |

## 三、嵌入 UI（统一链路 —— 只有 `Open`）

统一链路后**窗口与部件是同一条继承链**（都继承 `AbsUISystem`）：
**任何 UI 都能嵌另一个 UI，也都能被嵌**，不再区分「部件」和「子窗口」。
唯一区别是**怎么打开**：

| 打开方式 | `UIMode` | 行为 |
| --- | --- | --- |
| `UIManager.OpenWindow<T>()` | `TopLevel` | 有层节点 / Canvas / sortingOrder / 焦点；`GetOrCreateSystemManaged` 按类型单例 |
| 宿主 `Open<T>(...)` | `Embedded` | **无**层 / Canvas / 焦点；`CreateSystemManaged` **每次新实例** |

### 用法

```csharp
var c1 = Open<BagItemPanel>();                        // 用 PrefabKey 加载，挂到 View 根
var c2 = Open<BagItemPanel>(someTransform);           // 指定父节点
var c3 = Open<BagItemPanel>(someTransform, arg1);     // 带参数 → OnViewOpen(args)
var c4 = Open<BagItemPanel>(existingGameObject);      // 用已有对象（不加载）
var c5 = Open<BagItemPanel>(existingGameObject, someTransform);

c4.Close();              // 自关闭
Close(c2);               // 由宿主关闭
bool on = IsOpened(c2);  // 是否仍开着
```

| 重载 | 行为 |
| --- | --- |
| `Open<T>(Transform parent = null, params object[] args)` | 用 `PrefabKey` 加载；parent 为空时挂到 `View.transform` |
| `Open<T>(GameObject view, Transform parent = null)` | **不加载**，直接用该对象 |

- **每次调用都创建新实例** ⇒ 同类型可同时开多份（列表项）、可递归嵌套（A 里再开 A）。
- 关闭宿主时 `CloseAllEmbedded()` 自动递归关闭全部内嵌 UI。
- `Loaded` 表示视图是否已就绪。

⚠️ 内嵌 UI **不走 `UIManager` 的层管理** —— 没有 Canvas、没有 sortingOrder、不进 `LayerViews`。
因此 `ResetWindowFocus`（只扫 `LayerViews`）**永远不会把焦点给它**，也不会触发 HUD 隐藏；
内嵌模式还会跳过 `Enable()/Disable()`，不注册导航热键。

⚠️ 若 `PrefabKey` 为空且没传 GameObject →
`LogError($"打开 {type.Name} 失败 : 既未设置 PrefabKey, 也未指定界面对象")`，
但**仍然返回了 system 实例**，且它的 `View` 是 null。

### 迁移对照（破坏性变更）

| 旧写法 | 新写法 |
| --- | --- |
| `OpenWindowPart<T>()` | `Open<T>()` |
| `OpenWindowPart<T>(parent)` | `Open<T>(parent)` |
| `OpenWindowPart<T>(go)` | `Open<T>(go)` |
| `OpenWindowPart<T>(parent, go)` | `Open<T>(go, parent)` |
| `AbsParentBaseWindowSystem.Open<T>(parent, args)` | `Open<T>(parent, args)` |

- `PrefabKey` 由 `abstract` 放宽为 `virtual`（默认 `null`）—— 内嵌 UI 允许不配预制体。
- `BaseWindowPart` / `AbsParentBaseWindowSystem` **已删除**（原 `OpenWindowPart` / `Open<T>` / `Key` / 重复的热键与查找实现随之移除）。
  原窗口内可复用部件改用本节的 `Open<T>(...)`：继承 `BaseWindowSystem<T>`（或直接 `AbsUISystem`）+ 设 `Focusable = false`。

## 五、热键注册

```csharp
private HotkeyHandle mHotkey;

public override void OnViewOpen()
{
    // 最简单：动作名 + 回调
    mHotkey = RegisterHotkey(HotkeyActionNames.UI_UGUI_Cancel, ctx => UIManager.Close<BagWindow>());

    // 带长按（< 0.1 会被钳到 0.1，NaN 也变 0.1）
    RegisterHotkey("Game/UseItem", OnUse, holdTime: 0.5f);

    // 带 UI 提示元素（会在 parent 下生成按键提示 UI）
    RegisterHotkey("Game/UseItem", someHotkeyElement, OnUse, priority: 10);

    // 自定义样式 + 文本
    RegisterHotkey("Game/UseItem", OnUse, Binder.HotkeyRoot, "使用", HotkeyElementStyle.UI, 5);
}
```

- 所有重载都会把 handle 存进内部 `_hotkeys` 列表。
- **`OnViewClose()` 自动 `UnregisterAllHotkey()`**——只要没忘调 `base.OnViewClose()`。
- 失焦时框架把所有热键 `Silence = true`（`OnViewLost`），得焦恢复 `false`。
- 手动注销：`UnregisterHotkey(handle)`。

⚠️ `AbsUISystem.Enable()/Disable()` 会额外注册/注销四个导航热键 `UI_UGUI_Horizontal/Vertical/Submit/Cancel`——这两个方法由基类在 `OnViewOpen`/`OnViewClose` 里按 `Focusable` 自动调用，**不要手动调**。

## 六、组件查找

不想用生成 Binder 时，可以按路径找：

protected T FindComponent<T>(string path);            // 相对 View
protected T FindComponent<T>(Component node, string path);  // 相对某个节点

## 七、焦点导航（手柄/键盘）

框架自带完整实现，一般不用改。要点：

- **只在 `HotkeyManager.IsNavigateMode` 时生效**（鼠标键盘模式直接跳过）。
- 首次选中：`FindFirstSelection()` —— 先找 `FocusableCustom`，再找**可交互且 `navigation.mode != None`** 的 `Selectable`。
- 移动：`FindNextFocusBy(current, dir)`
  - `TMP_InputField` / `InputField` → 不移动（输入框内导航）。
  - `FocusableCustom` → 调它的 `OnMove(dir)`。
  - `Navigation.Mode.Explicit` → 直接取 `selectOnLeft/Up/Right/Down`。
  - 其它 → 走**几何打分**：`value = Dot(dir, 目标中心 - 参考点) / 距离平方`，取最大。
- 连发节流：见 [30 篇](./30-ECS-UI-总览.md) 的参数表。
- `AutoSelectOnGotFocus` 挂到对象上：导航到它时会**自动触发一次 Submit**。

自定义导航就继承 `AbsUISystem.FocusableCustom` 并重写 `OnMove(MoveDirection dir)` 返回目标 GameObject。

## 九、动画钩子

预制体根上挂 `UIAnimationHook`（`[RequireComponent(typeof(Animator))]`），Animator 的 Animation Event 调用：

| 方法 | 触发 |
| --- | --- |
| `FireAnimationEnterEvent()` | → `window.OnAnimationEvent("Enter")` |
| `FireAnimationExitEvent()` | → `window.OnAnimationEvent("Exit")` **然后自动 `Close(window, false)`** |
| `FireAnimationEvent(string key)` | → `window.OnAnimationEvent(key)` |

关闭时 `UIManager` 会先找 Animator 的 `"Exit"` **Trigger** 并 SetTrigger；所以**退出动画要靠 Animator 参数 `Exit`（Trigger 类型）+ 末尾的 Animation Event 调 `FireAnimationExitEvent`** 串起来。

## 十、注意事项 / 坑

1. **别在 `OnCreate` 里碰 `View`**——`OnCreate` 在 System 首次创建时跑，此时预制体还没实例化，甚至窗口还没被 Open 过。
2. **`OnViewClose` 一定要 `base.OnViewClose()`**——否则热键不会注销、Part 不会关闭、`Enable/Disable` 不配对。
3. **`Binder` 是懒构造的**：首次访问 `Binder` 时才 `new T()` + `Reset(View)`。`OnViewClose` 里会置 `default`（下次重新绑定）。所以**不要在 `OnViewOpen` 之前访问 Binder**（会绑到 null View 上）。
4. **`CanvasGroup` 不会自动创建**——需要淡入淡出就自己在预制体上放一个，并在 `OnViewOpen` 里赋给 `CanvasGroup` 属性。
5. **`UISystemType.Single` 只对 HUDNotice 路径生效**（`LoadPrefabBegin` 里判断后 `CloseHudNotice(SingleUISystem)`），全局只有一个 `SingleUISystem` 槽位。
6. **`IsOpen<T>()` 看的是 `window.Enabled`**，异步加载中返回 false；要"加载中也算开着"用 `IsOpenAsync(Type)`。
7. **`OpenWindowAndCloseOther<T>()` 只关 `Window` 层**且跳过同类型。
8. **窗口 System 是 `GetOrCreateSystemManaged` 复用实例**——关闭后 System 对象仍在 World 里，字段值不会重置。**下次打开前务必在 `OnViewOpen` 里重新初始化所有状态字段**。

## 十一、UI 层表（数据化 + 代码生成）

层集合不再是编译期枚举，而是 **FrameworkSettings 资产里的数据**（`uiLayers`，出包生效），在 **HYC Settings → UI/层级** 增删改名、拖动排序、写中文描述，一键「保存并生成」产出宿主侧常量。默认 10 层（下标 0 在最底）：

| 层名 | 默认用途 | HUD | 挡输入 | 全隐藏 |
| --- | --- | :-: | :-: | :-: |
| `HUD` | 血条 / 小地图等常驻信息 | ✓ | | ✓ |
| `HUDNotice` | 飘字 / 拾取提示 | ✓ | | ✓ |
| `Window` | 主功能窗口（背包 / 任务） | | ✓ | |
| `WindowNotice` | 窗口之上的轻提示 | | | |
| `Dialog` | 需要玩家决策的模态框 | | ✓ | |
| `TopWindow` | 压在弹窗之上的窗口 | | | |
| `ToolTip` | 跟随鼠标的说明 | | | |
| `Loading` | 加载遮罩 | | ✓ | 常驻 |
| `Cursor` | 自定义鼠标指针 | | | 常驻 |
| `Mask` | 全屏遮挡（引导 / 截屏） | | | 常驻 |

**顺序即层级**：列表下标 0 在最底层，越往后越靠上——决定 Canvas 的 `sortingOrder` 与 Hierarchy 里的兄弟顺序。「全隐藏」列对应 `HideAllUI` 时是否一起隐藏（不勾 = 常驻）。

### 三枚行为标记（替代原先按层名写死的判断）

| 标记 | 行为 | 框架里对应的老判断 |
| --- | --- | --- |
| `hud` | 有窗口类层开着时，自动关掉本层 Canvas 与射线 | 原 `ResetHudVisible` 写死 `HUD \|\| HUDNotice` |
| `blockInput` | 本层窗口挡住世界空间输入 | 原 `HitTest` 写死 Mask 层 |
| `hideOnHideAll` | `HideAllUI` 时是否一起隐藏 | 原写死 `层号 >= Loading`（且 `continue` 漏 `index++` 的隐 bug，已随本次重写修复） |

标记跟着**层本身**走：改名 / 插层后群体行为自动跟随，不需要改框架代码。

### 「保存并生成」产出什么

单个文件 `Assets/HYC/Generated/UI/UILayer.g.cs`（命名空间 `{生成代码root}.ui`，与配置类平级；host 侧 use 后）：

```csharp
// 每层一个 const int 常量（刻意不用 enum——框架 API 引用宿主类型会形成程序集环；
// int 常量零耦合，拼错名字照样编译报错，类型安全性与 enum 等价）
public static class UILayer
{
    public const int HUD = 0;
    public const int HUDNotice = 1;
    // …其余层…
    public const int Count = 10;

    // 每层一个 Open 糖，与 UIManager.Open<T>(layer, …) 等价
    public static T OpenWindow<T>(WindowCanvasType canvas = WindowCanvasType.Normal,
        UISystemType system = UISystemType.Normal, params object[] args) where T : AbsUISystem
        => UIManager.Open<T>(UILayer.Window, canvas, system, args);
}
```

宿主用法：`UILayer.OpenDialog<BagWindow>()` 或直接 `UIManager.Open<BagWindow>(UILayer.Dialog)`。**层表改了要重新生成一次**（旧常量文件会被整体覆盖，不会留过时常量）。

### 通用入口 Open（已公开）

```csharp
// 通用入口：层号 = 层表下标（越界 / 层表未初始化记错误并返回 null）
public static T Open<T>(int layer, WindowCanvasType canvas = ..., UISystemType system = ..., params object[] args) where T : AbsUISystem;
public static AbsUISystem Open(Type type, int layer, ...);
```

### 按默认层名查找的 API 与降级行为

少数 API 与「默认层名」精确绑定（`OpenHud*` / `OpenWindow*` / `OpenDialog` / `OpenTopWindow` / `OpenLoading` / `OpenCursor` / `OpenMask` / `OpenToolTip` 角色方法，以及 `HasWindow` / `ExistOtherWindow*` / `OpenWindowAndCloseOther`）。层名被改掉时它们查不到层（下标 -1），行为退化为「没有该层」，且 `UIManager` 初始化时**一次性报错**列出缺失的默认层名。两种出路：

1. 把层名改回默认（设置页「恢复默认层表」）；
2. 改用「保存并生成」产出的常量与方法（自定义层 / 改过名的层都走这条）。

### 迁移说明（破坏性变更）

| 变更 | 影响 |
| --- | --- |
| `UIManager.Open<T>(int layer, …)` / `Open(Type, int, …)` 由 private 改 **public** | 新增公开入口，原调用不受影响 |
| `enum WindowLayer` 由 public 改 **private** | 它只是「默认层名表」；宿主本来不该直接用（原先也无打开场景） |
| `HideAllUI` 按标记跳过而非「层号 ≥ Loading」，并修复 `continue` 漏 `index++` 的隐 bug | 自定义层默认一起隐藏；若某层要常驻（Loading/Cursor/Mask 类），在设置页把「全隐藏」取消勾选 |
| `WindowState.Layer`（private）类型 `WindowLayer` → `int`（层表下标） | 内部类型，无宿主影响 |

## 十二、模态窗口（报错 / 确认框）用法

> **先记住一个反直觉点**：层标记里的「挡输入」只挡**世界空间输入**（点游戏世界被拦截 + 热键静默），**不挡下层 UI**——各层 Canvas 各自 raycast，你点面板外的空白会漏到下层窗口。
> 所以「真模态」必须**两步一起**，单靠层标记做不到：

1. **弹窗预制体自带一张全屏半透明 Image**（`raycastTarget = true`，放在 Hierarchy 最底层当背景）——这张图负责挡住**下层 UI** 的点击。
2. 若还要挡**世界输入 + 热键静默**：在 **HYC Settings → UI/层级** 给对应层勾上「挡输入」。

### 两种档位

| 需求 | 做法 | 说明 |
| --- | --- | --- |
| 普通报错 / 确认框 | `UIManager.OpenDialog<MyDialog>()` | `Dialog` 层默认 `挡输入 = ✓`，本身就是模态；预制体带面板即可 |
| 顶级报错（要压在其它弹窗之上）| `UIManager.OpenTopWindow<MyTopError>()` | `TopWindow` 在所有 `Dialog` 之上；默认**不挡输入**，需手动勾「挡输入」+ 预制体带全屏 Image 才是真模态 |

独立全屏遮挡（引导 / 截屏）走 `UIManager.OpenMask<T>()` / `Mask` 层（常驻、不随 `HideAllUI` 隐藏），可与报错叠用当 backdrop。

### 预制体怎么做

```
MyTopError.prefab
└─ Canvas (TopWindow 层)
   ├─ [最底层] Image  full-screen, color = (0,0,0,0.5), Raycast Target = true   ← 挡下层 UI 点击
   ├─ Panel          报错内容（文字 + 确定按钮）
   └─ Button         确定 → UIManager.Close<MyTopError>()
```

> ⚠️ 别指望只勾「挡输入」做模态：它只能挡世界输入，挡不住下层 UI 的点击——必须配预制体全屏 Image。
> 若 `TopWindow` 将来还要承载「不挡输入的高优先级提示」，建议单独加一个报错层（设置页加层 + 保存并生成，零框架改动），不要给 `TopWindow` 全局勾挡输入以免误伤。
