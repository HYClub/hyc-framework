# 41 · 输入组件化（Input Component Generation）

> 配套索引：[100-文件与类索引](./100-文件与类索引.md) 的 `Runtime/Input/`（8 个文件）与 `Editor/Input/`（4 个文件）两节。
> 前置阅读：[40-输入与热键](./40-输入与热键.md)（事件 / 回调层 `HotkeyManager`）。

## 职责

基于 **Unity Input System（1.14.0，已是框架依赖）** 的 **代码生成** 方案：把你用 Input System 编辑器配好的 action，
**按 action map 动态生成**为 ECS 的 `IComponentData`（富状态 struct），并由驱动系统**每帧把当前输入写进玩家实体**。
宿主在游戏逻辑里**轮询式地"捞出来看"**——这个 action 现在点亮了吗？有数值吗？是摇杆偏移吗？

命名空间：运行时 **`HYC.Framework.Input`**；生成器 **`HYC.Framework.Editor`**。

一句话：
**`InputComponentGenerator` 读 `InputComponentMapping`（资产），按每个 action map 生成「富状态组件 + 写入器」，
`InputComponentDriverSystem`（挂在 `UpdateGroup_A0` 输入采样组）每帧把这些写入已注册的玩家实体；宿主直接读组件字段即可。**

---

## 为什么需要它（与 HotkeyManager 的分界）

| 维度 | `HotkeyManager`（40） | 输入组件化（本篇） |
| --- | --- | --- |
| 范式 | **事件 / 回调**：某动作发生一次就通知我 | **轮询 / 状态**：每帧查"现在是什么值" |
| 典型用途 | 菜单确认、热键提示、按钮音 | 角色移动摇杆、持续按压计量、状态机读输入 |
| 数据形态 | 回调里拿 `CallbackContext` 瞬时值 | 组件常驻实体，字段跨帧可查、可进 `System` 查询 |
| 生成 | 无（名字约定注册） | **按 action map 生成 component + writer** |
| 分包 | 不涉及 | **每 action map 独立 asmdef / 程序集** |

两者**共享同一份 `InputActionAsset`**：`HotkeyManager` 管"事件"，本篇管"状态"，互不冲突，可同时用。

## 架构

```
Input System 编辑器（.inputactions）
        │ 宿主配好 action
        ▼
InputComponentMapping（ScriptableObject 资产）   ← 菜单 HYC Framework/Input/Input Component Mapping
        │ asset + maps[ {mapName, outputFolder, ns, componentName} ]
        ▼
InputComponentGenerator.Generate(...)             ← 菜单 / 资产变更自动触发
        │ 按 action.expectedControlType 选类型
        ▼
┌─ 每个 map 一个文件夹 ─────────────────────────────┐
│  <Map>InputComponent.cs   : IComponentData        │  ← 富状态字段
│  <Map>InputComponentWriter.cs : IInputMapWriter   │  ← [RuntimeInitializeOnLoadMethod] 自注册
│  <Ns>.asmdef               : 最小 asmdef          │  ← 缺则自动补
└───────────────────────────────────────────────────┘
        │
        ▼  运行时
游戏层建玩家实体 → AddComponent(<Map>InputComponent) → InputUser 配对设备
        │
        ▼  InputPlayerRegistry.Register(entity, assetInstance)
InputComponentDriverSystem（UpdateGroup_A0）
   每帧：遍历 Players × Writers → writer.Write(em, player, map, prev) → em.SetComponentData
        │
        ▼
游戏 System 读组件：  if (ui.Submit.pressed) { ... }   var v = sense.Move.value;
```

## 快速上手（宿主）

### 1. 前置：在 Input System 编辑器里配好 `.inputactions`

先在工程里用 Unity 的 **Input System** 编辑器建一个 `Input Actions` 资产（`.inputactions`），按玩法加 action map 与 action。**这一步是生成器的输入源**——生成器只读 action 名和 `expectedControlType`，不碰任何具体设备。

具体步骤：
- **新建资产**：`Project` 右键 → `Create → Input Actions`，双击打开编辑器。
- **加 map**：例如 `UI`、`Sense`（map 名之后要**原样**填进 `InputComponentMapping`）。
- **加 action 并设好「控制类型（Control Type / `expectedControlType`）」**——这直接决定生成组件里字段的类型（对照见上文「富状态组件语义」表）：
  - `Submit`（Button）、`Cancel`（Button） → 字段 `InputButton`
  - `NavMove`（Vector 2）、`Look`（Vector 2） → 字段 `InputVector2`
  - `Aim`（Vector 3） → 字段 `InputVector3`
  - `Scroll`（Axis） → 字段 `InputAxis`
  - **没设控制类型会兜底成 `InputButton`**（按按钮处理），拿不到向量。
- **绑定设备**（键盘/手柄/鼠标）随意，生成器不关心设备——设备配对（`InputUser`）永远在游戏层。

示例（与 `Samples~/HYCSimple/Input` 一致，可直接抄）：
- map `UI`：`Submit`(Button)、`NavMove`(Vector2)、`Scroll`(Axis)
- map `Sense`：`Look`(Vector2)、`Fire`(Button)

### 2. 建映射资产并填 map 去向

`Project` 右键 → `Create → HYC Framework/Input/Input Component Mapping`，或菜单 `HYC Framework/Input/Generate Input Components` 时按提示建。
填：
- `Asset`：上面的 `.inputactions` 资产。
- `Maps` 列表，每一项：
  - `mapName`：要生成的 action map 名（须与资产里完全一致）。
  - `outputFolder`：生成 `.cs` 的文件夹（相对工程根）。**该文件夹归属的 asmdef 即"包"**——不同 map 指向不同文件夹 = 不同包。
  - `ns`：生成代码命名空间（如 `Game.Input.UI`）。
  - `componentName`：留空 = `mapName + "InputComponent"`。

> 分包示例：`UI` → `Assets/Game/Input/UI`（包 `Game.Input.UI`）；`Sense` → `Assets/Game/Input/Sense`（包 `Game.Input.Sense`）。两包互不可见，各自只引用 `HYC.Framework.Runtime`，靠 `InputMapWriterRegistry` 的接口契约解耦。

### 3. 跑生成器

菜单 `HYC Framework/Input/Generate Input Components`（扫描工程里所有 `InputComponentMapping` 资产并生成）。
也可在 Mapping 资产上右键 → `Assets/HYC Framework/Input/Generate This Mapping (Input Component)`（CONTEXT 菜单带 `Assets/` 前缀）。
另外 `InputComponentPostprocessor` 监听 `.inputactions` 资产导入 → 自动重跑生成（与 Attr/BT 一致，改了动作定义下次编译即同步）。

生成产物：
- 组件 `public struct <Map>InputComponent : IComponentData`，字段类型由 action 的 `expectedControlType` 决定（见下表）。
- 写入器 `public sealed class <Map>InputComponentWriter : IInputMapWriter`，`MapName => "<map>"`，
  并在静态构造里 `[RuntimeInitializeOnLoadMethod] RegisterSelf()` 把自己注册进 `InputMapWriterRegistry`。
- 若目标文件夹**缺 asmdef**，自动补一个最小 asmdef（引用 `HYC.Framework.Runtime / Unity.Entities / Unity.Collections / Unity.Mathematics / Unity.InputSystem`）。已存在则不覆盖。

### 4. 玩家接入（每玩家实体）

```csharp
// 引导 / 玩家加入时（游戏层）
var player = em.CreateEntity();
UIInputComponent.AddTo(em, player);     // 便捷挂载（生成器产出）
SenseInputComponent.AddTo(em, player);
// 设备配对由 InputUser 在游戏层完成；把"该玩家自己的" InputActionAsset 实例交给框架
InputPlayerRegistry.Register(player, myAssetInstance);
```

> `AddTo(em, player)` 是 **`InputComponentGenerator` 随组件一起产出的静态扩展方法**（写在生成文件里，如 `UIInputComponent.AddTo`），不是你手写的——直接调用即可把组件挂到玩家实体。它等价于 `em.AddComponent<UIInputComponent>(player)`。同理 `SenseInputComponent.AddTo` 等每个生成的组件都有。

> ⚠️ **每名玩家需要独立的 `InputActionAsset` 实例**（对同一资产定义 `Instantiate` / `Clone` 各一份）。
> 因为 `InputPlayerRegistry` 按"实体 ↔ 资产实例"登记，`prev` 边沿表是**每玩家一份**；共享同一实例会让多名玩家的边沿/启用状态串味。

### 5. 读取

```csharp
// 在某 System 里（例如挂在 UpdateGroup_B9 表现组）
if (SystemAPI.HasComponent<UIInputComponent>(player))
{
    var ui = SystemAPI.GetComponent<UIInputComponent>(player);
    if (ui.Submit.pressed)        Confirm();          // 按钮点亮
    if (ui.NavMove.active)        MoveCursor(ui.NavMove.value); // 摇杆有偏移
    if (ui.Submit.justPressed)    PlayClick();        // 本帧刚按下
}
```

## 富状态组件语义

生成器按 `expectedControlType` 选类型（见 [InputState.cs](./100-文件与类索引.md)）：

| `expectedControlType` | 字段类型 | 关键属性 |
| --- | --- | --- |
| `Button` | `InputButton` | `pressed`（= `value >= 0.5f`）、`justPressed`、`justReleased` |
| `Axis` | `InputAxis` | `active`（= `|value| > 1e-5f`）、`justPressed`、`justReleased` |
| `Vector2` / `Stick` | `InputVector2` | `value (float2)`、`magnitude`、`active`（= `magnitude > 1e-5f`） |
| `Vector3` | `InputVector3` | `value (float3)`、`magnitude`、`active` |
| `Quaternion` | `InputQuaternion` | `value (quaternion)`（一般不关心边沿） |
| `Integer` / `Discrete` | `InputInteger` | `value (int)`、`justPressed`（值变化即触发） |
| 未设 / 未知 | `InputButton`（兜底） | 按按钮处理 |

所有富状态 struct 均**纯数据、不引用 InputSystem**，可进任意宿主 asmdef、可随实体序列化/传输。
`phase` 字段为 `byte`（[`InputActionPhaseKind`](./100-文件与类索引.md) 取值 `Disabled/Waiting/Started/Performed/Canceled`），便于调试时看动作相位。
边沿（`justPressed/justReleased`）由 `InputRead` 用每玩家 `prev` 表跨帧比较算出，无需宿主操心。

## 本地多人（运行时动态加入）

玩家数量 = 运行时实体数量，**不是启动时写死**。先 1 人玩，按键再加第 2 人；设备组合可以是
键盘+手柄、手柄+键盘、手柄 A+手柄 B——**生成代码设备无关，设备分配 / 加入逻辑一律在游戏层**。

框架提供便捷监听器 [`LocalPlayerJoinDetector`](./100-文件与类索引.md)（基于 `InputUser.onUnpairedDeviceUsed`）：

```csharp
// 想接收"有人按了未配对设备"的时机
LocalPlayerJoinDetector.OnJoinRequested += device =>
{
    // 游戏层决定：是否还能加人？新建玩家实体？把 device 配对给新玩家？
    var user = InputUser.PerformPairingWithDevice(device);   // 设备配对
    var assetInstance = Instantiate(myActionAssetTemplate);   // 该玩家独立的资产实例
    user.AssociateActions(assetInstance);
    var player = em.CreateEntity();
    UIInputComponent.AddTo(em, player);
    InputPlayerRegistry.Register(player, assetInstance);
};
LocalPlayerJoinDetector.Start();   // 开启监听（引用计数，多次 Start 安全）
// 不想收了：LocalPlayerJoinDetector.Stop();
```

- `LocalPlayerJoinDetector` 只负责**发出"有未配对设备被按了"的事件**（回调一个 `InputDevice`），
  具体的配对 / 建实体 / `Register` / 人数上限 / P1 默认设备，全部由游戏层裁决。
- 内部用 `++InputUser.listenForUnpairedDeviceActivity` 开启系统级监听（计数器，按需开关，不泄漏）。

## 用法示例：ECS 里用 vs UI 里用

### 完整生命周期三步走

1. **生成**（编辑器）：建 `InputComponentMapping` → 菜单 `Generate Input Components` → 产出 `UIInputComponent` / `SenseInputComponent` 等组件 + Writer。
2. **接入**（运行时，游戏层）：建玩家实体 → `XxxInputComponent.AddTo(em, player)` → `InputPlayerRegistry.Register(player, assetInstance)`（每玩家独立资产实例）。
3. **读取**（每帧）：`InputComponentDriverSystem`（挂在 `UpdateGroup_A0`）每帧把输入写进组件；你的系统**在 A0 之后**查组件即可。

> 读取时序铁律：驱动系统在 `A0` 写入，因此任何读取系统必须挂在 `A1/A2/A3/B9` 或 UI 组（都晚于 A0）。UI 组天然晚于 A0，安全。

### ECS 里用（游戏逻辑系统）

典型的「每帧读输入驱动世界状态」——移动、开火、技能蓄力等。用 `SystemAPI.Query` 拿到组件，按值判断 `pressed/active/justPressed/magnitude`：

```csharp
using Unity.Collections;
using Unity.Entities;

[UpdateInGroup(typeof(UpdateGroup_A0))]   // 或你的逻辑组，只要晚于输入写入即可
public partial class MoveSystem : SystemBase
{
    protected override void OnUpdate()
    {
        // Entities 1.0：Query 泛型参数须实现 IQueryTypeParameter（Entity 已不在列），
        // 要同时拿 Entity 与组件改用 EntityQuery + 数组遍历
        var q = GetEntityQuery(typeof(SenseInputComponent));
        var players = q.ToEntityArray(Allocator.Temp);
        var senses = q.ToComponentDataArray<SenseInputComponent>(Allocator.Temp);
        try
        {
            for (var i = 0; i < players.Length; i++)
            {
                var s = senses[i];
                if (s.Fire.justPressed) TryFire(players[i]);   // 本帧刚按下 → 触发一次
                if (s.Move.active)                             // 摇杆有偏移
                {
                    var dir = s.Move.value;                    // float2，摇杆偏移量
                    ApplyMove(players[i], dir, SystemAPI.Time.DeltaTime);
                }
            }
        }
        finally
        {
            players.Dispose();
            senses.Dispose();
        }
    }
}
```

要点：
- `RefRO<T>` 表示只读引用，**不会破坏驱动系统的写入**（写用 `SetComponentData`，读用 `RefRO`，互不打架）；上述 `ToComponentDataArray` 拿的是值副本，同理只读。
- `justPressed` 已是跨帧算好的边沿，开火/确认这类「触发一次」直接用，无需自己比对上一帧。
- 想按玩家分别处理？数组里的 `players[i]`（`Entity`）就是键（与 `senses[i]` 同序配对）。

### UI 里用（窗口系统，本身即 `SystemBase`）

HYC 框架的 UI 窗口是 ECS 系统（`AbsUISystem : SystemBase`）。UI 要的是「本地人类玩家的 UI map 输入」——确认 / 取消 / 导航光标。直接从注册表取本地玩家实体，查 `UIInputComponent` 即可：

```csharp
using Unity.Entities;

public partial class GameMenuSystem : AbsUISystem
{
    private Entity LocalPlayer()
    {
        // 本地玩家：注册表第一个（单机 UI 只有一个本地玩家；多人时按你的"本地玩家"规则挑）
        foreach (var kvp in InputPlayerRegistry.Slots) return kvp.Key;
        return Entity.Null;
    }

    protected override void OnUpdate()
    {
        var p = LocalPlayer();
        if (p == Entity.Null || !SystemAPI.HasComponent<UIInputComponent>(p)) return;
        var ui = SystemAPI.GetComponent<UIInputComponent>(p);

        if (ui.Submit.justPressed) Confirm();        // 确认
        if (ui.Cancel.justPressed) CloseSelf();       // 取消 / 关窗
        if (ui.NavMove.active) DriveCursor(ui.NavMove.value);  // 摇杆/方向键导航光标
        if (ui.Submit.pressed)  UpdateHoldProgress(ui.Submit.value); // 按住进度（持续态）
    }
}
```

UI 与 HotkeyManager 的分工（详见 [40-输入与热键](./40-输入与热键.md)）：
- **组件化（本篇）**：适合**持续态**——按住进度、摇杆导航、连续数值（`pressed/active/value` 每帧可查）。
- **HotkeyManager**：适合**事件**——「按一次回调一次」的菜单确认、热键提示、按钮音；靠动作名注册，不关心当前值。
- 两者共享同一份 `InputActionAsset`，可同时用，互不干扰。

> 取本地玩家实体还有一种更稳的做法：游戏层在接入时把「本地玩家 `Entity`」存进一个单例组件 / 静态字段，UI 直接读，不必每帧遍历 `InputPlayerRegistry.Slots`。

### 底层回调式注册（UI 不必自己写 System，直接 `RegisterHandler`）

如果你只是想在 UI / 某处「每当输入更新就收到一次脉冲」，但又不想写一整个 `SystemBase` 每帧 Query 组件——框架在 `InputPlayerRegistry` 上提供了回调注册：

- **注册**：`InputPlayerRegistry.RegisterHandler<TComp>(player, comp => { ... })`
- **触发**：由 `InputComponentDriverSystem`（A0）在**写完本玩家全部输入组件后**立即回调，回调里拿到的是**本 tick 刚写好的最新组件值**。
- **注销**：`InputPlayerRegistry.UnregisterHandler<TComp>(player)`（或 `Unregister(player)` 一刀切清掉该玩家所有回调）。

签名 `Action<TComp>` 直接给你组件，省去再查一次实体。按组件类型**分桶**——`UI` 的回调只看 `UIInputComponent`、`Sense` 的回调只看 `SenseInputComponent`，互不干扰。这正是你想要的「底层处理、直接 `Registe(xxx, yyy => {})`」形态：

```csharp
// 在 UI 系统 / 任意初始化处（拿到本地玩家实体 player 后）
InputPlayerRegistry.RegisterHandler<UIInputComponent>(player, ui =>
{
    if (ui.Submit.justPressed) Confirm();                     // 本帧刚按下 → 确认一次
    if (ui.Cancel.justPressed) CloseSelf();                   // 取消 / 关窗
    if (ui.NavMove.active)    DriveCursor(ui.NavMove.value);  // 摇杆/方向键导航光标
    if (ui.Submit.pressed)    UpdateHoldProgress(ui.Submit.value); // 按住进度
});

// 同样的写法，玩法侧监听 Sense 组件
InputPlayerRegistry.RegisterHandler<SenseInputComponent>(player, sense =>
{
    if (sense.Fire.justPressed) TryFire(player);
    if (sense.Move.active)     ApplyMove(player, sense.Move.value, dt);
});
```

要点：
- **零 `SystemBase`**：你只写一个 lambda，底层在 A0 写组件后直接回调你，不用自己挂组、不用自己 Query。
- **时序保证**：回调在 A0 写完后触发，组件值即本帧最新；回调内只读组件即可（它跑在输入采样组里，别在里面做改写世界状态之外的重活）。
- **注册粒度 = 每玩家实体**：本地多人时给哪个 `player` 注册就收哪个玩家的输入；单机 UI 只有一个本地玩家。
- **回调里自由读 `justPressed/active/pressed/value`**，边沿已由框架算好，与你在 `System` 里读组件完全一致。
- 想彻底停收某玩家全部输入：`InputPlayerRegistry.Unregister(player)`（同时清掉该玩家的资产监听与所有回调）。

## 关键类清单

| 类 / 文件 | 层 | 职责 |
| --- | --- | --- |
| `InputComponentMapping` / `InputMapTarget` | Editor | 映射配置资产：资产 + 每 map 的输出去向 |
| `InputComponentGenerator` | Editor | 主生成器：读 Mapping → 按 map 生成组件 + Writer + 兜底 asmdef |
| `InputComponentGeneratorMenu` | Editor | 菜单 `HYC Framework/Input/Generate Input Components` + 资产右键菜单 |
| `InputComponentPostprocessor` | Editor | `.inputactions` 导入即自动重生成 |
| `InputPhase`（`InputActionPhaseKind`） | Runtime | 相位枚举（byte 承载，组件里不引 InputSystem） |
| `InputState`（`InputButton` 等 6 个 struct） | Runtime | 富状态输入分量定义 |
| `InputRead` | Runtime | action → 富状态 struct + 边沿计算（被 Writer 调用） |
| `IInputMapWriter` | Runtime | 单 map 写入器契约（生成 Writer 实现并自注册） |
| `InputMapWriterRegistry` | Runtime | 写入器静态注册表（驱动系统只读这张表） |
| `InputPlayerRegistry` | Runtime | 玩家注册表：实体 ↔ 该玩家资产实例（支持动态加入/退出）；并提供 `RegisterHandler<TComp>/UnregisterHandler<TComp>/InvokeHandlers` 的底层回调式输入（A0 写组件后即时回调） |
| `InputComponentDriverSystem` | Runtime | `UpdateGroup_A0` 驱动系统，每帧写所有玩家组件（未标 `[DisableAutoCreation]`，自动装配） |
| `LocalPlayerJoinDetector` | Runtime | 本地多人"未配对设备被按即加入"事件（游戏层裁决） |

## 注意事项 / 坑

1. **每名玩家要独立 `InputActionAsset` 实例**——共享实例会让边沿与启用状态跨玩家串味（见上文）。
2. **生成代码设备无关**：生成器只认 action 名与 `expectedControlType`，不碰任何具体设备；设备配对（`InputUser`）永远在游戏层。
3. **组件字段按 `expectedControlType` 定**：action 没设控制类型会兜底成 `InputButton`（按按钮处理）。要拿向量就得在 Input System 里把 action 设成 `Vector2` 等。
4. **`prev` 边沿表按 `mapName:field` 拼 key，存在玩家注册槽里**，因此同一 action 名在不同 map 互不干扰；换资产实例 / 注销玩家会清空。
5. **写入器通过 `[RuntimeInitializeOnLoadMethod]` 自注册**，所以生成代码所在 asmdef 必须能被加载（默认 `autoReferenced: true`，已生成 asmdef 满足）。若宿主把生成的包设成 `autoReferenced: false`，需手动保证它被引用。
6. **驱动系统未标 `[DisableAutoCreation]`**，会被框架自动装配进 `UpdateGroup_A0`（输入 tick 采样组），宿主无需手动接线；若想关掉，给 `InputComponentDriverSystem` 加 `[DisableAutoCreation]` 并在合适位置手动 `World.GetOrCreateSystem` 即可。
7. **`AssetPostprocessor` 靠 `EditorApplication.delayCall` 延后生成**，避免导入流程重入；若工程很大、`.inputactions` 频繁改动，留意生成发生在编译后而非导入瞬间。
8. **`RegisterHandler<TComp>` 的回调跑在 `UpdateGroup_A0`（输入采样组）内、写完组件后**：回调里只读组件、做轻量响应（确认/导航/触发一次）即可，**不要在回调里改写世界状态或做重活**——它和驱动系统同组，重活会拖慢整条输入采样链路；需要改世界的逻辑仍应走正规 `System`（在 A0 之后的组里跑）。
