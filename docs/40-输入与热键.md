# 40 · 输入与热键（Hotkey）

## 职责

基于 **Unity Input System** 的动作名 → 回调注册中心。框架不依赖游戏生成的枚举，一律用**字符串动作名**。

命名空间：**`HYC.Framework.Input`**

一句话：**`HotkeyManager` 是个静态注册表，把 InputSystem 的 Action 事件分发给多个回调，并按窗口焦点自动静默。**

---

## 核心类

| 类 / 文件 | 职责 |
| --- | --- |
| `HotkeyManager` | 静态注册表与分发器 |
| `HotkeyHandle` | 轻量 `struct` 句柄（只装一个 `int ID`），所有读写都代理回 Manager |
| `HotkeyInputContext` | 统一回调载荷（包装 `InputAction.CallbackContext` 或合成的 UI 事件） |
| `HotkeyInputPhase` | 相位枚举：`Disabled/Waiting/Started/Performed/Canceled/End` |
| `HotkeyMode` | `Press` / `Hold` |
| `InputDevice` | `None / KeyboardAndMouse / Gamepad / Touch` |
| `HotkeyActionNames` | 框架 UI 栈用到的动作名常量 |
| `IHotkeyElement` / `BaseHotkeyElement` | 热键提示 UI 元素契约 / 抽象基类 |
| `HotkeyElementStyle` | 提示样式：`UI / UI_SIMPLE / HUMAN_INTERACTIVE / SHIP_INTERACTIVE / UI_ICON` |
| `HotkeyElementLayout` | 自动换行的 `LayoutGroup` |

---

## 初始化

```csharp
// 引导期（宿主做一次）
HotkeyManager.BindAsset(myInputActionAsset);
```

- `BindAsset` 会 `UnregisterAll()` **清空已有注册**，然后订阅 `InputSystem.onActionChange`。
- 也可以直接 `HotkeyManager.InputAsset = asset;`（不清空、不订阅）。
- ⚠️ **重复调 `BindAsset` 会重复订阅 `onActionChange`**（没有先退订），回调会执行多次。要换资产就先用 `InputSystem.onActionChange -= ...` 的思路规避，或只调一次。

动作查找：`ResolveAction(name)` 遍历 **所有 actionMap**，用 `map.FindAction(name)` 找第一个匹配——**靠名字，不靠 map 限定**。

## 注册

```csharp
// 完整签名
public static HotkeyHandle RegisterHotkey(
    string actionName,
    Action<HotkeyInputContext> callback,
    float holdTime = 0,                              // > 0 → Hold 模式
    Transform parent = null,                         // 提示元素挂载点
    string text = null,                              // 提示文本
    HotkeyElementStyle style = HotkeyElementStyle.UI,
    int priority = 0)
```

```csharp
var h = HotkeyManager.RegisterHotkey("UI_ESC", ctx =>
{
    if (ctx.started) CloseSelf();
});
```

- **动作找不到 → `Debug.LogError($"RegisterHotkey failed, action not found: {actionName}")` 并返回 `ID = 0` 的无效句柄**。
- `ID` 从 1 开始自增，`ID == 0` 恒表示无效（`UnregisterHotkey` 会直接 return）。
- 内部路径 `InputActionPath = "{actionMap.name}/{action.name}"`，**这是分发的 key**——同一个 Action 的多个注册共享一个回调列表。
- 注册时给 Action 订阅 `started / performed / canceled`（先 `-=` 再 `+=`，重复注册不会叠加）。

### Press vs Hold

| 模式 | 触发的相位 |
| --- | --- |
| `Press`（`holdTime <= 0`） | `started` / `performed` / **`cancelled`** 都会调 |
| `Hold`（`holdTime > 0`） | 只有 `started` / `performed` |

⚠️ **Press 模式一次点击通常回调 2~3 次**（Started → Performed → Canceled）。**必须自己用 `ctx.started` / `ctx.performed` 过滤**，否则逻辑会跑多遍。

### 分发顺序与中断

```csharp
private static void OnNativeCallback(InputAction.CallbackContext context)
{
    var path = $"{context.action.actionMap.name}/{context.action.name}";
    if (!_pathToIDs.TryGetValue(path, out var ids)) return;

    var ctx = HotkeyInputContext.CreateFrom(context);
    for (var i = 0; i < ids.Count; i++)
    {
        if (_needStopInvoke) { _needStopInvoke = false; break; }   // 可被中断
        if (_idToState.TryGetValue(ids[i], out var hotkey)) Dispatch(hotkey, ctx);
    }
}
```

- 顺序 = **注册顺序**；源码里有个 `_sortedIDs` 字段但**从未被使用**，所以 `priority` **目前不参与排序**（只存着）。
- 回调里调 `HotkeyManager.StopCurrentInvokeList()` 可以中断本次后续分发——**在当前回调返回后才生效**（标志位在下一轮循环开头检查），用于"顶层窗口吃掉这次输入"。
- `Dispatch` 前置检查：`!Enabled || Silence` 直接 return。

## 句柄操作

`HotkeyHandle` 是 struct，属性直接代理：

```csharp
h.Text = "使用";          // 提示文本
h.Silence = true;        // 静默（UI 失焦时框架自动设）
h.Visible = false;       // 隐藏提示
h.Enable = false;        // 禁用分发
h.DisableTime = 0.5f;    // 置灰时间（框架不消费，给宿主 UI 用）
```

对应的 Manager 静态方法也公开：`SetSilence / SetVisible / SetEnabled / SetText / SetDisableTime` 与 `Is*` / `Get*`。

⚠️ **句柄是值类型且 ID 永不复用**——注销后再操作只是空操作（查不到就返回 false/null），不会误伤别人。

## 设备与导航模式

```csharp
HotkeyManager.SetCurrentDevice(InputDevice.Gamepad);   // 变了才触发事件
HotkeyManager.SetNavigateMode(true);                   // UI 手柄导航开关
HotkeyManager.CurrentCursorPosition = Input.mousePosition;
```

| 成员 | 说明 |
| --- | --- |
| `CurrentDevice` | 默认 `KeyboardAndMouse`；变化触发 `OnInputDeviceChanged` + `UpdateAllHotkeyIcons()` |
| `IsKeyboardMouseDevice` | `CurrentDevice == KeyboardAndMouse` |
| `IsNavigateMode` | 变化触发 `OnNavigateModeChanged` |
| `OnInputDeviceChanged` | `Action<InputDevice>` |
| `OnNavigateModeChanged` | `Action<bool>` |

设备变化或 Action 绑定变化（`InputActionChange.BoundControlsChanged`）时会 `UpdateAllHotkeyIcons()` → 对所有 `state.Element` 调 `RefreshIcon()`。

⚠️ **`HotkeyState.Element` 从不被 `HotkeyManager` 自己赋值**（框架里没有创建提示元素的代码），需要宿主在创建提示 UI 时手动塞进 `state.Element`。当前注册 API 只传 `Parent`/`Text`/`Style`，**提示元素的实例化要宿主自己接**。

## 与 UI 的联动

- `AbsUISystem` / `BaseWindowPart` 的 `RegisterHotkey(...)` 会把句柄存进内部列表；
- 窗口 `OnViewLost()` → 所有热键 `Silence = true`；`OnViewFocus()` → `false`；
- 窗口 `OnViewClose()` → `UnregisterAllHotkey()`；
- `UIManager.ResetGUIInput()` 根据是否有可聚焦窗口调 `SetNavigateMode`。

详见 [31-窗口系统](./31-窗口系统.md)。

## 回调载荷（HotkeyInputContext）

```csharp
ctx.started / ctx.performed / ctx.cancelled / ctx.ended   // bool，由 phase 派生
ctx.phase                                                  // HotkeyInputPhase
ctx.time / ctx.startTime / ctx.duration                    // double
ctx.ReadValue<TValue>()        where TValue : struct       // 非原生返回 default
ctx.ReadValueAsObject()
ctx.GetHoldProgress()                                      // Clamp01((time-startTime)/duration)
ctx.Native                                                 // 原始 CallbackContext
ctx.isFromUI / isFromNative / isFromKeyboardMouse / isButtonSchema
```

三种构造：

| 工厂 | 用途 |
| --- | --- |
| `CreateFrom(CallbackContext)` | 原生输入 |
| `CreateFrom(CallbackContext, bool isButtonSchema)` | 指定是否按钮型 |
| `CreateFrom(phase, time, startTime, duration, isFromUI)` | **合成 UI 事件**（action/control 为 null，`ReadValue` 返回 default） |

⚠️ 合成事件里 `isButtonSchema` 恒为 `true`，`valueType` 为 null。

## 框架内置动作名（HotkeyActionNames）

宿主的 InputManager **必须暴露同名 Action**（UI map），否则 UI 栈的导航/通用按钮会注册失败：

**功能键**：`UI_FuncA/B/X/Y`、`UI_FuncLT/RT`、`UI_FuncL3/R3`

**UI 导航**：`UI_NavUp/Down/Left/Right`、`UI_NavNegative/Positive`、`UI_ESC`、`UI_Enter`、`UI_ReleaseCursor`、`UI_MouseLeft/Middle/Right`

**UGUI 虚拟光标导航**（`AbsUISystem.Enable()` 会注册这四个）：
`UI_UGUI_Horizontal`、`UI_UGUI_Vertical`、`UI_UGUI_Submit`、`UI_UGUI_Cancel`
另有 `UI_UGUI_Stick1/2`、`UI_UGUI_Button1/2` 备用。

**玩法映射**（框架不强制，给宿主参考）：`Human_ESC/MoveAxis/Interactive`、`Ship_ESC/MoveAxis/CameraAxis/Interactive`

## 提示元素（BaseHotkeyElement）

宿主继承它做按键提示 UI：

```csharp
public class MyHotkeyElement : BaseHotkeyElement
{
    public override Sprite KeyIcon { get; set; }
    public override string DescText { get; set; }
    public override float Progress { get; set; }     // 长按进度 0..1
    public override void RefreshIcon() { /* 按 CurrentDevice 换图标 */ }
    public override void PlayStartAnim() { }
    public override void PlayFinishAnim() { }
    public override void Reset(HotkeyManager.HotkeyState s) { m_State = s; }
    public override void Clear() { }
    public override void OnPointerDown(PointerEventData e) { }
    public override void OnPointerUp(PointerEventData e) { }
}
```

- `[RequireComponent(typeof(Button))]`，`Awake` 里取 `m_Button`。
- `onClick` 直接暴露 `m_Button.onClick`。
- `FindComponent<T>(path)` 便捷查找子节点。

**布局**：用 `HotkeyElementLayout`（继承 `LayoutGroup`）当容器，它按子元素 `rect.width` 自动换行，支持 `spacing` 与 `childAlignment`。

⚠️ `HotkeyElementLayout` 只实现了 `SetLayoutVertical`；`SetLayoutHorizontal` 与 `CalculateLayoutInputVertical` 是空的——**宽度由父布局给**，自己不算。

## 注意事项 / 坑

1. **Press 模式一次按下回调多次**，务必用 `ctx.started`/`ctx.performed` 过滤。
2. **`priority` 不生效**——`_sortedIDs` 未使用，分发顺序就是注册顺序；要靠优先级就自己控制注册时机或用 `StopCurrentInvokeList()`。
3. **`BindAsset` 重复调用会重复订阅 `InputSystem.onActionChange`**，图标刷新会跑多次。
4. **`InputAsset == null` 时所有注册都失败**（返回 ID=0 + LogError），`AbsUISystem` 仍会把这个无效句柄存进列表——所以**引导期必须先 BindAsset**。
5. **`UnregisterAll()` 不重置 `_autoID`**，也不清 `Priority` 之类；它只退订事件 + 清字典。
6. **`Interactable` 在注册瞬间就固定为 `CurrentDevice == KeyboardAndMouse`**，之后换设备不会更新这个字段（只刷图标）。
7. **`HotkeyState.Element` 没人赋值**，提示元素要宿主自己创建并塞进去，`UpdateAllHotkeyIcons()` 目前实际是空转。
8. **动作按名字全局查找**，不同 actionMap 里有同名 Action 会命中第一个——给动作起全局唯一名。
9. **`DisableTime` 只存不消费**，是给宿主 UI 做置灰倒计时的。
