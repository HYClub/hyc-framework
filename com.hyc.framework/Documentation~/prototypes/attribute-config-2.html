属性配置：目录 / 组合 / 生成访问器

v2 配置表驱动 回答三个问题：①目录是一堆属性 ②组合是数据不是代码 ③可 codegen 访问器让代码更好用
问题 1：配置就是写一堆属性，不管谁有谁没有。目录是扁平全量的 AttributeDef 行（由配置管线生成），它不关心归属——"HP/ATK" 只是两条并列的定义。

属性目录（全量，扁平）

每条 = 一个属性定义。下面随便加/改，右栏组合和底部的生成访问器会同步。

key类型默认minmax显示名

角色组合（编辑器勾选 = 数据）

问题 2：组合是编辑器里勾选的数据，不是代码。勾完存成一串 ConfigRowRef，运行时 AttributeInitializer.Init 消费。不需要生成代码。

[可选] 从目录生成便捷访问器（让代码更好用）

问题 3：想代码里更方便，可额外从目录 codegen 一个 AttrAccess：预哈希 key + 类型安全 Get/Set。它和"组合"无关，纯属调用 convenience 层。


  

    一句话总结工作流： 目录（Excel→生成 AttributeDef 行）→ 在实体编辑器里勾选它引用哪些（数据）→ 运行时 Init 出属性袋。
    想要代码好用就再 codegen 一个 AttrAccess。组合本身永远是数据，不进代码。
  







  
1) 裸 API 用法（框架直接给的）

  
// 按 key 字符串读写，key 运行时 FNV-1a 哈希；拼错 key 只能运行期发现
int  atk = AttributeStore.GetInt (em, hero, "ATK");
AttributeStore.SetInt (em, hero, "ATK", atk + 10);   // 越界自动钳制
float spd = AttributeStore.GetFloat(em, hero, "MoveSpeed");


  
2) 生成访问器用法（codegen 出来的 AttrAccess）

  
// 预哈希 key 编译期算好；Get/Set 类型安全；拼错方法名编译期就报错；省掉每帧哈希
int  atk = AttrAccess.GetATK(em, hero);
AttrAccess.SetATK(em, hero, atk + 10);
float spd = AttrAccess.GetMoveSpeed(em, hero);
