# 70 · 消息与日志

## 一、消息（MessageEntity）

### 设计

配置/事件以**单帧实体**在 ECS 里流动：创建 → 同帧内被若干系统读取 → 帧末销毁。

| 类型 | 命名空间 | 说明 |
| --- | --- | --- |
| `Message` | `HYC.Framework.Dots` | 标记「这是一条消息」（源框架的 `Message` 契约） |
| `MessageEntity` | 同上 | 标记「单帧消息实体」——`MessageClearSystem` 帧末清掉整个实体 |
| `DestroyEndOfFrame` | 同上 | 标记「帧末可删」，由 `MessageExpirySystem` 清掉 |
| `EventMessage` | 同上 | 消息载荷：`int EventID` + `bool IsRepeated` |
| `MessageAttribute` / `StatusAttribute` | 同上 | 给消息/状态组件加 `Desc/Group/Order` 元数据（编辑器组件浏览器用） |

### 生命周期

```
SystemAPI.CreateEntity()
  .AddComponent<Message>()          // 可选，语义标记
  .AddComponent<MessageEntity>()    // 关键：让 MessageClearSystem 清它
  .AddComponent(new EventMessage { EventID, IsRepeated })
        ↓ 同帧内（A3 玩法 / B9 UI）多个系统用 SystemAPI.Query 读取
        ↓
MessageClearSystem   [UpdateInGroup(SimulationSystemGroup), OrderLast = true]
  → DestroyEntity(所有带 MessageEntity 的实体)
```

- **`MessageClearSystem` 在 `SimulationSystemGroup` 末尾（OrderLast）**跑——保证 A0~A3 全部读完后再清。
- **`MessageExpirySystem` 在 `UpdateGroup_B9`（OrderLast）** 跑——比 `MessageClearSystem` 更晚，专清 `DestroyEndOfFrame` 标记的实体（游戏逻辑在 A3 消费、UI 在 B9 消费完才清）。

⚠️ 两个清理系统**顺序极其讲究**：源码注释明确说原来用 `EndSimulationEntityCommandBufferSystem` 排序会跨级抛 NRE（`EndSimulation` 在 `LateSimulationSystemGroup` 里，永远晚于整个 `UpdateGroup_B9`）。**不要改它们的 `[UpdateInGroup/OrderLast]`**。

### 用法

```csharp
// 发一条引导弹窗消息（UI 窗口基类 AbsUISystem.OpenGuide 内部就这么干）
var e = ecb.CreateEntity();
ecb.AddComponent<MessageEntity>(e);
ecb.AddComponent(e, new EventMessage { EventID = 10023, IsRepeated = false });

// 消费系统
public partial struct GuideSystem : ISystem
{
    public void OnUpdate(ref SystemState state)
    {
        foreach (var msg in SystemAPI.Query<EventMessage>())
            ShowGuide(msg.EventID, msg.IsRepeated);
    }
}
```

⚠️ **`Message` 与 `MessageEntity` 是两个不同的标记**。只有带 `MessageEntity` 的实体会被 `MessageClearSystem` 清；光 `Message` 不会被自动清（它是给源 `com.qianking.game.MessageEntity` 概念留的兼容标记）。发消息请加 `MessageEntity`。

## 二、日志（Log / GameLog）

### Log（框架日志门面，写入文件 + 转发）

```csharp
Log.Open(dir = null);                       // 在 PersistentDataPath/logs 下开 framework_时间.log
Log.Trace(msg); Log.Info(msg); Log.Warn(msg); Log.Error(msg);
Log.Error(ex, "context");                   // 异常 → 字符串
Log.Format(LogLevel.Info, "玩家 {0} 升到 {1} 级", id, lv);
Log.Close();                                // flush + dispose

LogLevel : Trace(0) / Info(1) / Warning(2) / Error(3) / Fatal(4)
Log.OnLog += (level, row, a, b) => { /* 转服务器 */ };
```

行为：

- `Open` 幂等（已开直接 return）；`PersistentDataPath/logs` 自动建。
- 文件名：`framework_{yyyyMMdd_HHmmss}.log`（每次 Open 一个新会话）。
- `Write` 里**先写文件（lock），再按级别调 `Debug.Log/Warn/Error`，最后 `OnLog?.Invoke`**。
- 级别映射：Trace/Info → `Debug.Log`；Warning → `LogWarning`；Error/Fatal → `LogError`。
- `_file` 用 `StreamWriter { AutoFlush = true }`，崩溃前不丢。

### GameLog（Unity 原生日志钩子，写 log.json）

```csharp
GameLog.SaveLog = true;  GameLog.SaveLogWarning = true;  GameLog.SaveLogError = true;
GameLog.Startup(dataPath, true, true, true);   // 或靠 [RuntimeInitializeOnLoadMethod(AfterSceneLoad)] 隐式起
GameLog.LogFilePath;                            // 只读，debug 用
```

- 路径：`{dataPath}/../log.json`（**注意是 `dataPath` 的上一级**，不是 `persistentDataPath`）。
- 三个开关分别控制 Log / Warning / Error 是否落盘；全 false 则 `StartupInternal` 直接 return。
- 通过 `Application.logMessageReceived` 订阅 Unity 原生日志，**Hook 掉 `Debug.unityLogger.logHandler`**：
  - 非编辑器：每条日志前加 `[yyyy/MM/dd HH:mm:ss.fff]` 时间戳。
  - 编辑器：直接走原 handler（异常在 Console 看）。
  - `LogException`：非编辑器只打 `Exception` 占位 + 时间戳，真异常仍丢给原 handler。

⚠️ **`GameLog` 与 `Log` 是两套互不相关的日志**：`Log` 写 `PersistentDataPath/logs/*.log` 并带 `OnLog` 转发；`GameLog` 写 `dataPath/../log.json` 并劫持 `Debug.unityLogger`。不要以为开了 `Log.Open` 就自动接管 `Debug.Log`——要接管得 `GameLog.Startup`。

⚠️ `GameLog` 的 `dataPath/../log.json` 路径在打包后未必可写，且每次 `StartupInternal` 会**先删旧文件再追加**（`File.Delete` + `AppendAllText`）。

## 三、注意事项 / 坑

1. **消息实体必须同帧消费完**——下一帧 epic 就没了（`MessageClearSystem` 帧末清）。延迟处理（如等动画）请改用 `DestroyEndOfFrame` 或自己维护状态组件。
2. **发消息只加 `Message` 不行**，必须 `MessageEntity` 才会被自动清，否则实体泄漏。
3. **`EventMessage` 是 `IComponentData` 但非 blittable 友好**（含 bool，blittable），没问题；但别往消息实体上堆 `class` 组件。
4. **`MessageClearSystem` 要求 `RequireForUpdate<MessageEntity>()`**——没有消息实体时整个系统跳过（零开销）。
5. **两个清理系统别动排序**：改 `[UpdateInGroup/OrderLast]` 会让 Entities sorter 抛 NRE（已踩过）。
6. **`Log.OnLog` 是全局静态事件**，多系统订阅时要注意回调里别抛异常（`Write` 里没 try/catch `OnLog`）。
7. **`GameLog` 的 `DebugLogExt` 在 `StartupInternal` 里 `new` 一次**并替换 `Debug.unityLogger.logHandler`，**没有还原逻辑**——一旦装上去，整个会话的原生日志处理器都被替换（非编辑器下加时间戳）。测试环境要注意。
8. 命令行 `GameCommandArgs` 与日志无关，但常一起在引导期读；`--lang` 的优先级低于 `StartupSetting`/`LocalizationManager.SelectedLanguage` 解析链。
