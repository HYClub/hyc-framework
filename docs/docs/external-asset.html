外部资产 ·「外部配置」

把不是 HYC 生成的 Unity 资产（.inputactions、音频、贴图、材质…）挂进数据配置窗口统一管理。

做法是配置树底部的一个「外部配置」虚拟文件夹——只登记引用，文件本体留在原位置。

先搞清楚：它是虚拟的

「虚拟」不是说效果打折，而是它不是一个磁盘目录，只是一组 GUID 引用：

项说明
位置配置树最底部，恒定显示（即便一条都没有，好让人知道能往哪拖）
外观标签是独立青色（只有它染色，子节点保持默认色）
数据HYCSettings.IncludedAssetGuids，随工程提交、跨会话持久化
本体不动成员的资产文件不会被移动或复制，仍留在原路径

由「引用语义」推导出的三条约束

约束兜底机制
不可重命名（改名＝改真资产）CanRename 只认文件夹 / 文件节点
不可往外拖（无路径可搬）CanStartDrag 只认文件夹 / 文件节点
Delete 键不会误删真资产树没有接 KeyCode.Delete，命令行由指令入口处理

另外，选中它时点「新建配置」不会拿到空路径——GetTargetFolder() 遇到非文件夹/文件会回落到配置根目录。

唯一入口：拖到树的空白区

从 Project 窗口 把资产拖到左侧树的空白区（不能压在任何节点行上）松手即可。

拖入 → [过滤 + 分类] → 弹确认 → 登记 GUID → 重建树
                                        → 自动展开「外部配置」→ 选中并滚动到新项
⚠
必须落在空白区：压在具体节点行上时本控件返回 None（不处理），保持原有的「配置资产移动」语义。这是有意的设计，不是漏了——压在真实文件夹上就该是搬家。

被拒绝会说明原因

情况文案要点
拖了文件夹「外部配置」只登记单个资产
扩展名黑名单（代码 / 着色器 / UI 资源 / 程序集定义 / 预制体）不支持该文件类型
主类型黑名单（框架自产资产）它本就应该显示在配置树里
混合拖放（外部 + 内部配置资产）一次只能处理一种
◈
确认弹窗慢一拍是正常的：弹窗与写库都经 EditorApplication.delayCall 推出拖拽事务——拖拽回调里做 IO / 弹模态窗不稳。
混合拖放整批拒绝，不会「只收能收的」：两种语义互斥。

谁能进来：过滤器

ExternalAssetFilter 不持有状态，只有三个判断方法；扩展名与类型黑名单：

黑名单内容
扩展名.cs .js .ts .shader .compute .cginc .hlsl .uss .uxml .asmdef .asmref .prefab
类型ConfigBase 系、ConfigTemplate、ConfigEnumDefinition、BTTreeAsset、InputComponentMapping、HYCSettings、SceneContentAuthoring

过滤器的三个方法，以及注册表（AddIncludedAssetGuid / RemoveIncludedAssetGuid / ClearIncludedAssets / IsIncluded，写操作自带落盘）见框架文档。

日常操作

操作做法
加入Project 窗口拖到树空白区 → 确认
编辑选中成员 ⇒ 右栏嵌该资产的原生 Inspector（.inputactions 例外，见下）
定位右键「定位资源」（Project 窗口 Ping）
移除右键「从外部配置移除（不删除资产）」——只删注册表条目
清空右键文件夹「清空外部配置（仅移除引用）」——有二次确认

右栏：原生 Inspector，只有一处例外

选中外部资产节点
   ├─ .inputactions  → InputActionsAssetEditor（占位 + 「在官方编辑器中打开」按钮）
   └─ 其余            → UnityAssetEditor（整体嵌入原生 Inspector）

为什么 .inputactions 不做自建界面——三条源码级事实：

  1. 原生 Inspector 天生空白：Input System 的 InputActionAssetEditor 刻意留空（注释原文 “Editing happens in a dedicated window.”），OnInspectorGUI() 是空实现 ⇒ 嵌入没得看。
  2. 官方窗口拿不到句柄：它的两个编辑窗口都是 internal，InternalsVisibleTo 只列自家测试程序集。
  3. 没有「把 EditorWindow 挂进另一个面板」的公开 API：docked 只是只读状态；而本窗口是 IMGUI，UI Toolkit 的 VisualElement 无法在其中渲染。

所以定下口径：这类「编辑能力只在官方独立窗口」的资产，右栏一律做跳板，不重复实现官方功能（否则包一升级就腐化）。判断方法只有一步——看它有没有非空的 CustomEditor；是空的就必须专开跳板类。

坑

  • 引用 ≠ 导出：Ctrl+S 会把有修改的外部资产一并落盘，但真正带出去要靠导出流程遍历注册表。
  • 资产被删会留幽灵项（GUID 解析不到路径），安装时跳过，需手动右键移除清理。
  • prefab 在黑名单里：预制体走专门的场景/预设流程，不进数据配置树。
  • 移除类文案必须写明「不删除资产」，否则极易被误读成删文件。
◈
完整版（节点 ID 分段、Link 光标语义、delayCall 缘由、UnityAssetEditor 的销毁约束）见框架 Documentation~/15-外部资产集成.md。
