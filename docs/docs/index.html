HYC Framework 使用文档

一个基于 Unity 2022.3 + DOTS/ECS 的数据驱动框架：配置 / 本地化 / 行为树在生成与编辑期烘焙为不可变 Blob，UI 即 ECS System，世界由引导期组装、按固定阶段更新。

本站点逐模块说明「怎么用」，所有内容基于源码实测撰写。左侧选择模块，右侧为本页目录。

它解决什么

传统 Unity 项目里，配置、本地化、UI、AI 往往是各写一套、难复用、难跨端。HYC Framework 把它们统一成一套数据驱动管线：

  • 配置 / 本地化 / 行为树：编辑期是 ScriptableObject + 生成代码，运行期只有一个 Blob 指针，零分配查询。
  • UI 即 System：每个界面是一个 SystemBase 子类挂在固定更新组里，最后刷新（B9），不抢玩法帧。
  • 一套代码跨端：PC / iOS / Android / WebGL 共用 InitializeAsync 入口，平台差异全部由框架内部吸收。
◈
数据流四阶段：生成期（模板/Excel/行为树 → 代码生成 + 数据编辑）→ 引导期 A0/A1（装单例、加载配置）→ 运行期 A2/A3（模拟、技能、AI、战斗）→ 表现期 B9（UI 最后跑，读一帧前算好的状态）。UI 永远晚一帧看到玩法改的值，这是设计，不是延迟。

5 分钟跑通

最小引导只需要一个 MonoBehaviour 和一个异步入口：

// 全平台统一入口：WebGL/Android 会先把数据 HTTP 进内存缓存，PC/iOS 上是 no-op
public sealed class GameBootstrap : MonoBehaviour
{
    private async void Start()
    {
        await new FrameworkBootstrap().InitializeAsync("Game World");
        // 之后照常：装 UI、进主菜单……
    }
}

打开一个窗口（注意是异步的，初始化写在 OnViewOpen）：

public class BagWindow : BaseWindowSystem<BagBinder>
{
    public override string PrefabKey => "UI/BagWindow.prefab";
    public override void OnViewOpen(params object[] args)
    {
        base.OnViewOpen();
        Binder.CloseButton.onClick.AddListener(() => UIManager.Close<BagWindow>());
    }
}

// 打开窗口（异步！View 在 OnViewOpen 里才就绪）
UIManager.OpenWindow<BagWindow>(1001);

// 查配置 —— 门面是唯一入口，必须 ref 接收（EA0001 铁律）
ref var row = ref ConfigManager.ItemRow.GetByID(1001);
Debug.Log(row.Name);

⚠
开始之前请记住三条铁律：① 创建配置资产必须走 ConfigAssetFactory、创建行为树必须走 BTAssetFactory，禁止手填 ID / GUID / TreeId；② 配置行查询必须 ref var row = ref ... 接收（值拷贝 = 运行期内存错误）；③ 宿主禁止直接调用 ConfigRegistry，统一走生成式门面 ConfigManager。
