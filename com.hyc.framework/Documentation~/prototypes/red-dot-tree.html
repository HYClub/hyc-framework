HYC 框架 · 红点树系统 — UI 集成方案 v2

已按推荐锁定 D1–D5；本版重点细化如何接进现有「Binder 绑定 + System 窗口」制作链路，并把方法下沉到 UI System 基类。待你确认后进入编码。

① 核心改动：红点接进 UI System 生命周期

红点刷新由 窗口 System 驱动，而不是预制体上散落的 MonoBehaviour Update —— 与「UI 即 ECS System、最后运行读最新状态」一致。

OnViewOpen
自动收集 View 下所有 RedDotBehaviour → 逐个绑定（零代码）
→
OnChanged（变更时）
RedDotManager 变更事件 → RefreshRedDots() 只刷受影响绑定；值未变不写 SetActive
→
OnViewClose
全部解绑 + 退订事件（与 Binder 置空同一时机）

窗口未打开时其 System 不在更新列表 → 无需刷新；打开瞬间 OnViewOpen 做一次全量刷新，避免「打开时红点已亮却没刷」。

② 三层消费模型（同一 Manager，按需取用）

L1
预制体
零代码

美术/策划在预制体红点节点上挂 RedDotBehaviour（key 选择器 + 红点 GameObject + 可选数字 Text）。

基类 OnViewOpen 自动收集并绑定 —— 窗口代码一行都不用写。

key 在 Inspector 用下拉选择器从已注册树里选（复用 LocKey / AudioEvent 的「只能选不给手填」做法），拼错不可能。

L2
基类方法
代码驱动

在 AbsUISystem 新增 #region 红点（与「热键 / 部件窗口」同级分块）：

// 绑定：自动跟随刷新，Close 自动解绑
protected void BindRedDot(RedDotKey key, GameObject dot);
protected void BindRedDot(RedDotKey key, GameObject dot, Text count);
protected void BindRedDot(RedDotKey key, RedDotBehaviour b);
protected void UnbindRedDot(RedDotKey key);

// 查询 / 消费（何时清除由业务决定）
protected bool IsRedDotActive(RedDotKey key);
protected void ConsumeRedDot(RedDotKey key);

因为挂在 AbsUISystem，窗口 / HUD / 弹窗全部自动获得，无需每处重复实现。

L3
显式查询
逃生舱

需要精细布局时，窗口 OnViewUpdate 里直接 RedDotManager.IsActive(key) / GetCount(key)。

关键取舍：刷新用事件订阅（变更才刷）而非每帧轮询 —— 避免每帧 N 次 SetActive；OnViewOpen 全量刷新兜底。退订必须与 Binder 置空同在 OnViewClose，否则窗口关了还在收事件（悬空 View）。

③ 宿主窗口实际长什么样

public class MailWindow : BaseWindowSystem<MailBinder>
{
    public override string PrefabKey => "UI/MailWindow.prefab";

    public override void OnViewOpen(params object[] args)
    {
        base.OnViewOpen();              // ← 已自动收集并绑定预制体上全部 RedDotBehaviour
        Binder.CloseButton.onClick.AddListener(() => UIManager.Close<MailWindow>());

        ConsumeRedDot(RedDotKeys.Mail);      // 打开邮件 = 已读 → 清红点（业务决定）
    }
    // 预制体上的红点无需任何代码：L1 自动绑定 + 基类自动刷新
}

不写 BindRedDot 也能工作（L1）；只有动态生成的列表项红点才需要 L2。

⑤ 全流程：数据怎么流

0

定义期 · 树结构注册

代码流式注册：key / 父 / 模式(Bool|Count) → RedDotTree 挂进 RedDotManager。不进 Blob（结构小、低频、需运行时可变）。

↓
1

运行期 · 玩法标记叶子（A3）

RedDotManager.Mark(key) · SetCount(key,n) · Clear(key)。

⚠ 红点态跨帧持久，不能用单帧 EventMessage 承载；可桥接（玩法发消息 → 系统里转 Mark），与 OpenGuide 同链路。

↓
2

聚合 · 向上传播

Bool：父 active = 任一子 active；Count：父值 = Σ子值（或 Max，按节点配）。变更触发 OnChanged。

↓
3

表现期 · UI 消费（B9）

L1 预制体 RedDotBehaviour 自动绑定（零代码）→ L2 基类 BindRedDot → L3 显式查询。

刷新时机：OnViewOpen 全量 + OnChanged 增量；OnViewClose 解绑。

↓
4

清除 · 消费即灭

窗口 OnViewOpen 调 ConsumeRedDot(key)（业务决定）→ 向上重算 → 红点灭。跨会话「已读」由游戏经 SaveManager 持久。

⑥ 决策状态

#决策结论说明
D1树结构来源代码流式注册快、类型安全，v1 不做可视化编辑器
D2状态类型Bool + Count 双模式邮件要数字、任务只要点
D3UI 消费三层（L1 零代码为主）本版细化：刷新改由 System 驱动，非 MonoBehaviour 轮询
D4编辑器 / 调试v1 运行时只读状态窗先看「哪个节点亮了」，定义编辑器留 v2
D5键类型安全RedDotKey 结构体（代码侧零字符串）预制体侧序列化为字符串 + Inspector 下拉选择器（取自注册树），绑定时校验
