瓦片地图 Map

地图只存每格是什么值，铺哪张瓦片由规则在加载时算出来。换美术、改规则都不用重导地图。

一张 512×512 的地图在磁盘上是 256KB 出头（每层），支持多层值、自动边缘、可行走查询。

五个对象，一条链路

MapTileSet（瓦片集）
   ├─ materials + extraGrids   值层：第 0 层地形（沙/水/草），其后是通行/区域/密度…
   ├─ tiles                    瓦片池：扁平的一堆 Sprite，只被规则按下标引用
   └─ ruleSets                 规则集：一层 Tilemap 一套规则，各自声明读哪一层值
        │  被引用
        ▼
MapAsset（地图资产：N 层 width × height 字节网格 + 道具落点）    ← 编辑器里改的是它
        │  导出
        ▼
MapBlob（StreamingAssets/Map/<mapId>.blob）                  ← 只存各层值 + 指纹
        │  加载
        ▼
MapView（MonoBehaviour：读 Blob → 按规则集建层 → 逐格求值铺瓦片）
对象类型建在哪谁改它
瓦片集MapTileSet (SO)Assets/Create/HYC Framework/Map/Tile Set美术/策划一次性配好，所有地图共用
地图MapAsset (SO)Assets/Create/HYC Framework/Map/Map编辑器窗口里画
Blob二进制菜单 Export Blob代码生成，不要手改
装载器MapView (MonoBehaviour)菜单 Export Prefab 产出 prefab拖进场景即可
⚠
三块内容不要混：值层是玩法语义（存档、寻路、伤害都只认它），瓦片是表现，规则是两者之间的连接。一旦让值自己固定持有一组瓦片，就退回「一种材质只能有一种长相」——想让「沙地贴水边变湿沙」只得再开一种材质，地图数据跟着膨胀。

自动边缘：A + B = C

排序贴法把「干沙旁边是水 → 湿沙」这类关系交给规则表达，而不是手工逐格换瓦片。配过渡关系请用编辑器里的过渡向导，别手写 16 条——向导一次把两侧对称方向的组合铺满。

之所以不用 47 张 / 256 张全邻接表：那会把美术资源的数量放大一个数量级，且规则与具体瓦片绑死；这里只记录「哪两个值相邻、产出哪个过渡瓦片」，数据量与组合数无关。

◈
多层：河流压在草地上，是靠「渲染层」顺序叠出来的，值层仍然只有一层地形。多网格：地形是一层，通行、区域、密度各自再开一层，每层都是 width × height 个字节。

可行走

河流挡路、花草能踩这类语义，由瓦片集上单独声明的通行值层（WalkableGrid）承载，与地形层解耦。查询走 MapView.IsWalkable(x, y)：地图外 / 空格 / 未加载一律返回 false。

怎么画（编辑器约束）

  • 值只能往后加、只能删末尾：中间插入或删除一个值会让所有既有索引平移，旧地图会变成一张错位却「看起来正常」的乱图。
  • 道具通过 footprint 声明占地，不再是单点。
  • 拖动预览期间不写数据：只在松开时落一次，避免一次拖拽产出一堆撤销点。
  • 画布永远是运行期的样子：所见即所得，不用另开预览。

规则怎么写

  • 3×3 图案编辑器：直接在 3×3 网格里按「中心是 X、四周是 Y」的方式画期望图案。
  • 优先级与兜底：多条规则同时命中时按优先级取一条，务必留一个兜底规则。
  • 命中概率：同一值可以配多个候选瓦片并按权重随机，避免重复感。
  • 瓦片池与「去空槽」：瓦片是扁平池，按下标引用；清理空槽时注意不要错位。

导出与运行期加载

菜单 HYC Framework/Map/Export Blob 导出到 Assets/StreamingAssets/Map/<mapId>.blob；菜单 HYC Framework/Map/Export Prefab 产出装载器 prefab。铺哪张瓦片、规则怎么配一律不进 Blob，所以换美术、改规则、加规则层都不用重导地图。

⚠
Blob v2 与 v1 不兼容：BlobVersion 从 1 升到 2（加了 GridCount、Cells 改扁平多层）。旧版本导出的 .blob 读不出来，会直接报版本不符；升级后每张地图都要重导一次。这是有意的——让旧文件读失败，比被当成 v2 解析出一张乱图要好得多。
// 场景里的 MapView 会按 loadOnStart 自动读 blob 并建层；想手动控制：
mapView.Load(mapId);   // 读 blob + 校验指纹 + 建层，返回是否成功
mapView.Load();        // 用组件上序列化的 mapId

// 自己管 blob 时（比如走 Addressables）：
if (MapBlobLoader.TryLoad(mapId, out var blob))
{
    if (!MapBlobLoader.Validate(blob, tileSet, out string error))
        Debug.LogError(error);   // 多半是材质表被改过，指纹不符
}

查询接口

byte cell  = mapView.GetCell(x, y);     // 0 = 空，n = 第 0 层的值 n-1
byte pass  = mapView.GetCell(1, x, y);  // 第 1 层（通行层）同格的值
var  mat   = mapView.MaterialAt(x, y);  // 第 0 层的值定义（可能为 null）
var  val   = mapView.ValueAt(1, x, y);  // 任意层的值定义
bool walk  = mapView.IsWalkable(x, y);  // 读 tileSet.WalkableGrid
bool ready = mapView.IsLoaded;

刻意不做的事

不做理由
运行时算边缘边缘是加载时算一次，不是每帧算，所以不占运行开销
湿沙 / 湿润扩散子系统「湿沙」不是算法，就是沙与水这对材质之间的过渡瓦片；做成距离场等于把美术问题变成模拟问题
把地图烘成静态 Tilemap烘进去要给每张瓦片建 Tile 资产，地图一改就得重建，且两张只差几格的地图会各存一份完整副本
