# 21 · 本地化数据管线（Excel → Blob）

> 面向**填表/导表的人**。只想查 API 的看 [20-多语言-总览](./20-多语言-总览.md)。

## 一、配置路径

`HYC Framework/Localization/Settings` 打开设置窗口，四个值都存在 **EditorPrefs**（换机器不跟随仓库）：

| 设置 | 默认值 | 说明 |
| --- | --- | --- |
| Excel folder | `Assets/Localization` | 递归扫描 `*.xls` + `*.xlsx` |
| Output folder | `Assets/StreamingAssets/Localization` | Blob 产物目录 |
| Default language | `en` | 写进 `lang` 文件 |
| Sensitive words file | `Assets/Localization/filter.txt` | 可选，逗号/换行分隔 |

保存时会自动 `Trim()`；默认语言留空会回落到 `en`。

## 二、Excel 格式要求

```
| id                  | 中文        | English     | 日本語   |
|---------------------|-------------|-------------|----------|
| ui/common/confirm   | 确定        | Confirm     | 確認     |
| ui/common/cancel    | 取消        | Cancel      | キャンセル |
```

规则：

1. **第一行为表头**，其中必须有一列叫 `id`（小写），否则整张 sheet 报错跳过：
   `Header row of {file}:{sheet} has no 'id' column.`
2. 其余表头经过 `LocaleUtil.NormalizeLangHeader` 归一化 → 决定产出的 `.lang` 文件名。
3. 一个工作簿的 **所有 sheet 都会被读**（`workbook.NumberOfSheets` 全遍历），sheet 名不参与 key。
4. 多个文件按**文件名排序**后依次合并（`files.Sort`），不是按目录遍历顺序。
5. 以 `~` 开头的文件被跳过（Excel 临时锁文件）。

### 行级跳过规则

| 条件 | 结果 |
| --- | --- |
| 行首列文本以 `#` 开头 | 整行跳过（注释行） |
| 该行所有表头列单元格都为空 | 跳过 |
| `id` 列为空 | 跳过 |

单元格取值用 NPOI `DataFormatter().FormatCellValue(cell)` 后 `Trim()`——**数字、布尔、缓存过的公式结果都能读**。

## 三、Key 冲突检查

导入时维护 `idConflictTable: Dictionary<string, List<string>>`，同一个 id 出现第二次就记录位置，最后统一报：

```
Key conflict 'ui/common/confirm':
    E:\...\ui.xlsx:Sheet1 12:0
    E:\...\system.xlsx:UI 7:0
```

格式是 `{文件路径}:{sheet名} {行号(1-based)}:{列号}`。

**有冲突时不会写出任何产物**（`if (errors.Count == 0)` 才 `Save`），并且弹窗提示 `Import failed, see Console for details.`。

⚠️ 注意：`if (locations.Count > 1) continue;`——**冲突的重复行不会写入文本队列**，但首次出现的行已经写入了，所以 `idQueue` 与 `txtQueue` 长度仍然对齐（`while (queue.Count < idQueue.Count) queue.Add(string.Empty)` 兜底）。

## 四、产物文件

全部写到 Output folder：

| 文件 | 类型 | 内容 |
| --- | --- | --- |
| `id` | Blob `CfgLocalization` | 所有 key，按导入顺序 |
| `{code}.lang` | Blob `CfgLocalization` | 该语言的文本数组，与 `id` **同序同长** |
| `lang` | 纯文本 | 默认语言代码 |
| `filter` | Blob `CfgLocalization` | 敏感词数组 |
| `debug_ids` | Blob `CfgLocalizationIndex` | 【编辑器】每个 key 属于第几个 Excel 文件 |
| `debug_names` | Blob `CfgLocalizationIndex`(string) | 【编辑器】Excel 文件名列表 |

Blob 写入方式：

```csharp
var builder = new BlobBuilder(Allocator.Temp);
ref var root = ref builder.ConstructRoot<CfgLocalization>();
var array = builder.Allocate(ref root.values, values.Length);
// ... AllocateString 手写 UTF-8 分配
BlobAssetReference<CfgLocalization>.Write(builder, path, 3);   // 版本号 3
builder.Dispose();
```

读取侧必须**用同样的 3**：`BlobAssetReference<CfgLocalization>.TryRead(reader, 3, out var blob)`。改这个数字会导致所有旧产物读不出来。

## 五、UTF-8 分配（重要实现细节）

```csharp
private static unsafe void AllocateString(ref BlobBuilder builder, ref BlobString blobStr, string value)
{
    var bytes = Encoding.UTF8.GetBytes(value ?? string.Empty);
    var blobData = (BlobArray<byte>*)UnsafeUtility.AddressOf(ref blobStr);
    var res = builder.Allocate(ref *blobData, bytes.Length + 1);
    fixed (byte* ptr = bytes)
        UnsafeUtility.MemCpy(res.GetUnsafePtr(), ptr, bytes.Length);
    ((byte*)res.GetUnsafePtr())[bytes.Length] = 0;   // null 结尾
}
```

- Unity 内置扩展按 `Length * 2 + 1` 预留，中文（3 字节）会**截断**。
- 这里按真实字节数 + 1 分配并补 `\0`。
- 运行期 `BlobString.ToString()` 依赖 null 结尾布局——**别把 `+1` 优化掉**。

## 六、运行期加载

`LocalizationBlobSystem`（`SystemBase`）两处入口：

```csharp
[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSceneLoad)]
private static void AutoLoadAtPlay()
{
    if (LocalizationManager.IDs == null || LocalizationManager.IDs.Length == 0)
        Load();          // 只在没数据时装
}

protected override void OnCreate() { base.OnCreate(); Load(); }
```

- `AutoLoadAtPlay` 让**没有 Bootstrap 的场景也能出字**。
- `OnCreate` 里无条件 `Load()`——如果宿主自己创建了 installer，`AutoLoadAtPlay` 已经加载过，这里会再刷一次（幂等，因为 `Reload` 先清空）。

`Load()` 拼 `Application.streamingAssetsPath + "/Localization"`，目录不存在就打 warning：
`Localization folder not found: {path}. Run HYC Framework/Localization/Import Excel first.`

### Reload 流程

```
清空 mIDs/mLangs/mTexts/mLang2Index/mKey2Index（+ 编辑器的 mExcelNames/mIDExcelNameIndexs）
  ↓ 遍历目录下所有文件
  switch(文件名):
    "id"      → ReadStrings → mIDs
    "lang"    → ReadLang   → mConfigLanguage（缺失则 "en"）
    "filter"  → ReadStrings → mSensitiveWords
    "debug_ids"   → ReadInts   （仅编辑器）
    "debug_names" → ReadStrings（仅编辑器）
    default: 扩展名 == ".lang" → 加入 langFiles
  ↓ 若 mIDs 非空：
    langFiles.Sort()
    mLangs = 文件名去扩展名后 NormalizeLangHeader
    mTexts[i] = ReadStrings(langFiles[i])
  ↓ RefreshAll()
```

⚠️ **`langFiles.Sort()` 按完整路径字符串排序**，`mLangs` 顺序由此决定。`mTexts` 的索引和 `Langs` 的索引一一对应，**不要假设 `Langs[0]` 是中文**。

## 七、Key Browser（检视工具）

`HYC Framework/Localization/Key Browser`：

- **Filter**：按 key 子串过滤（大小写敏感，`Contains`）。
- **Import Excel / Reload / Export CSV** 三个按钮。
- 每行显示：`key`（宽 220） / **来源 Excel 文件名**（宽 180，依赖 `debug_ids` + `debug_names`） / 该语言文本。
- **Export CSV**：`SaveFilePanel` 选路径，制表符分隔，首行 `key\t cn\t en ...`，可用于回灌翻译。

`[LocalizedText]` 特性（可选 `preview: bool`）由 `LocalizedTextDrawer` 绘制：

```
[本地化ID]  [ ui/common/confirm        ] [▾] [◉]
                                          │   └─ LocalizedTextPreviewWindow：预览当前语言文本
```

## 九、注意事项 / 坑

1. **表头列名区分大小写**——只有精确的 `id` 才认（`IdColumn = "id"`，且比较是 `sheetTitles.ContainsKey("id")` 大小写敏感）。
2. **改列顺序会改变文本数组顺序吗？** 不会——`txtQueue` 是按列组织的 `Dictionary<string, List<string>>`，每个语言一列，最终按 `id` 顺序对齐。
3. **`GetCellText` 每次 new 一个 `DataFormatter`**——大表会有点 GC，编辑器操作可接受。
4. **敏感词文件不存在只是 warning**，不会让导入失败；但 `filter` 产物也不会更新（旧文件保留）。
5. **包体里没有 `debug_*`**：运行期访问 `LocalizationManager.ExcelNames` 会拿到空数组（属性有 null 兜底，不崩）。
6. **编辑器有个"灌水文本"开关**：`LocalizationManager.SetAppendTextType(1/2)` 会在每条文本后面追加一段长英文/中英混排，用来测文本溢出。忘了关会让 UI 看起来全是乱字。
