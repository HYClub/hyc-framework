# 00 · 架构总览

## 它是什么

一套面向 **Unity 2022.3** 的 **DOTS / ECS 数据驱动**游戏框架。核心主张有三条：

1. **配置、本地化、行为树全部是 Blob**——生成期烘焙成不可变数据，运行期直接 `BlobAssetReference<T>.TryRead` 读取，无托管对象、无反序列化。
2. **UI 就是 ECS System**——不是 MonoBehaviour 窗口管理器；窗口/HUD/弹窗都是 `SystemBase`，挂进 `UpdateGroup` 参与更新阶梯。
3. **世界无关的静态查询**——`ConfigManager` 是静态表，玩法层和 UI 层不需要持有 World 句柄就能查配置。

包路径 `com.hyc.framework`，命名空间 `HYC.Framework.*`。

---

## 数据流：四个阶段

三种数据（配置 / 本地化 / 行为树）走同一条路：**编辑 → Blob → 注册 → 消费**。

### ① 生成期（Editor）

| 数据 | 输入 | 处理 | 产物 |
| --- | --- | --- | --- |
| 配置 | Excel / 配置模板 | `ConfigGenerator` 生成 blittable `struct`（带 `[BlobGenerate]`），`ConfigExportService` 烘焙 | `BlobAssetReference<BlobRoot<TRow>>` |
| 本地化 | Excel（NPOI 读取） | `LocalizedExcelReader` | `id` / `lang` / `filter` + 每语言 `{lang}.lang` Blob |
| 行为树 | `BTTreeAsset`（画布编辑） | `BTBlobBuilder.Build` | `BTRootBlob`（纯数据树） |

生成的配置类默认落在命名空间 `HYC.Framework.Config.Generated`。

### ② 引导期（A0 / A1 数据阶段）

游戏的 Bootstrap 把 Blob 读进来并完成注册：

```csharp
ConfigManager.Register(table);                  // 配置（世界无关静态表）
LocalizationManager.Reload(folder);             // 本地化（或由 LocalizationBlobSystem 自动从 StreamingAssets/Localization 加载）
BTManager.Register(treeId, blobRef);            // 行为树
```

### ③ 运行期（A2 / A3 玩法阶段）

- 玩法系统从 `ConfigManager` 查行、从 `LocalizationManager` 取文本，**都不需要 World 句柄**。
- 行为树由 `BTInterpreterSystem`（`ISystem`）对挂了 `RunningBT` 组件的实体逐帧 `Tick`；`BTInterpreter` 以**指针遍历** `BTRootBlob`。
- `GameCustom` 节点通过 `BTContext.GameHandler` 派发到 `BTNodeRuntimeRegistry`（反射缓存的 `BTCustomNode` 子类），读写每树实例的 `BTBlackboardRuntime`（定义只读、实例可写）。

### ④ 表现期（B9，最后运行）

- UI 系统（`UIManager` + `AbsUISystem`）最后运行，读玩法阶段产生的最新状态刷新 HUD / 窗口。
- 单帧 `MessageEntity` / `EventMessage` 在玩法阶段被消费，**帧末由 `MessageExpirySystem` / `MessageClearSystem` 清理——消息绝不过帧**。

> **为什么 UI 放最后**：保证 UI 读到的一定是这一帧玩法算完的最新状态，不会出现"UI 比逻辑慢一帧"。

---

## ECS 更新阶梯

```
A0 / A1   引导 · 数据         读 Blob、注册静态表
   ↓
A2 / A3   玩法               查表、跑行为树、产生状态与消息
   ↓
B9        表现               UI 刷新（最后运行）
   ↓
帧末      清理                消息过期 / 清空
```

`UpdateGroups.cs` 定义各阶段分组；`BootstrapSystems.cs` 负责把系统挂进对应组。

## 模块地图

### Runtime（根散落 57 个 .cs + 4 个子目录）

| 子系统 | 关键类 | 说明 |
| --- | --- | --- |
| 配置 | `ConfigManager`、`ConfigTemplate`、`ConfigEnumDefinition`、`IConfigIdProvider` | Blob 静态表 + 模板驱动的生成 |
| 本地化 | `Localization`、`LocalizationManager`、`LocalizationBlobSystem`、`CfgLocalization` | Blob 多语言、占位符、运行时切语言 |
| ECS UI | `UIManager`、`AbsUISystem`、`BaseWindowSystem`、`BaseDialogSystem`、`BaseHudSystem`、`UIGroup` | UI 即 System，分层 Canvas |
| 输入/热键 | `HotkeyManager`、`HotkeyHandle`、`HotkeyElement*`、`InputDevice` | InputSystem action-name 分发 |
| 过场 | `CutsceneDirector` | 播放队列 + 跳过，片段由游戏层实现 |
| 引导/世界 | `Bootstrap`、`BootstrapSystems`、`Simulation`、`UpdateGroups`、`Settings` | 世界与系统装配 |
| 消息/日志 | `MessageEntity`、`MessageAttribute`、`Log`、`GameLog` | 单帧消息 + 日志 |
| Blob 基础 | `BlobTable` | Blob 辅助 |
| `Attributes/` (17) | `CfgAsset`、`LocKey`、`ReadOnly`、`AddressableField`、`BehaviourTreeField`… | 各类标记特性 |
| `BT/` (14) | `BTInterpreter`、`BTManager`、`BTTreeAsset`… | 行为树运行时 |
| `Components/` (4) | ECS 组件 | — |
| `ToolTip/` (4) | ToolTip 支持 | — |

### Editor（根散落 17 个 + `DataEditor/`(44) + `BT/`(10) + `Dlls/`）

- 配置：`ConfigWindow`、`ConfigGenerator`、`ConfigValidator`、`DataEditor/`（44 个文件，配置管线编辑器主体）
- 本地化：`LocaleWindow`、`LocalizedKeyPickerWindow`、`LocalizedExcelReader`、`SensitiveWordWindow`
- UI：`ComponentBinderCodeGenerator`、`ComponentBinderTableEditor`
- 其他：`AssetTools`、`QKEditorSettingsWindow`
- BT：`BTGraphWindow`、`BTGraphIMGUI`（画布）、`BTBlobBuilder`、`BTValidator`、`BTNodeCatalog`
- `Dlls/`：NPOI 等 Excel 读取依赖（仅编辑器）

> 编辑器代码量约为运行时的 **1.8 倍**——这个框架的价值大半在工具链。

https://github.com/HYClub/hyc-framework.git?path=com.hyc.framework

## 设计红线（改动前必看）

1. **新增脚本必须连 `.meta` 一起提交**——漏了会导致别人 clone 后 GUID 重建、引用全断。
2. **Blob 里的类型必须 blittable**——不能放托管对象；字符串要走 `BlobString` / `FixedString`。
3. **消息不过帧**——不要指望跨帧还能读到 `MessageEntity`。
4. **BT 编辑器代码禁止 `using NodeCanvas/ParadoxNotion`**——只移植逻辑与视觉数值。
