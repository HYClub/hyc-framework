# 54 · 通用属性配置（Attr，ECS 版）

> ⚠️ **状态**：本系统**已实现**（代码在 `Runtime/Attr/` + `Editor/Attr/`，共 18 个 `.cs` + 18 个 `.meta`），
> 但**沙箱禁 `csc`、未在 Unity 中编译验证**。本文档既是设计提案，也是当前实现的事实说明，
> 供评审；评审通过后由你提交。**任何「改目录后必须重生成」类约束都在文末「坑」一节。**

## 一、动机与范围

「通用属性配置」解决的是**框架级、per-entity 的基础属性能力**：角色/怪通用，框架不认识
"HP/ATK" 等具体属性名，也不内置公式/buff。上一轮讨论中你选了四个优化方向，本文档即这
四个方向的完整设计：

| 方向 | 代号 | 解决什么 |
| --- | --- | --- |
| 单一属性清单 | **B** | 属性定义散落各处、易漂移 → 一个 `AttributeCatalog` 作单一真源 |
| 内置代码生成器 | **A** | 手写 key 字符串易拼错 → 由目录生成枚举 + 映射 + 类型安全 bag |
| 预设 + 自动初始化 | **C** | 每个实体手写初始化循环 → `AttributeSetAsset` + `AttributeInitSystem` 自动灌值 |
| 编辑器 + 校验 | **D** | 没有校验/编辑器 → `AttributeValidator` + 两个 `CustomEditor` |

设计原则（你拍板的）：①仅 ECS ②`IAttributeDef` 接口接缝 ③目录在 `Runtime/Attr/`
④Float 走 bits ⑤仅 Init 钳制、运行期 `Set` 不钳 ⑥keyHash 用**名**的 FNV-1a 哈希
（防增删错位）⑦`AttrBag` 包 `(em, e)` 粒度。

## 二、架构总览

```
            ┌─────────────────────────── Editor ───────────────────────────┐
            │  AttributeCatalog (SO)  ← 单一真源：List<AttributeCatalogEntry> │
            │        │                                                       │
            │        ├─ AttributeCatalogEditor (CustomEditor: 增删条目/校验)  │
            │        ├─ AttributeSetAsset (SO) → OnValidate 烘成 AttributeValue
            │        │     └─ AttributeSetAssetEditor (勾选即加属性)          │
            │        │                                                       │
            │        └─ AttributeGenerateWizard (ScriptableWizard)            │
            │               └─ AttributeCodeGenerator.Generate()             │
            │                      → <prefix>AttrKey.cs / AttrKeyMap.cs /    │
            │                        AttrBag.cs  (Assets/HYC/Generated/Attr/) │
            └───────────────────────────────────────────────────────────────┘
                                       │ (运行期，真机)
            ┌─────────────────────────── Runtime ──────────────────────────┐
            │  AttributeInitializer.Init<T>(em,e,List<ConfigRowRef>)         │
            │  AttributeInitializer.InitFromSet(em,e,AttributeSetAsset)      │
            │        └─ 把默认值(按[Min,Max]钳制) 灌进                        │
            │            DynamicBuffer<AttributeValue>                       │
            │  AttributeSetRef(IComponentData, 托管) 挂在实体上               │
            │        └─ AttributeInitSystem(SystemBase) 自动 AddBuffer+灌值   │
            │  AttrBag / <prefix>AttrBag : IAttrBag ← AttributeStore         │
            │        (按 keyHash 线性查找；找不到 Get 返默认、Set 为 no-op)    │
            └───────────────────────────────────────────────────────────────┘
```

**数据流**：编辑期在 `AttributeCatalog` 定义属性 → （可选）在 `AttributeSetAsset` 勾选预设 →
向导生成三件套 → 运行期 `AttributeInitSystem` / `AttributeInitializer` 把值灌进实体 buffer →
玩法代码用枚举版 `AttrBag` 读写。

## 四、用法

**1. 定义属性清单**
Project 右键 `HYC Framework/Attributes/Attribute Catalog` 建资产，加条目
（key / type / defaultRaw / minRaw / maxRaw）。这是唯一需要手填的地方。
也可以从菜单 **`HYC Framework/Attributes/Attribute Catalog Editor`** 打开独立面板编辑
（`AttributeCatalogWindow`，自动绑定当前选中 / 工程里第一个 Catalog），与资产 Inspector 编辑器并存。
窗口把 `entries` 画成一张**类型感知表格**（替代默认 PropertyField 的 "Element N" 折叠盒 + 裸 `long` 字段）：
表头 `键 / 类型 / 最小值 / 默认 / 最大值`，Float 显示小数并自动在 bits↔double 间转换，
Bool 只显示勾选框并隐藏 min/max，整数类型显示整数；行首 ≡ 拖拽重排、行尾 ✕ 删除，底部「＋ 添加属性」。

窗口顶部有**两个分页**：`属性目录`（上面这张表）与 `属性组`。`属性组` 页用来**组装
`AttributeSetAsset`**——左栏列出工程里全部属性组资产（`AssetDatabase.FindAssets("t:AttributeSetAsset")`），
选中后在右栏从当前目录里勾选"这个实体要哪些属性"；勾选变化会即时 `Rebuild()` 烘焙 `values`。
「＋ 新建属性组」会创建并自动绑定当前目录的组资产。复用 `AttributeSetAssetEditor` 的勾选逻辑，
因此与资产 Inspector 里的 `CustomEditor` 行为一致。

**2.（可选）做预设集**
建 `HYC Framework/Attributes/Attribute Set`，绑定 catalog，勾选"这个实体要哪些属性"；
保存时 `OnValidate` 自动把所选属性烘成 `AttributeValue` 列表。

**3. 生成访问器**
在 Catalog 编辑器点「生成属性访问器」，或菜单 `HYC Framework/Attributes/Generate Accessor`，
选 catalog → 向导生成到 `Assets/HYC/Generated/Attr/`（生成代码统一总根下）：
- `<prefix>AttrKey.cs`：`enum`（序数 = 目录顺序）
- `<prefix>AttrKeyMap.cs：`static ulong[] Hash`（= `AttributeKey.Hash(key)`）+ `AttributeType[] Type`
- `<prefix>AttrBag.cs`：实现 `IAttrBag`，暴露 `GetInt(<prefix>AttrKey.ATK)` 等友好重载

**4. 代码里用枚举（零手写 key）**
```csharp
// em, e 来自你的 World
var bag = new GameAttrBag(em, e);
int atk = bag.GetInt(GameAttrKey.ATK);     // IntelliSense + 拼错编译期报错
bag.SetInt(GameAttrKey.ATK, atk + 5);
```
（`<prefix>` 默认 `Game`，命名空间由「生成代码命名空间 root」派生为 `{root}.Attr`，可在向导里改。）

**5. 自动初始化**
实体挂 `AttributeSetRef { asset = 你的Set }` → `AttributeInitSystem` 进 Play 后自动
`AddBuffer<AttributeValue>` 并灌入预设值；或手动 `AttributeInitializer.InitFromSet(em, e, set)`。

**6. 校验**
Catalog 编辑器点「校验目录」跑 `AttributeValidator`，命中空 key / 重名 / 非法标识符 /
`min>max` / 默认值越界 / Float bits 为 NaN·Inf 时给出 `AttributeIssue`。

## 五、取舍（设计决策与代价）

1. **枚举是目录的快照**：目录增删属性后**必须重新 Generate**，否则枚举与运行时袋数据序数错位。
   keyHash 按**名**算（非序数），所以同 key 改名不影响旧袋；但**枚举序数变了要重生成**。
2. **运行期 `Set` 不钳制**：袋是运行时真相，配置边界只约束默认值；若需运行期 clamp，由使用方自己包一层。
3. **`AttributeSetRef` 是托管 `IComponentData`（class）**：不走 Burst/Job，适合低频初始化，不进逐帧热路径。
4. **完全生成、无 `#region USER`**：生成文件**不要手改**，改目录后重生成即可整体覆盖。
5. **`ConfigRowRef` 迁移**带来一次性的 Talent 侧 `using` 调整（已做），换来 `Attr` 不反向依赖 `Talent`。
6. **keyHash 命中失败是静默的**：Get 返调用方默认值、Set 为 no-op（袋即"声明过的属性集合"，不自动扩容）。
   调试时若读到 0，先确认实体确实 `AddBuffer<AttributeValue>` 且 key 在袋内。

## 七、坑（实现者须知）

- **改目录后必须重生成**：枚举版 `AttrBag` / `AttrKeyMap` 是生成物的硬编码副本，目录变了不同步会串号。
- **Float 存 bits**：`AttributeValue.raw` 对 Float 走 `BitConverter.DoubleToInt64Bits`/`Int64BitsToDouble`，
  校验器对 Float 的 `defaultRaw/minRaw/maxRaw` 会按 double 解释，NaN/Inf 会被 `AttributeValidator` 拦下。
- **`AttributeInitSystem` 的查询**：`CreateEntityQuery(typeof(AttributeSetRef), ComponentType.Exclude<AttributeValue>())`，
  只处理"还没初始化"的实体；已初始化的不重复灌（幂等）。
- **`ConfigRowRef` 迁移是破坏性改名**：旧 `TalentTreeAsset` 内联的 `ConfigRowRef` 类已删，引用它的旧 `.asset`
  若序列化了该内联类型需重新保存（当前 Talent 资产只用 `ConfigRowRef` 数据，未内嵌类型，影响可控）。
