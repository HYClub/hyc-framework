# 61 · 同步（帧同步 Lockstep / 状态同步路线）

## 职责

联机方案的 ECS 底层：**帧同步（P1 已落地）** 与 **状态同步（P3 路线，共用同一底座）**。
框架负责传输抽象、输入汇流、tick 推进、确定性纪律工具；游戏层只做两件事：
**继承基类写逻辑**、**照常用 SystemAPI 取数**——不收发字节、不管对齐、不判角色。

```
com.hyc.framework / Runtime/Sync/（命名空间 HYC.Framework.Sync，ECS 底层，Host/Client 两端同码）

┌ 共享底座 ────────────────────────────────────────────────┐
│ ITransport 传输抽象   LoopbackTransport 回环（单机双端）   │
│ BlitIO 二进制读写     SyncRandom 确定性随机               │
│ SyncBootstrap.Install 装配入口  SyncRole 角色单例         │
│ SyncTick / PlayerTable tick 与玩家表单例                  │
└──────────────────────────────────────────────────────────┘
        │                              │
┌ 帧同步 Lockstep（P1 ✓）─┐  ┌ 状态同步 StateSync（P3 路线）─┐
│ LockstepDriver  齐帧推进 │  │ StateSyncAuthority 脏检广播   │
│ LockstepInputSystem<T>  │  │ StateSyncReplica   副本应用   │
│ LockstepLogicSystem     │  │ StateInterpolation B9 前插值  │
└─────────────────────────┘  └──────────────────────────────┘
        │
┌ 游戏接入层（宿主工程）───────────────────────────────────┐
│ class MyInput : LockstepInputSystem<MyInput>   采本地输入 │
│ class MySim   : LockstepLogicSystem            写 Step   │
│ 逻辑系统内 SystemAPI 取组件/取输入，与单机写法完全一致      │
└──────────────────────────────────────────────────────────┘
```

## 共享底座

### ITransport（`ITransport.cs`）

| 成员 | 说明 |
| --- | --- |
| `Role` / `LocalPlayerId` / `PeerCount` | 角色与玩家编号；成对传输 Host=0、Client=1，`PeerCount=2` |
| `IsConnected` | 链路是否可用 |
| `Send(kind, ReadOnlySpan<byte>)` | 发包；Span 同步传参零拷贝 |
| `event MessageReceived` | 收包事件；**参数为 byte[]**——ref struct 不能作泛型实参，事件签名放不了 Span |
| `Pump()` | 把已到达消息派发为事件；由 Driver 每逻辑帧调用 |
| `Dispose()` | 断链并退订 |

框架**不绑定任何网络库**。真实传输（ENet / WebSocket / Relay）由宿主实现本接口注入。
`LoopbackTransport` 仅为单机双端联调与确定性回归：`CreatePair` 建一对互联传输，
`CreateSolo` 建单端（Send 静默丢弃——单人确定性模式，等价于录制/回放基线）。

### BlitIO（`BlitIO.cs`）

`BlitWriter` / `BlitReader`：blittable 类型顺序 memcpy，零分配零反射，`unsafe` 收敛在框架内
（调用方无需开 unsafe）。只同步 blittable 组件；**BlobAssetReference 字段不同步引用数据，
只同步引用 ID**（双方各持同一 blob，与配置管线哲学一致）。

### SyncRandom（`SyncRandom.cs`）

确定性随机：splitmix64 + 纯整数位运算，同 seed 全平台逐位一致。帧同步逻辑内
**禁止 `UnityEngine.Random`**——按帧演化用 `SyncRandom.ForTick(tick, matchSeed)`，
跨帧连续演化用局部变量。帧号演进、命中判定、掉落摇号全部走它。

### 单例（`SyncRole.cs` / `SyncTick.cs`）

| 单例 | 字段 | 写入方 |
| --- | --- | --- |
| `SyncRoleSingleton`（+ `SyncRole_Host/Client/Observer` tag） | `Role` | SyncBootstrap.Install |
| `SyncTickSingleton` | `CurrentTick`（已推进逻辑帧）、`AdvancedCount`（累计推进次数） | LockstepDriver |
| `PlayerTableSingleton` | `LocalPlayerId`、`PlayerCount` | SyncBootstrap.Install |

### SyncBootstrap.Install（`SyncBootstrap.cs`）

```csharp
public static void Install(World world, ITransport transport)
```

装配：建三个单例 → 创建 `LockstepDriver` 入 A0 组并 `SortSystems` → 绑定传输 →
注册已存在的输入汇 → **校验游戏侧组特性**（缺失即 LogError，见「约束与坑」第 1 条）。

**调用时机**：游戏 bootstrap 的 `RegisterSystems` / installer 内，必须早于首次世界 Update
（A0 组排序时 `[UpdateBefore(typeof(LockstepDriver))]` 约束要生效）。多端各自 `Install` 一次，
传输由宿主创建（Loopback 双端 = 两个 World 各装一端）。

### SyncSessionSystem（`SyncSessionSystem.cs`）

链路会话监控（A0 组，`[UpdateAfter(typeof(LockstepDriver))]`，随 `Install` 自动创建入组）：
轮询 `ITransport.IsConnected`，**仅边沿触发**两个实例事件——

| 事件 | 触发 | P1 语义 |
| --- | --- | --- |
| `LinkLost` | 已连接 → 断开 | 宿主弹「对方已断线」UI / 回主菜单；P1 无重建动作（重链快照追赶是 P2） |
| `LinkRestored` | 已断开 → 连接 | 仅通知；初始即连通 / 初始即断开都不触发（首观测只记基线） |

```csharp
var session = world.GetExistingSystemManaged<SyncSessionSystem>();
session.LinkLost += () => { /* 弹断线 UI、回主菜单 */ };
// 退局 / 切场景时退订：session.LinkLost -= 同一委托（实例随 World 销毁，刻意不用静态事件防跨 World 泄漏）
```

P1 断链后世界默认永久等齐（`MaxStallFrames=0`）；若要「超时强制推进按 default 输入处理」的断线容忍，
向 `world.GetExistingSystemManaged<LockstepDriver>().MaxStallFrames` 设正数（>0 生效，日志只报一次）。

## 帧同步数据流

固定步长由框架阶梯树的 `RateManager`（`FixedRateCatchUpManager`）保证，逻辑帧与渲染帧解耦；
Driver 每次 `OnUpdate` = 一次逻辑帧机会。

```
[输入系统 OnUpdate · A0 · UpdateBefore(Driver)]
    SampleLocal(playerId, ref input)           ← 游戏采集（键盘/手柄/SystemAPI）
    Submit(tick = CurrentTick+1, playerId)     ← 本地入库（立即可读）+ 二进制发远端
[Driver OnUpdate · A0]
    Pump → OnMessage(Input) → sink.OnRemoteInput   ← 远端输入入库
    齐帧判定：nextTick 的全部 PlayerCount 个玩家 mask 到齐？
        齐 → CurrentTick++ / AdvancedCount++ / 输入历史 PruneBefore
        不齐 → 本帧不推进（等待；MaxStallFrames>0 时超时强制推进并报错）
[逻辑系统 OnUpdate · A3]
    AdvancedCount 变化？→ Step(CurrentTick)     ← 两端同 tick 同序执行
        TryGetInput<TInput>(playerId, out input)   ← 取两端本 tick 输入
```

- 目标帧号 = `CurrentTick + 1`；首个提交目标帧为 1，tick 0 为装配前状态。
- 输入历史保留 64 tick（`KeepInputTicks`），逻辑系统读当前帧，过期由 Driver 回收。
- 未齐帧的帧：世界其余系统照常更新（表现层不卡），只有 Lockstep 逻辑系统被闸门跳过。

## 上层接入范式

```csharp
// ① 输入结构：blittable（unmanaged IComponentData）
public struct MyInput : IComponentData
{
    public float2 Move;
    public uint Buttons;   //  bit0=跳 bit1=攻击 …
}

// ② 输入系统：两组特性必须自带（ILPP 不继承基类特性，见坑 1）
[UpdateInGroup(typeof(UpdateGroup_A0))]
[UpdateBefore(typeof(LockstepDriver))]
public partial class MyInputSystem : LockstepInputSystem<MyInput>
{
    protected override void SampleLocal(int localPlayerId, ref MyInput input)
    {
        input.Move = new float2(Input.GetAxisRaw("Horizontal"), Input.GetAxisRaw("Vertical"));
        input.Buttons = (Input.GetKey(KeyCode.Space) ? 1u : 0u);
    }
}

// ③ 逻辑系统：组特性自带；OnUpdate 被封闭，只写 Step
[UpdateInGroup(typeof(UpdateGroup_A3))]
public partial class MySimSystem : LockstepLogicSystem
{
    protected override void Step(int tick)
    {
        float dt = 1f / 60f;                        // 固定步长，禁读 Time
        var rng = SyncRandom.ForTick(tick, 20261019); // 确定性随机
        if (TryGetInput<MyInput>(0, out var local)) { /* 本地玩家 */ }
        if (TryGetInput<MyInput>(1, out var remote)) { /* 对端 */ }
        foreach (var (hp, vel) in SystemAPI.Query<RefRW<Health>, RefRW<Velocity>>())
        {
            // 与单机完全同形的确定性逻辑
        }
    }
}

// ④ bootstrap 装配（FrameworkBootstrapBase 子类 / installer 内）
protected override void RegisterSystems(World world)
{
    HYC.Framework.Sync.SyncBootstrap.Install(world, new MyEnetTransport(...));
}
```

**取数不变**：Step 内 `SystemAPI` 查询、读写组件与单机写法一致；客户端侧若接了 P3
状态同步副本，同样 `SystemAPI.GetComponent<Health>(e)` 直接读。

## 确定性纪律（帧同步生命线）

| 禁止 | 替代 |
| --- | --- |
| `Time.time` / `Time.deltaTime` / `Time.frameCount` | Step 形参 tick、固定 dt 常量 |
| `UnityEngine.Random` | `SyncRandom` |
| HashMap/Dictionary 迭代顺序驱动逻辑 | 定长数组 / 输出显式排序（迭代顺序不可依赖） |
| 表现层状态驱动逻辑（Animator 参数、Transform 位置） | 逻辑状态写组件，表现层 B9 读 |

浮点运算限 `Unity.Mathematics`；**同版本同平台**两端才保证一致——iOS/Android/PC
异构互同步不在承诺范围（要覆盖需定点数化，成本另评）。

## 约束与坑

1. **组特性必须游戏侧具体类自带**。Entities ILPP 用 Cecil 直读类型特性、**不继承泛型基类特性**
   （源码实证：`StaticTypeRegistryPostProcessor.InjectGetSystemAttributes` 读 `sysDef.CustomAttributes`，
   且开放泛型/抽象基类不入 systemList）。缺失症状：输入系统脱离 A0（推进降半速——本地输入总在
   Driver 检查后才提交）、逻辑系统脱离固定步长（Step 里拿到渲染帧 dt）。`SyncBootstrap.Install`
   会在装配期对缺失类 LogError。系统类还必须是 `partial`（源码生成器要求）。
2. **一个玩法一个输入系统**。多个 `LockstepInputSystem<T>` 会各自解码同一份远端字节；多路输入
   （移动+技能+表情）合并进同一个 TInput 结构，不要按功能拆系统。
3. **playerId < 32**（齐帧用位掩码）。P1 传输模型 = 一条链路两个端点；N 人中继是后续路线。
4. **MaxStallFrames 默认 0 = 永久等齐**。设为正数时，输入超时后强制推进并按 default 输入处理
   （断线容忍策略之一，日志只报一次）。
5. **追帧期间同渲染帧复用输入快照**：`FixedRateCatchUpManager` 允许一个渲染帧跑多个逻辑 tick，
   本地输入按渲染帧采样，快进追赶时各 tick 拿到同一份输入——这是正确行为（两端各自一致），
   不要试图在 Step 内重新采样。
6. **SampleLocal 内可用 SystemAPI**（系统实例上下文有效）；但不要在 Step 之外读逻辑组件，
   也不要把输入系统的 Enabled 手动关闭（关闭后本地输入停采，对端将永远等不齐）。
7. **Solo 模式**：`LoopbackTransport.CreateSolo()` 固定 0 号玩家、PeerCount=1——单人确定性会话
   （录制输入存档 / 回放基线 / AI 对战回放），齐帧判据只剩本地，每逻辑帧必推进。
   ⚠️ 掩码陷阱：齐帧位掩码按「玩家 0..PlayerCount-1 连续编号」取连续低位，**solo 必须为 0 号**
   （若本地是 1 号而 PlayerCount=1，置位 bit 1 永远凑不齐 `0b01`，Driver 死等）；
   多玩家录制的回放注入是 P2 范围（缺位玩家输入从文件灌入），届时另给注入 API。
   另注意 `CreatePair` 是**两个端点必须各装一个 World**——单 World 只装一端时对端输入永远不到，
   同样表现为不推进（Loopback 的 in-process 特性，真实传输无此问题）。
8. **基类 `OnUpdate` 不能写 `sealed`**（Entities 源生成器硬限制）：源生成器会把 `OnUpdate` 改名成
   `__OnUpdate_<hash>` 再重新生成入口，保留 `sealed` 触发 **CS0238「cannot be sealed because it is
   not an override」**。框架两个基类因此都是 `protected override`；游戏侧子类**禁止 override
   `OnUpdate`**——那会绕过输入提交 / tick 闸门，只实现 `SampleLocal` / `Step`。

## 路线图

| 阶段 | 内容 | 依赖 |
| --- | --- | --- |
| P1 ✓ | 共享底座 + 帧同步（Driver/InputSystem/LogicSystem/Loopback 双端） | — |
| P2 | 帧同步快照（`[SyncSnapshot]` 标记组件全量二进制）、断线快照重连追赶、观战用快照中途加入 | BlitIO 拓展 |
| P3 | 状态同步：`StateSyncAuthoritySystem`（脏检广播）/ `StateSyncReplicaSystem`（应用+实体映射）/ `StateInterpolationSystem`（B9 前插值）/ spawn·despawn 原型 ID / `SyncIdService` 发号 | Chunk ChangeVersion |
| P4 | 确定性校验和（周期 hash 比对）+ Samples 示例 | P1/P3 |

状态同步与帧同步共用底座（传输 / 角色 / 二进制 / 随机）；游戏侧接入面同样只有
「继承 + 取数」，届时本文补状态同步篇。
