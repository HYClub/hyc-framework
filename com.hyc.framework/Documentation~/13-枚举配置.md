# 13 · 枚举配置

> 对应 `Runtime/ConfigEnumDefinition.cs` + `Editor/DataEditor/ConfigEnumCodeGen.cs`，
> 并与 `Editor/DataEditor/ConfigTemplateCodeGen.cs` 的 `ConfigFieldType.Enum` 分支协作。
>
> **一句话**：把配置表里那些「`0=顺序 1=随机 2=离玩家最远`」的裸 `Int` 字段，变成真正的 C# 枚举——
> 编辑器里下拉选择、自动导出枚举类、运行期按枚举名比较，同时 **Blob 里仍然是 `int`，数据结构不变**。

---

## 一、解决什么问题

没有枚举配置时，分类字段只能这么写：

```csharp
F("PointStrategy", ConfigFieldType.Int, "0=顺序 1=随机 2=离玩家最远"),
```

问题在于**数值与含义的绑定只存在于注释里**：

- 编辑器里是个裸数字输入框，填错没人拦；
- 运行期代码散落 `== 0` / `== 1` 这类魔法数，和注释对不上也不会报错；
- 想给中间插一个新值，所有下游数字要手工改一遍。

枚举配置把「有哪些值」提升成**独立资产**，由框架统一分配数值、生成 C# 枚举类，并在编辑器里渲染成下拉。

---

## 二、架构：三段式

```
① 枚举定义资产          ② 生成 C# 枚举类           ③ 配置字段引用
ConfigEnumDefinition  →  ConfigEnumCodeGen      →  ConfigFieldType.Enum
(.asset，用户填名字)      (WriteFile / Export)       + enumRefClassName
                              ↓
                     Assets/.../Enums/XxxEnum.cs
                              ↓
                     配置类字段 = 枚举类型
                     Blob 字段  = int（(int) 转换）
```

- **定义资产**放在 `ConfigDataSettings.RootFolder` 下任意目录（约定放 `枚举/`），
  由 `ConfigEnumCodeGen.LoadAllEnums()` 用 `AssetDatabase.FindAssets("t:ConfigEnumDefinition")` 扫描；
- **生成的枚举类**落在 `ConfigDataSettings.OutputDir/Enums/`，命名空间取 `ConfigDataSettings.Namespace`；
- **配置字段**通过 `enumRefClassName` 指向枚举的 `className`，生成时字段名即枚举类型。

---

## 三、关键类

### `ConfigEnumDefinition`（`HYC.Framework.Config`，ScriptableObject）

`[CfgAsset("枚举/枚举定义", 0)]`，本身也是配置资产，在数据编辑器里可见。

| 字段 | 说明 |
| --- | --- |
| `displayName` | 显示名，支持 `分类/名称` |
| `className` | **生成的 C# 枚举名**（如 `WavePointStrategy`），被 `enumRefClassName` 引用 |
| `isFlags` | `false`=普通枚举（1,2,3…）；`true`=复合枚举（1,2,4…，生成时加 `[Flags]`） |
| `exportTarget` | `Client` / `Server` / `Both` |
| `values` | `List<ConfigEnumValue>`，每项 `name` + `description` |

```csharp
// 数值由框架自动分配，用户只填名字
public static long ValueOf(ConfigEnumDefinition def, int index)
    => def != null && def.isFlags ? 1L << index : index + 1L;
```

### `ConfigEnumCodeGen`（`HYC.Framework.Config.Editor`）

| 成员 | 说明 |
| --- | --- |
| `EnumsOutputDir` | `{ConfigDataSettings.OutputDir}/Enums` |
| `LoadAllEnums()` | 扫 `RootFolder` 下全部枚举定义 |
| `FindEnum(className)` | 按类名查（**模板校验走这条**） |
| `IsClassNameTaken(className, self)` | 重名检查 |
| `Validate(def, out error)` | 见下方「校验规则」 |
| `GenerateCode(def)` | 生成 C# 源码字符串 |
| `WriteFile(def, out error)` | 校验 + 写 `.cs` + `AssetDatabase.Refresh()` |
| `Export(def, client, server)` | 按 `exportTarget` 复制 `.cs` 到 `ClientExportDir/Enums`、`ServerExportDir/Enums` |
| `CreateEnumAsset(folder)` | 数据树右键入口，创建 `NewEnum.asset` |

**`Validate` 规则**（失败会阻断代码生成）：

1. `displayName` 非空；
2. `className` 是合法 C# 标识符；
3. `className` 不与**其它枚举定义**重名；
4. `className` 不与**任何配置模板的 `className`** 重名；
5. 每个值名非空、是合法标识符、互不重复；
6. `isFlags` 时最多 31 个值（`1 << 31` 越界）。

**`GenerateCode` 产物**（无显式基类型，即 `int` 承载）：

```csharp
using System;

namespace <ConfigDataSettings.Namespace>
{
    /// <summary>
    /// 装备/部位
    /// </summary>
    public enum EquipSlot
    {
        /// <summary>
        /// 头部
        /// </summary>
        Head = 1,
        Body = 2,
        Weapon = 3,
    }
}
```

> `displayName` / `description` 会做 XML 转义（`&`→`&amp;`、`<`→`&lt;`、`>`→`&gt;`），
> 所以描述里写 `存活<=N` 是安全的，生成的是 `存活&lt;=N`。

### 配置字段侧

`ConfigTemplateField.type = ConfigFieldType.Enum` 时**必须**填 `enumRefClassName`（= 枚举的 `className`）。
`ConfigTemplateCodeGen` 的处理分两处：

| 阶段 | 行为 |
| --- | --- |
| 校验 | `enumRefClassName` 为空 → 报错；`FindEnum` 找不到 → 报错「枚举不存在（未创建或已删除）」 |
| 生成配置类 | `ResolveTypeName` → `baseName = e.className`，**字段类型就是枚举** |
| 导出 Blob | `case ConfigFieldType.Enum: info.TypeName = "int"`，写入表达式为 `(int){expr}` |

## 四、完整用法

1. **创建定义**：数据编辑器里右键 → 枚举定义（或脚本调 `ConfigEnumCodeGen.CreateEnumAsset(folder)`）；
2. **填值**：只填 `name` / `description`，数值由 `ValueOf` 自动分配；
3. **生成**：`ConfigEnumCodeGen.WriteFile(def, out err)`（编辑器里保存即触发；脚本化批量建枚举也调它）；
4. **引用**：模板字段设 `type = Enum`、`enumRefClassName = "<className>"`；
5. **重跑配置管线**：重新生成配置类 + 导出 Blob（枚举字段在 Blob 里是 `int`，布局不变）。

### 脚本化批量创建（推荐给「配置表由代码定义」的工程）

```csharp
private static void EnsureEnumDefs()
{
    EnsureFolder($"{ROOT}/枚举");
    foreach (var ed in EnumDefs)   // (className, displayName, (name, desc)[])
    {
        var path = $"{ROOT}/枚举/{ed.className}.asset";
        var def = AssetDatabase.LoadAssetAtPath<ConfigEnumDefinition>(path);
        if (def == null)
        {
            def = ScriptableObject.CreateInstance<ConfigEnumDefinition>();
            AssetDatabase.CreateAsset(def, path);
        }
        def.displayName  = ed.displayName;
        def.className    = ed.className;
        def.isFlags      = false;
        def.exportTarget = ConfigExportTarget.Both;
        def.values = new List<ConfigEnumValue>();
        foreach (var v in ed.values)
            def.values.Add(new ConfigEnumValue { name = v.name, description = v.desc });
        EditorUtility.SetDirty(def);

        if (!ConfigEnumCodeGen.WriteFile(def, out var err))
            Debug.LogError($"生成枚举 {ed.className} 失败：{err}");
    }
    AssetDatabase.SaveAssets();
}
```

> **调用时机很关键**：必须排在「清理 `ConfigDataSettings.OutputDir`」**之后**、「遍历模板生成配置类」**之前**。
> 清理会连 `Enums/*.cs` 一起删掉；而模板生成时要 `FindEnum` 查枚举定义资产。

## 五、数值规则：HYC 标准是 **1 基**

普通枚举从 `1` 开始（`index + 1`），复合枚举是 `1 << index`。

这意味着：

- **没有 `0` 值**——`0` 表示「未设置 / 非法」，别拿它当 `None` 用（要「无」就显式列一个 `None`，它也是 `1`）；
- 从旧的手写 `0` 基枚举迁移时，**所有既有数据要 `+1`**，并且运行期所有 `== 0` / `== 1` 的比较都要跟着改；
- 编辑器下拉里看到的顺序即数值顺序，**在中间插入新值会让后面的数值整体后移**——已导出的 Blob 必须重新生成。

## 六、Blob 里的表现（最容易误判的一点）

| 位置 | 类型 |
| --- | --- |
| 生成的**配置类**字段（`ActorConfig.Kind`） | **枚举类型** `ActorKind` |
| 生成的 **Blob** 字段（`CfgActorConfig.Kind`） | **`int`**（写入时 `(int)` 转换） |

所以：

- 运行期通过 `ConfigManager.TryGet<CfgXxx>(...)` 拿到的是 **`int`**，
  需要自己转枚举（`(ActorKind)row.Kind`）或与枚举常量比较（`row.Kind == (int)ActorKind.Flyer`）；
- ECS 组件里一般继续用 `int` 承载（拷值自 Blob），**不要**因为是枚举就改成枚举类型去改变结构体布局；
- 反过来说：把 `Int` 字段改成枚举字段，**Blob 布局完全不变**，只影响编辑器体验与配置类字段类型——
  这是低风险改动，代价只在「数据值要换成 1 基」。

## 七、编辑器渲染

枚举字段在 Data Editor 里走 Unity 内置 `PropertyField`
（`SerializedPropertyType.Enum` → 原生下拉），无需为枚举单独写抽屉。

## 注意事项 / 坑

1. **枚举定义必须先于配置模板生成**。模板校验会 `FindEnum(enumRefClassName)`，
   找不到就报「字段 X 的枚举 Y 不存在（未创建或已删除）」。建表脚本里请把 `EnsureEnumDefs()` 放在模板循环之前。
2. **`enumRefClassName` 填的是 `className` 不是 `displayName`**。
   `displayName` 支持 `分类/名称` 这种带斜杠的写法，不能直接当类名。
3. **类名不能与配置模板的 `className` 冲突**（`Validate` 第 4 条），也不能与其它枚举同名。
   建议枚举名带语义后缀（`WaveSpawnMode`、`ItemKind`），避免和 `WaveConfig`、`ItemConfig` 撞车。
4. **枚举名 == 字段名是合法的**（如字段 `OnMaxStacks` 类型 `OnMaxStacks`），
   C# 的 Color-Color 规则能正确处理，不必为了避讳改名。
5. **1 基，没有 0**。老数据迁移要 `+1`；判断「未设置」要用 `0`，不要用某个枚举成员。
6. **改枚举成员顺序 / 增删成员会改变既有数值**，属于破坏性变更——必须重跑配置导出，
   否则 Blob 里的旧数字会指向错误的含义。
7. **`isFlags` 最多 31 个值**，且生成时加 `[Flags]`；普通枚举不要开这个开关。
8. **写脚本批量建枚举时，要把 `EnsureEnumDefs()` 放在 OutputDir 清理之后**（见第四节）。
   否则这一轮生成的 `Enums/*.cs` 会被随后的清理删掉，编译期报找不到枚举类型。
9. **枚举值改名不影响数值**（数值按序号分配），但会打断运行期代码里的名字引用，两边要一起改。
