## 零、动手前先判断：你的工程走哪条路

配置管线有**两条完全不同的路**，走错会白干：

| | **编辑器驱动** | **脚本驱动** |
| --- | --- | --- |
| 怎么配 | 在 Data Editor 窗口里点 | 写 `XxxConfigSetup.cs`，跑菜单批量生成 |
| 表结构存在哪 | `ConfigTemplate` 资产里 | C# 代码里的 `TemplateDefs()` |
| 数据行存在哪 | 一个个 `.asset` | C# 代码里的 `RowDefs()`（**唯一真相源**） |
| 适合 | 表少、策划自己填 | 表多、配置即代码、要进版本库 diff |

**怎么判断**：看工程里有没有 `Assets/Editor/**/*ConfigSetup.cs`。有 → 脚本驱动。
SnowBros 与 TD 都是脚本驱动。

## 一、新增一张配置表

### 路径 A：脚本驱动（SnowBros 采用）

1. 在 `TemplateDefs()` 里加一个 `TplDef`：`ClassName`（生成的类名）、`DisplayName`（`分类/名称`）、`Fields`（字段列表）。
2. 在 `RowDefs()` 里加数据行：`new RowDef { ClassName = "...", Folder = "...", AssetName = "...", Id = 1001 }.Set("字段名", 值)`。
3. 跑**菜单 1（生成模板与代码）** → 产出 `CfgXxx` / 配置类 / Blob 构建器 / 加载 System。
4. 跑**菜单 2（创建/覆盖数据行）** → 按 `RowDefs()` 写 `.asset`（反射写字段，**已存在则覆盖**）。
5. 跑**菜单 3（导出全部 Blob）** → 产出 `StreamingAssets/ConfigBlob/*.blob`。
6. 运行期 `ConfigManager.Register` 后即可查询。

> ⚠️ 顺序不能乱：**改了表定义必须 1 → 2 → 3 全跑**；只改 `.asset` 数值可以只跑 3。
> 只跑 3 不生效——schema 变了不重新生成代码，产物还是旧的。

### 路径 B：编辑器驱动

1. `HYC Framework/Config/Config Window` → 新建 `ConfigTemplate`，填 `className` / `displayName`，加字段。
2. 生成代码（配置窗口内的生成入口）。
3. `HYC Framework/Config/Data Editor` → 在数据树里右键该类型新建数据行，填字段。
4. 导出（数据编辑器右键 / 工具栏，见 [90 篇](./90-编辑器工具链.md)「导出」小节）。
5. `HYC Framework/Tools/Validate Config` 校验。

## 二、给表加字段：类型与导出模式怎么选

**决策表（按你要存的东西选）**：

| 我要存 | `ConfigFieldType` | 导出模式（`clientExport`） | 说明 |
| --- | --- | --- | --- |
| 数值 / 布尔 | `Int` `Float` `Bool` `Long` … | `Direct` | 直接进 Blob |
| 短文本（名称） | `String` | `FixedString` `Size64` / `Size128` | 定长内联，省一次寻址 |
| 长文本 / 长度差异大 | `String` | `BlobString` | 变长，省空间但有间接寻址 |
| **分类（0/1/2 这种）** | **`Enum`** | `Direct`（Blob 里落成 `int`） | **必须用枚举，不要用裸 Int**，见 [13 篇](./13-枚举配置.md) |
| Prefab / Sprite / 音效 | `Object` `GameObject` `Sprite` `AudioClip` | `AssetAddressable` | 拖资源自动生成 AA 地址字符串，运行期按地址加载 |
| 引用另一张表的行 | `Reference` + `refTypeFullName` | `Direct` 或 `Member`（只导出对方 `ID`） | — |
| 引用的行为树 | `BehaviourTree` | `Direct` | 存 `TreeId`（`long`），下拉选树 |
| 多语言文本 | `LocalizedKey` | `FixedString` | 生成 `string` + `[LocKey]`，需 loc 包 |
| 只在客户端用的表现字段 | 任意 | — | 把 `exportTarget` 设为 `Client` |

> ⚠️ **字符串必须显式选 `BlobString` 或 `FixedString`**，`Direct` 会把托管 `string` 带进 Blob 导致烘焙失败。
> ⚠️ **Bitmask（如 `-1=全部` 的位掩码）不是枚举**，保持 `Int`。枚举是「互斥分类」，位掩码是「可组合开关」。

## 三、枚举字段（分类值必做）

1. 建枚举定义：`Assets/ConfigData/枚举/<Xxx>.asset`（`ConfigEnumDefinition`），只填**名字**，数值由框架分配。
2. 生成枚举类：`ConfigEnumCodeGen.WriteFile(def)` → `Assets/GeneratedConfigs/Enums/<Xxx>.cs`。
3. 字段引用：`F("字段名", ConfigFieldType.Enum, "说明", "<枚举className>")`。
4. 重跑 1 → 2 → 3。

**关键三条**：
- 数值是 **1 基**（普通 `index+1`；`isFlags` 时 `1<<index`），**没有 0**；
- **Blob 里是 `int`，配置类字段才是枚举类型**——运行期拿到 `int`，用 `(int)XxxEnum.Member` 比较；
- 脚本化批量建枚举时，`EnsureEnumDefs()` 必须排在「清理 OutputDir」**之后**、「生成配置类」**之前**。

完整机制与 9 条坑见 **[13 · 枚举配置](./13-枚举配置.md)**。

## 四、运行期读配置

```csharp
// 引导期（A1）注册
ConfigManager.Register(myTable);                       // ConfigBlobTable<TRow>

// 任意处查询（无需 World 句柄）
if (ConfigManager.TryGet<CfgItemConfig>(4001, out var row))
{
    int  kind  = row.Kind;                             // 枚举字段在 Blob 里是 int
    bool isRed = row.Kind == (int)ItemKind.Red;         // 与枚举常量比较
}
```

- `TRow` 必须 **blittable**；`Get` 找不到返回 `default`（不抛异常），要区分「没这条」用 `TryGet`。
- `GetAllRows<T>()` 返回 `BlobArray<T>`，**不要跨帧持有**。

## 五、行为树：从零到跑起来

1. **建资产**：`HYC Framework/BT/BT Editor` 打开画布 → File → 新建 → 存到 `Assets/BTTrees/`。
2. **设 `TreeId`**：运行期按 `TreeId` 查找，**改 `TreeId` 会断引用**（移动/改名不会）。
3. **连线**：必须有且仅有一个 `Root`，**且 Root 必须连线**——否则 `BTBlobBuilder.Build` 直接失败。
4. **给实体挂执行标记**：
   ```csharp
   ecb.AddComponent(e, new RunningBT {
       TreeId   = treeId,
       RunState = new BTRunState { TreeId = treeId, RootNode = 0 }
   });
   ```
5. **确认解释器在跑**：`BTInterpreterSystem` 是一个 **`ISystem`（非托管 struct）**，
   挂组要用 `world.GetOrCreateSystem<BTInterpreterSystem>()`（返回 `SystemHandle`），
   **不能**用 `GetOrCreateSystemManaged<T>()`（它只收 class，会 CS0311）。
   凡引用 `UpdateGroup_*` 的文件顶部都要 `using HYC.Framework.Dots;`。
6. **自定义节点**（可选）：继承 `BTCustomNode`，实现 `SubType` / `NodeName` / `Kind` / `Execute`；
   自动被反射扫描注册，无需手动登记。
7. **出包前必做**：`Tools/HYC/BT/导出 Blob(打包用)` → 引导期 `BTBlobLoader.LoadAll()`。
   **编辑器能跑 ≠ 真机能跑**——编辑器靠 `BTAutoRegisterOnPlay` 自动注册，真机没有这回事，
   只改树不导出，真机会静默跑旧版本。

详见 [80](./80-行为树-总览.md) / [81](./81-BT-编辑器画布.md) / [82](./82-BT-运行时与Blob.md) / [83](./83-BT-自定义节点.md)。

## 六、新增一个 UI 窗口

```csharp
// ⚠️ 必须写 partial：框架会给每个 SystemBase 子类生成同名 partial（不写会 CS0101）
public partial class BagWindow : BaseWindowSystem<BagBinder>
{
    public override string PrefabKey => "UI/BagWindow";   // Addressable key

    public override void OnViewOpen(params object[] args)
    {
        base.OnViewOpen();
        Binder.CloseButton.onClick.AddListener(() => UIManager.Close<BagWindow>());
    }

    public override void OnViewClose()
    {
        base.OnViewClose();     // 必调：否则热键不注销、部件不关
        // …
    }
}

UIManager.OpenWindow<BagWindow>(1001);
```

- `UIManager` 是 `[DisableAutoCreation]`，**引导期必须手动 `GetOrCreateSystemManaged<UIManager>()`**。
- 打开是**异步**的：`Open<T>()` 返回时 `View == null`，初始化写 `OnViewOpen`，别写 `OnCreate`。
- Binder 由 `HYC Framework/UI/Generate UI Binders` 从 `ComponentBinderTable` 生成。

## 八、改完之后必须重跑什么

| 改了什么 | 要跑什么 |
| --- | --- |
| 表结构（增删改字段） | 菜单 **1 → 2 → 3** 全跑 |
| 只改 `.asset` 里的数值 | 只跑菜单 **3** |
| 改枚举成员（增删 / 换顺序） | 菜单 **1 → 2 → 3**（数值会变，属破坏性变更） |
| 改了行为树 | 重新**导出 BT Blob**（`Tools/HYC/BT/导出 Blob(打包用)`） |
| 改 `exportTarget` 或导出模式 | 重新导出，否则产物还是旧的 |
| 改节点参数槽位 | 先读 `BTNodeType.cs` 的注释，**新类型必须追加在末尾** |

## 十、最容易踩的 8 件事

1. **字符串字段必须显式选 `BlobString` / `FixedString`**，否则烘焙失败。
2. **分类字段用 `Enum` 不用裸 `Int`**，且枚举是 **1 基、没有 0**。
3. **Blob 里枚举是 `int`**——运行期别指望拿到枚举类型。
4. **改表结构只跑菜单 3 不生效**，必须 1 → 2 → 3。
5. **UI 类必须 `partial`**，且 `OnViewClose` 要调 `base`。
6. **`UpdateGroup_*` 要 `using HYC.Framework.Dots;`**；`BTInterpreterSystem` 是 struct，用 `GetOrCreateSystem<T>()`。
7. **BT 出包必须导出 Blob**，编辑器自动注册真机没有。
8. **新增 `BTNodeType` 要追加在末尾**（插中间会让旧资产序列化错位）。
