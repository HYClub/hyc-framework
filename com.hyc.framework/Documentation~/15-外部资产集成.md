# 15 · 外部资产集成（External Asset Integration）

> 让**非 HYC 生成的 Unity 资产**（如 `.inputactions`、材质、贴图、第三方 ScriptableObject 等）
> 也能挂进**数据配置（`HYC Framework/Config`）**窗口，在同一个左侧树里统一管理、在右侧用**原生 Inspector** 编辑。

## 一、核心概念：「外部配置」是一个非常规虚拟文件夹

这是最容易搞错的地方 —— **它不是磁盘上的目录，只是一组引用**：

| 项 | 说明 |
| --- | --- |
| 位置 | 配置树**最底部**（`InstallFolders` / `InstallFiles` 之后安装） |
| 外观 | 标签用独立青色（只有它自己染色，子节点保持默认色） |
| 数据 | `HYCSettings.IncludedAssetGuids` 注册表，跨会话持久化、随工程提交 |
| **本体不动** | 成员的资产文件**不会被移动或复制**，仍保留在它原来的位置；这里只登记 GUID 引用 |

由「引用语义」直接推导出的三条约束（**已有机制兜住，不需要额外代码**）：

| 约束 | 兜底机制 | 位置 |
| --- | --- | --- |
| 不可重命名（改名＝改真资产） | `CanRename` 只认 `FolderNode` / `FileNode` | `ConfigDataTree.cs` |
| 不可往外拖（无路径可搬） | `CanStartDrag` 只认 `FolderNode` / `FileNode` | `ConfigDataTree.cs` |
| Delete 键不会误删真资产 | 树**没有**实现 `ExecuteCommand` / `KeyCode.Delete` | —— |

另外：选中虚拟文件夹时点「新建配置」不会拿到空路径 —— `GetTargetFolder()` 遇到非 folder/file 会回落到 `ConfigDataSettings.RootFolder`。

### 节点类型

| 类型 | ID | 含义 |
| --- | --- | --- |
| `ConfigDataTreeVirtualFolderNode` | `-4`（常量 `NodeId`） | 「外部配置」虚拟文件夹本身 |
| `ConfigDataTreeExternalNode` | `-1000` 起始递减（`GetExternalID()`） | 单个外部资产的引用子节点 |

两者都定义在 `Editor/DataEditor/ConfigDataTree.cs`，与右侧查看器 `ConfigDataContainer` 共用同一套类型。

## 二、唯一入口：拖到树的空白区

从 **Project 窗口**把资产拖到**左侧树的空白区**（不能压在任何文件夹/文件行上）松手即可。

```
Project 窗口选中资产 → 拖到配置树的空白区 → 弹「确定/取消」确认框
  → 确定：登记 GUID → 重建树 → 自动展开「外部配置」→ 选中并滚动到新加入项
```

所有判断集中在一处：`ConfigDataTree.HandleDragAndDrop`。它先按「是否在 `ConfigDataSettings.RootFolder` 内」
把拖拽路径分成两组，**两条语义彻底隔离**：

| 组 | 落点 | 语义 | 光标 |
| --- | --- | --- | --- |
| **外部组**（不在配置根目录内） | 必须是树空白区 | 登记引用到「外部配置」，文件原地不动 | `Link` |
| **内部组**（配置根目录内） | 真实文件夹行 | 沿用原有「树内移动」（真搬家，`FileUtil`） | `Move` |

> ⚠️ **这是本方案唯一真正的危险点**：外部路径一旦误接入内部的 Move 分支，
> `.inputactions` 之类的资产就会被**真搬**到配置目录里，与「虚拟文件夹、文件原地不动」完全相反。
> 改这块时必须确认外部路径永远到不了 `ApplyMoveCore`。

### 空白区判定

`IsBlankDropArea()`：Unity 在空白区悬停时 `parentItem` 可能是 `null`，也可能给出隐藏的根节点
（`BuildRoot` 里根是 `{ id = -1, depth = -1 }`）——两种都算空白。
压在具体节点行上时返回 `None`（本控件不处理）。

### 会被拒绝的情况（都弹一句话说明）

| 情况 | 说明文案要点 |
| --- | --- |
| 拖了文件夹 | 「外部配置」只登记单个资产 |
| 扩展名黑名单（代码/着色器/UI 资源/程序集定义/预制体） | 不支持该文件类型 |
| 主类型黑名单（框架自产资产） | 它本就应该显示在配置树里 |
| 混合拖放（外部 + 内部配置资产） | 一次只能处理一种 |

### 确认弹窗

每次拖入**都弹**，列出资产名（超过 6 条折叠为「…等共 N 个」），并写明三条事实：
不移动文件、仍保留在原位置、右键移除只删引用。全部已在「外部配置」里时改为提示而非重复登记。

> 弹窗与写注册表都用 `EditorApplication.delayCall` 推出拖拽事务 ——
> 与 `FileUtil.MoveFileOrDirectory` 同因：拖拽回调事务内做 IO / 弹模态窗不稳。

## 三、过滤器：`ExternalAssetFilter`

`Editor/DataEditor/ExternalAssetFilter.cs`（`HYC.Framework.Config.Editor`），**不持有状态**。

| 方法 | 作用 |
| --- | --- |
| `IsBlacklistedExtension(path)` | 扩展名是否黑名单（不区分大小写；**无扩展名视为可纳入**） |
| `IsBlacklistedType(type)` | 主类型是否黑名单（含 `ConfigBase` 的全部子类） |
| `IsIncludablePath(path)` | 只看路径/扩展名的快速判断（拖拽校验用） |

**扩展名黑名单**（禁纳入）：`.cs` / `.js` / `.ts` / `.shader` / `.compute` / `.cginc` /
`.hlsl` / `.uss` / `.uxml` / `.asmdef` / `.asmref` / `.prefab`。

**类型黑名单**（框架自己产出的资产，由各自专用编辑器管，不进统一数据编辑器）：
`ConfigBase`（及其子类）、`ConfigTemplate`、`ConfigEnumDefinition`、`BTTreeAsset`、
`InputComponentMapping`、`HYCSettings`、`SceneContentTypeDef`。

拖放判定 `TryClassifyExternal()` 组合使用上述三个方法，并额外检查 GUID 是否可解析。

## 四、注册表：`HYCSettings`（持久化）

`Editor/HYCSettings.cs`，项目级 ScriptableObject（随工程提交，全团队共享，不用 `EditorPrefs`）。

| 成员 | 语义 |
| --- | --- |
| `IncludedAssetGuids` | `IReadOnlyList<string>`，当前登记的 GUID 集合（只读视图） |
| `AddIncludedAssetGuid(guid)` | 登记一个，**返回 `bool`**（重复时为 `false`，不抛异常） |
| `RemoveIncludedAssetGuid(guid)` | 移除一个，返回 `bool` |
| `ClearIncludedAssets()` | 清空注册表，无返回值 |
| `IsIncluded(guid)` | 存在性检查（写操作前先问它，比读整个列表干净） |

> 这一层**只做集合加减，不做校验** —— 合法性由 `ExternalAssetFilter` 在上层把关。
> 三个写方法内部都自带 `Save()`（立即落盘），调用方**不需要**再 `SetDirty` / `SaveAssets`。

`Ctrl+S` 的 `SaveAll` 会遍历 `IncludedAssetGuids`，把有未保存修改的外部资产一并落盘。

## 五、操作方式

| 操作 | 做法 |
| --- | --- |
| 加入 | Project 窗口拖到树空白区 → 确认 |
| 编辑 | 选中成员节点 ⇒ 右栏整体嵌入该资产的**原生 Inspector**；`.inputactions` 只给跳转按钮（见第六节） |
| 定位 | 双击成员节点，或右键「定位资源」（Project 窗口 Ping） |
| 移除 | 右键成员节点「从外部配置移除（不删除资产）」—— 只删注册表条目 |
| 清空 | 右键「外部配置」→「清空外部配置（仅移除引用）」—— 有二次确认 |
| 搜索 | 树内搜索直接生效（`TreeView` 基类按 `displayName` 匹配，文件夹名与成员名都能命中） |

## 六、右侧检视：`UnityAssetEditor`

`Editor/DataEditor/UnityAssetEditor.cs`。选中外部节点时右栏**整体嵌入 Unity 原生 Inspector**，
而不是自己再造一套字段绘制。它继承 `ConfigDataEditor`（`Open` / `Reload` / `OnGUI` / `Dispose`）。

| 约束 | 说明 |
| --- | --- |
| **原生编辑器不进 GC** | `Editor.CreateEditor(asset)` 出来的实例必须 `DestroyImmediate`，否则泄漏 IMGUI 状态 ⇒ `RebuildNative()` 与 `Dispose()` 里都强制销毁 |
| **切换/关闭都要销毁** | 只依赖 `mTreeNode.GetAsset()`，与任何树形态都能搭配；换选中即重建 |
| **`Reload()` 不是无操作** | 外部资产随时可能被改名或重导入，重建才能反映最新 `SerializedObject` |
| **创建失败要兜底** | `CreateEditor` 返回 `null` 时显示「无法为选中资产创建编辑器。」，不抛异常 |

选中「外部配置」文件夹本身时，右栏显示用法说明文案（`ConfigDataContainer` 的虚拟文件夹分支），不显示编辑器。

### `InputActionsAssetEditor`：`.inputactions` 只给一个跳转按钮

`Editor/DataEditor/InputActionsAssetEditor.cs`，约 130 行。右栏显示**资产名 / 路径 + 居中的
「在官方编辑器中打开」按钮**，点了直接进 Input System 自己的窗口。**不做任何编辑界面重实现。**

三条候选都评估过，最终定这条：

| 候选 | 能不能做 | 为什么没选 |
| --- | --- | --- |
| **嵌官方编辑窗口**（动作表 / 动作 / 绑定的编辑 UI） | **不能** | 这才本来是想要的东西，但：① `EditorWindow` 全部 39 个公开成员里没有 Embed / Attach / Reparent / Host，`docked` 只是只读状态（依据：安装目录 `Managed/UnityEditor.xml`；枚举正则要用 `[^"(]+` 断参，否则只匹配到无参方法会漏判）；② 官方窗口 IMGUI 版 `AssetEditor/InputActionEditorWindow.cs`、UITK 版 `UITKAssetEditor/InputActionsEditorWindow.cs` 都是 `internal`，`InternalsVisibleTo` 只列 Unity 自家测试程序集 ⇒ `GetWindow<T>()` 拿不到句柄；③ 唯一能改 UI 归属的 `rootVisualElement` 是 UITK `VisualElement`，而本窗口是 IMGUI（`TreeView` + `BeginArea`），渲染不了 |
| 嵌原生 Inspector | 能，但**不是要的东西** | 资产级 `InputActionAssetEditor` 的 `OnInspectorGUI()` / `OnHeaderGUI()` 都是空实现；导入器级 `InputActionImporterEditor` 有内容，但画的是「Edit Asset」跳转按钮 + 生成 C# 包装类的导入设置 + `ScriptedImporterEditor` 自带的 Asset Post Processors 等**与配置编辑无关的噪音控件**。嵌进来等于往右栏塞一堆导入设置，不做 |
| 自建一套输入动作编辑界面 | 能，但**不该做** | 与官方功能重复演进，Input System 包一升级就腐化。已实现过一版（714 行可增删改），按此口径移除 |

> 需要区分两个词：**「官方编辑器」= 那个独立的 Input Actions 编辑窗口**（嵌不进来）；
> **「原生 Inspector」= Project 选中资产时右侧的属性面板**（能嵌，但不是编辑界面）。
> 需求里说「把官方编辑器放进来」时指的永远是前者。

## 七、注意事项 / 坑

- **引用 ≠ 导出**：登记只是把 GUID 写进注册表；`Ctrl+S` 会落盘，但真正带出去要靠导出流程遍历 `IncludedAssetGuids`。
- **资产本体删除后**会留下幽灵项（GUID 解析不到路径），安装时跳过，需手动右键移除清理。
- **落点必须是空白区**是有意的设计：压在真实文件夹上仍走原有的「配置资产移动」语义，两者不混淆。
- **`prefab` 在黑名单里** —— 这是当初定的口径：预制体由专门的场景/预设流程管，不走数据配置树。
- 改过滤器黑名单时注意：`IsBlacklistedType(null)` 返回 `true`（空类型视为黑名单），这是有意的安全倾向。
