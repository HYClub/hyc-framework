# 11 · 字段类型与导出设置

> 对应 `Runtime/ConfigTemplate.cs`。这是配置管线里最需要细读的一章——字段怎么落到 Blob，全看这里的设置。

## 一、字段类型 `ConfigFieldType`（45 种）

### 基础类型（11）
`String` `Int` `Long` `Float` `Double` `Bool` `Short` `Byte` `UInt` `Char` `Decimal`

### Unity 资源引用（11）
`Sprite` `Texture2D` `GameObject` `AudioClip` `Material` `Mesh` `PhysicMaterial` `Font` `Shader` `TextAsset` `Object`

### 数学 / 结构体（16）
`Vector2` `Vector3` `Vector4` `Vector2Int` `Vector3Int` `Quaternion` `Color` `Color32` `Rect` `RectInt` `RectOffset` `Bounds` `BoundsInt` `Gradient` `AnimationCurve` `LayerMask`

### 框架扩展（7）

| 类型 | 存储 / 生成 | 说明 |
| --- | --- | --- |
| `Enum` | 引用 `ConfigEnumDefinition.className` | 需填 `enumRefClassName`；**完整机制见 [13-枚举配置](./13-枚举配置.md)**——数值 **1 基**、Blob 里存 `int`、配置类字段才是枚举类型 |
| `LocalizedKey` | 生成 `string` + `[LocKey]` | 多语言 key，需配合 loc 包 |
| `Reference` | 引用另一个 `[CfgAsset]` 类型 | 需填 `refTypeFullName`（pick 时的 Assembly-qualified 名）。**生成类按「短名 + 当前命名空间 root」确定性解析，不信全名里的旧命名空间**——root 切换后旧命名空间已失效，按它反射会生成失效 using（CS0246）；手写 `[CfgAsset]` 类（无对应模板）才按全名反射取真实命名空间 |
| `BehaviourTree` | 存 `BTTreeAsset.TreeId`（`long`） | 运行期经 `BTManager` 加载执行 |
| `AnimationClip` | 拖 `.anim`，生成 `AnimationClip` 字段 | — |
| `AnimatorController` | 拖 `.controller`，生成 `AnimatorController` 字段 | — |
| `Addressable` | **拖资源自动填地址，生成 `string`** | 运行期按地址加载 |

> **跨配置引用·运行期取回**：`Reference` 字段在配置类里是目标配置类型（如 `EffectConfig`），取其 ID 落盘（导出模式 `Member` 选 `id`）。运行期取回走**生成式静态门面** `{ns}.ConfigManager.{Type}.GetByID(id)`（无 World 依赖，内部转框架 `ConfigRegistry.GetRef`，零拷贝 ref，落 `Assets/HYC/Generated/Config/ConfigManager.cs`；未命中抛 `KeyNotFoundException`）；若需宽松语义（未命中不抛），用门面 `ConfigManager.{Type}.Contains(id)` 预判存在性、命中再取行。框架低层注册表名为 `ConfigRegistry`（`HYC.Framework.Config.ConfigRegistry`，原 `ConfigManager` 已改名）：与门面不重名，宿主同时 `using {ns};` 与 `using HYC.Framework.Config;` 也不会 CS0104；只有手工建表 / 注册才直接调 `ConfigRegistry`。**不再提供 World 扩展** `world.GetCfg{className}(id)`——它返回 blob 行值拷贝、未命中返 `default`，是 EA0001 运行期炸弹。

## 二、导出目标：每侧各自的「不导出」

配置模板字段**不再**用 `exportTarget`（Client/Server/Both）判定进哪一侧——那套已移除。
现在由每侧的导出设置单一决定：把该侧 `mode` 选成 `ConfigFieldExportMode.None`，这一侧产物就不含此字段。

| 想要的效果 | 设置 |
| --- | --- |
| 两侧都导出（默认） | 两列各自选正常导出方式 |
| 只在客户端用它 | **服务端**那列选「不导出」 |
| 只在服务端用它 | **客户端**那列选「不导出」 |
| 编辑器留着、两侧产物都不要 | 两列都选「不导出」 |

> 服务端拿不到的字段在服务端那列选「不导出」，可减小服务端数据体积、也避免把客户端资源信息下发给服务端。

编辑器入口：模板编辑器字段表里的 **客户端导出** / **服务端导出** 两列（「导出」「字段检查配置」两个切页均已移除——导出与检查都并进了这张字段表，改这里即可）。

> ⚠️ `ConfigExportTarget`（Client / Server / Both）本身仍保留，但**只用于枚举定义**（见 [13 篇](./13-枚举配置.md)），与配置模板字段无关——别再往模板字段上找它。

## 三、导出设置 `ConfigFieldExportSetting`

每个字段有**两套**导出设置：`clientExport` 和 `serverExport`——同一字段在两侧可以取不同值、不同类型表示。

### `ConfigFieldExportMode`（9 种）

| 模式 | 效果 |
| --- | --- |
| `Direct` | 原样导出（按字段自身类型/对象） |
| `ToString` | 数值/布尔/枚举/结构 `ToString()`，导出 `string` |
| `BlobString` | 字符串在 Blob 里用 `BlobString`（**变长**，由 BlobBuilder 分配） |
| `FixedString` | 字符串在 Blob 里用 `FixedString`（**定长内联**，容量见下） |
| `Member` | 配置引用字段导出它的某个标量成员（如 `ID` / `GUID`），填 `memberName` |
| `AssetName` | 资源/对象字段导出**资源名**（`string`） |
| `AssetPath` | 资源/对象字段导出**项目内路径**（`Assets/...`，`string`，导出时解析） |
| `AssetAddressable` | 资源/对象字段导出 **Addressable 地址**（`string`，导出时解析） |
| `None` | **不导出**：这一侧的产物不含此字段（见 [二](#二导出目标每侧各自的不导出)） |

> 下拉里 `Direct` 从不单独出现，一律写明类型名——如 `直接导出(Int)`、`直接导出(string)`、`直接导出(Vector3)`，
> 避免"直接导出"到底是啥类型要靠猜。

辅助属性：

```csharp
setting.IsDirect       // mode == Direct
setting.IsStringValue  // BlobString 或 FixedString
setting.mode == ConfigFieldExportMode.None   // 该侧不导出
```

### 新建字段 / 改类型后的下拉默认值

改字段类型（或勾选/取消「列表」）时，两侧导出设置会按新类型复位为各自的默认值：

| 字段类型 | 默认导出 |
| --- | --- |
| 值类型（Int / Long / Float / Bool / 枚举 / Vector… / 行为树） | `Direct`——直接导出该值类型本身（下拉显示 `直接导出(Int)` 等） |
| 引用其他配置（`Reference`，含 `List<引用>`） | `Member`——**取成员 `ID`** |
| 字符串 / 多语言 Key / AA 地址 | `Direct`——`直接导出(string)` |
| 音频事件 | `BlobString`（变长、不截断） |
| 资源/对象（Sprite、GameObject、AudioClip…） | `AssetName`——导出资源名 |

> 多语言 Key 另有约定：它只进客户端，切到该类型时**服务端会自动置「不导出」**（用户可改）。

### `ConfigFixedStringSize`（定长档位）

`Size32` `Size64` `Size128`（默认） `Size512` `Size4096`

对应 `Unity.Collections.FixedString{size}Bytes`。

> **怎么选**：名称/短文本用 64～128；描述性长文本用 512 或 4096；超长或长度差异极大的用 `BlobString`（变长，省空间但有间接寻址）。**定长会按最大容量占位**，别所有字段都给 4096。

## 四、检查规则

三个规则各自带级别，`None` 表示不启用：

| 字段 | 规则 | 适用类型 |
| --- | --- | --- |
| `notEmptyCheck` | 非空（null / 空串） | 仅**有真空态**的类型：字符串族（String / LocalizedKey / Addressable / AudioEvent）、配置引用、Unity 对象族（Sprite / GameObject / AudioClip…）、行为树 |
| `notZeroCheck` | 非 0 | 仅数值类型 |
| `rangeCheck` | 落在范围内（配合 `hasRange` / `minValue` / `maxValue`） | 仅数值类型 |

级别 `ConfigCheckLevel`：`None` < `Info` < `Warning` < `Error`。

设置 `Error` 会让校验不通过（进而阻断导出），`Warning` 只提示。

> ⚠️ **纯值类型没有「非空」可言**：int / float / bool / 枚举 / 结构体永远有值，「非空」对它们不存在——菜单里不出现、生成器不发射（强行判空只会得到 `== default`，对 int 即 `== 0`，与「非0」重复且语义错误）。数值类型的「必须有值」需求用「非0」表达。存量值类型字段上遗留的 `notEmptyCheck` 按无效处理：菜单显示「不检查」、生成器不发射；改一次字段类型（`OnFieldTypeChanged` 联动清理）或任选一项检查（互斥落盘时归零其余）即被清掉。

### 编辑器入口：字段表「检查」列一个下拉（互斥三选一）

模板编辑器字段表每行有一个「检查」下拉，点开是**二级菜单**：顶层 `不检查 / 非空▸ / 非0▸ / 范围▸`，后三项各悬停出子菜单选 `Info / Warning / Error`。

- **三项互斥**：同一字段同时只能生效一项检查——选「非0 · Warn」会自动清掉「非空」「范围」的设置。落盘仍是三个独立枚举字段（选中项写级别、其余置 `None`），序列化格式不变；历史存档里多项同时非 `None` 的遗留数据，按 `非空 > 非0 > 范围` 的优先级显示一项，下次选择时归零其余。
- **可选性按字段类型决定**（与生成器的发射条件严格一致）：
  - 「非空」只对**有真空态的类型**（字符串族 / 配置引用 / Unity 对象族 / 行为树）出现——值类型的菜单里**根本没有这一项**；
  - 「非0」「范围」只对**数值类型**（Int / Long / Float / Double / Short / Byte / UInt / Decimal）出现，其他类型菜单里也不渲染。
  - 不支持的项从入口上就选不出；字段被改成不支持的类型时，已设置的对应检查会被自动清除（如 int → string 清「非0 / 范围」，string → int 清「非空」）。
- **「范围」选中后才出现 Min / Max**（小宽输入框，紧贴下拉右侧）；选其他项或「不检查」时只显示下拉按钮本身。
- 旧存档里若 `hasRange` 未勾选但 `rangeCheck` 有级别，菜单显示生效项、Min/Max 不出现（勾选状态随「范围」选择联动开关）。

## 四·A、编辑器只读 `readOnly`（仅展示层）

`ConfigTemplateField.readOnly = true` 时，生成代码会给该字段加 `[ReadOnly]` 特性，数据编辑器里该字段的输入被禁用（置灰），无法手改。

- **只影响编辑器展示**：不影响运行时。像 `ID` / `GUID` 这类由框架在保存时反射赋值（自动发号）的字段，置灰后照常由代码写入。
- **不影响导出**：Blob / JSON 导出照常带上该字段的值（与 `notEmptyCheck` 等"校验"无关，它不产生任何 `CheckError`）。
- **框架基类已默认开启**：`FrameworkTemplates/ConfigBase.asset` 的 `ID` / `GUID` 已勾选 `readOnly`，所有继承它的配置表（如 ActorConfig）在编辑器里这两个字段均置灰。
- **设置入口**：在模板编辑器里展开某字段行（▶），勾选「只读」。等价于在 `.asset` 里写 `readOnly: 1`。

> ⚠️ 改了模板的 `readOnly` 后，**使用该模板的游戏工程必须重新生成配置代码**（`[ReadOnly]` 才会进入生成的 C# 类）。只改 `.asset`、不重新生成，看不到置灰效果。

## 四·B、关联参数 `visibility`（条件显示）

`ConfigTemplateField.visibility`（`List<ConfigVisibilityCondition>`）给字段挂**条件显示规则**：仅当规则**全部满足**时，该字段才在**数据编辑器的配置面板**上绘制。典型场景：勾了「是否掉落」才出现「掉落物 ID」「掉落概率」这组字段。

- **设置入口**：模板编辑器展开字段行（▶）→「关联参数」块 →「+ 添加条件」。每条 = 左下拉选本模板（含继承链）一个 **bool/enum 标量字段** + 右侧控件（bool→勾选，勾选 = 要求为真；enum→`MaskField` 多选枚举值，≤32 个）。可加多条、× 删除。
- **多条之间 AND**：全部满足才显示；enum 条件命中任一所选值即满足。
- **目标字段丢失 / 类型不符 ⇒ 视为满足（字段保持显示）**：配置面板不能因为目标字段被改名、删除就把字段吞掉。失效条件在模板编辑器汇总区给**黄字警告**（未选目标 / 指向自身 / 目标不存在 / 目标为列表 / 目标非 bool-enum / enum 条件未选值，共六类；只警告，不阻断生成，无效条件不发射特性）。
- **仅影响数据编辑器面板**：不影响反射赋值（自动发号照常）、不影响导出（Blob / JSON 照常带该字段的值）。
- **不级联**：条件只读目标字段本身的值，不递归展开其它条件字段的可见性。

数据流复用「模板标记 → 生成特性 → 编辑器读取」既有范式（与 `readOnly` 同款）：

```
模板 .asset：visibility[i] = { targetField, boolValue, enumValues }
   ↓ 生成代码
生成的类字段上：[CfgVisibleWhen("targetField", true)] / [CfgVisibleWhen("target", "Value1", "Value2")]
   ↓ GUIType 反射缓存
GUITypeField.VisibleWhen
   ↓ GUIDrawer.CheckVisible 求值（反射读目标对象当前值，AND）
不满足 ⇒ 整行跳过 DrawField（面板上不出现）
```

> ⚠️ 改了模板的关联参数后，**游戏工程必须重新生成配置代码**（`[CfgVisibleWhen]` 才会进入生成的 C# 类）。enum 条件超过 32 个值无法多选（`MaskField` 上限），需精简枚举或改用布尔字段。

## 四·C、导出可行性校验（静态，哪些组合能导）

有些「字段类型 + 导出模式 + 一侧」组合在生成阶段就会产出坏代码（客户端编译报错）或运行时导出失败（服务器 JSON 无法序列化）。框架在**模板保存时即红字提示**、在**生成代码时硬拦截**，而不是等导出/编译才爆。

- **两套后端**：客户端 = `CfgXxx` **Blob**（必须 blittable，结构体不能继承、不能放 Unity 对象）；服务器 = `XxxServer` **JSON**（Newtonsoft 序列化）。
- **统一判定（静态，不靠捏样例试跑）**：直接复用代码生成器的类型解析，永不漂移：
  - **客户端不可导**：`BlobElemInfoOf` 对不支持的类型会落到 `default: int` 兜底（生成器随后在 BlobBuilder 里把对象/结构赋给 `int` 字段 → 编译报错）。涵盖：Sprite / Texture2D / GameObject / AudioClip / Material / Mesh / PhysicMaterial / Font / Shader / TextAsset / Object / AnimationClip / AnimatorController / Gradient / AnimationCurve / Rect / RectInt / RectOffset / Bounds / BoundsInt / LayerMask / Decimal / Char 等用「直接导出」。
  - **配置引用不再有这条坑**：引用字段默认就是「取成员 ID」（标量、blittable），下拉里也不再提供「直接导出(整对象)」。只有历史存档里残留的整对象设置才会被判定为不可导，此时下拉会把它显示成「(旧设置: Direct)」提示你换掉。
  - **服务器不可导**：「直接导出」且类型是 Unity 对象或不可 JSON 序列化的类型（以上资源/对象引用族 + Color / Color32 / Gradient / AnimationCurve）。Rect / Bounds / Vector* / Quaternion 等结构 Newtonsoft 能序列化，所以只拦客户端那一侧（其中 Rect / Bounds / Rect* / LayerMask 等虽能序列化但服务器通常无法消费，默认仍可「直接导出」，按需选「不导出」）。
  - **服务器侧「强制不导出」**：上述服务器不可导类型在服务器导出下拉里**只提供「不导出」一项**（不再给「直接导出」/「资源名」等），且默认即 `None`——这类字段在服务器数据里没有意义，从源头杜绝服务器 JSON 自引用崩溃（如 GameObject 的 `gameObject` 循环引用）。历史存档若残留「直接导出」会被可行性校验红字提示，改回「不导出」即可；运行期导出也加了容错（自引用循环 / 无法序列化成员自动跳过并告警，不再整文件崩溃）。
- **提示与拦截**：
  - 模板编辑器 → 顶部 `tplErrors` 红字汇总 + 字段表里不可导的那一侧 Popup **红底高亮**，并给出建议（服务器不可导类型 → 「服务器导出」下拉已强制只给「不导出」，历史残留的「直接导出」改回即可；其余资源/对象族 → 改「资源名 / 资源路径 / AA地址 / 转字符串」；非资源类型 → 改「转字符串」；两侧都能直接选「不导出」）。
  - 「生成代码」按钮 → `ConfigTemplateCodeGen.Validate` 返回失败，**直接阻断生成**，错误信息即上述红字内容。
  - 「保存模板」**不受影响**（草稿可以存，但生成前必须修掉）。
- **为什么不误伤**：合法用 `int` / `enum → int` 的字段被正确排除；`BehaviourTree → long`、`Vector*` / `Color*` / `Quaternion` 等 blittable 结构，以及一切「转字符串 / BlobString / FixedString / 取成员 / 资源名 / 资源路径 / AA地址」模式（都转成 string 或标量）均判定为可导。
- **维护点**：增删资源 / 不可 JSON 类型时，只需改 `Runtime/ConfigFieldTypes.cs` 的 `IsAssetRef` / `IsServerUnsupported`——模板编辑器与代码生成器**都委托到它**（唯一判定真源），不再各自维护 switch，也就不会出现「能选 Direct 却生成拦截」或「下拉禁了却还能导」的漂移。改完再补 `UnityTypeName` 的资源类型映射。

## 五、`ConfigTemplateField` 字段一览

| 字段 | 说明 |
| --- | --- |
| `name` / `description` | 字段名 / 说明 |
| `type` | `ConfigFieldType` |
| `isList` | 是否为列表 |

## 六、典型组合

| 场景 | 设置 |
| --- | --- |
| 装备名（多语言） | 类型 `LocalizedKey`，`clientExport = FixedString(Size128)` |
| 长描述文本 | 类型 `String`，`BlobString`，`Size4096` 浪费就用 `BlobString` |
| 图标 | 类型 `Sprite`，`clientExport = AssetAddressable`（生成地址字符串，运行期按地址加载） |
| 关联另一张表的行 | 类型 `Reference` + `refTypeFullName`，或 `Member` 模式只导出对方的 `ID` |
| 引用的行为树 | 类型 `BehaviourTree`（存 `TreeId`） |
| 只在客户端用的表现字段 | 服务端那列选「不导出」（`serverExport.mode = None`） |
| 只在服务端用的校验字段 | 客户端那列选「不导出」（`clientExport.mode = None`） |
| 服务端校验用的关键数值 | 「检查」下拉选 `非0 · Error`（与「范围」互斥，二选一） |
| 勾选后才出现的字段 | 加「关联参数」：目标 bool 字段 + 勾选（要求为真） |

## 注意事项 / 坑

1. **字符串必须显式选 `BlobString` 或 `FixedString`**，`Direct` 会把托管 `string` 带进 Blob 导致烘焙失败。
2. **`Reference` 要填完整的 Assembly-qualified 类型名**，填错会在生成/导出阶段报错，且错误信息不一定直观。
3. **改任一列的导出设置（含选「不导出」）后必须重新导出**，否则产物还是旧的。
4. **改字段类型会连带把两侧导出设置复位为默认值**（引用→取成员 ID、值类型→直接导出自身类型…）。若之前手动改过，切类型后要重新确认一遍。
5. **`FixedString` 溢出会静默截断**——容量选小了不会报错，只会丢字，长文本务必留余量。
6. **`AssetPath` 依赖项目内路径**，资源挪动后旧数据不会自动更新；跨工程复用优先用 `AssetAddressable`。
7. **关联条件的目标字段被删/改类型后条件静默失效**（字段保持显示，模板汇总区黄字警告）——重构模板时留意警告，条件要重新指。
8. **资源/对象/Color/Gradient/曲线字段在服务器侧已强制「不导出」**：Sprite 等 Unity 对象或不可序列化类型「直接导出」到服务器会生成无法 JSON 序列化的字段（自引用循环导致导出崩溃），故服务器导出下拉对这些类型**只提供「不导出」一项、且默认即不导出**，无需手动改；到客户端会生成编译报错的 Blob（`BlobElemInfoOf` 落到 `default: int` 兜底）仍走「资源名/路径/AA地址/转字符串」。若历史存档残留「直接导出」，模板保存即红字提示、「生成代码」硬拦截，改回「不导出」即可。详见 [四·C](#四c导出可行性校验静态哪些组合能导)。
