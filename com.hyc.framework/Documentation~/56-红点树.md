# 56 · 红点树（Red Dot）

> **面向宿主游戏**的用法文档：只讲怎么用，不展开框架内部实现。
> 源码：`Runtime/RedDot/`（3 个文件）、`Editor/RedDot/`（2 个文件）。

## 一句话

在**代码里注册一棵红点树**，玩法侧只打标（`Mark` / `SetCount`），UI 侧在 `AbsUISystem` 里挂一下
`RedDotBehaviour` 就能自动显隐 —— 父节点亮灭由子节点自动聚合，不需要手动逐级刷新。

---

## 一、注册树（启动期一次，自顶向下）

```csharp
using HYC.Framework.RedDot;

public static class RedDotIds
{
    public static readonly RedDotKey Main     = new RedDotKey(1000);
    public static readonly RedDotKey Mail     = new RedDotKey(1001);
    public static readonly RedDotKey MailSys  = new RedDotKey(1002);
    public static readonly RedDotKey Shop     = new RedDotKey(1100);
}

// 在引导阶段（Bootstrap / 首个 System 初始化）注册一次即可
RedDotManager.Register(RedDotIds.Main,    default,              "主界面");
RedDotManager.Register(RedDotIds.Mail,    RedDotIds.Main,       "邮件", mode: RedDotMode.Count);
RedDotManager.Register(RedDotIds.MailSys, RedDotIds.Mail,       "系统邮件");
RedDotManager.Register(RedDotIds.Shop,    RedDotIds.Main,       "商店");
```

- **键是强类型**（`RedDotKey` 包一个 `int`），代码侧没有字符串，拼错编译不过。
- `id = 0` 视为无效（`IsValid == false`），注册会被忽略并告警。
- **先注册父、再注册子**；即使子先注册，父注册时也会把这些子接回来，不会丢。

## 二、打标（玩法侧，A3）

```csharp
RedDotManager.Mark(RedDotIds.MailSys);        // 置「亮」
RedDotManager.Mark(RedDotIds.Shop, false);    // 熄
RedDotManager.SetCount(RedDotIds.MailSys, 3); // 计数（> 0 同时视为亮）
```

**聚合规则**：父「亮」= 自身亮 **或** 任一子亮；父「计数」= 自身计数 **+** 所有子计数之和。
所以只要给**叶子**打标，整条祖先链会自动亮。

## 三、UI 显示（三层，从零代码到完全手动）

### L1 · 预制体零代码（默认，推荐）

1. 在窗口预制体里建一个「红点」子物体（Image 圆点，或「底板 + TMP 数字」）。
2. 挂 `RedDotBehaviour`，填 `Key`（编辑器已注册节点多时是**下拉**，否则填 id）。
3. 需要显示数字就勾 `Show Count` 并把 `Count Label` 指向 TMP 文本。
4. **不用写任何代码** —— 窗口打开时 `AbsUISystem` 自动收集并绑定，关闭时自动退订并复位。

> `Badge` 留空 = 组件所在物体。**如果本物体还承载其它内容，请把红点放到单独子节点并在 `Badge` 指向它。**

### L2 · 动态列表项

列表项是运行时实例化的，「打开时收集」扫不到，显式绑：

```csharp
protected override void OnViewOpen()
{
    base.OnViewOpen();                      // 必须调 base：红点/焦点/热键都靠它
    foreach (var item in itemList)
        BindRedDot(RedDotIds.MailSys, item.Dot);   // item.Dot 是该行上的 RedDotBehaviour
}

protected override void OnViewClose()
{
    foreach (var item in itemList)
        UnbindRedDot(item.Dot);
    base.OnViewClose();
}
```

### L3 · 逃生舱（自己控制布局）

```csharp
if (IsRedDotActive(RedDotIds.MailSys)) { /* 自定义表现 */ }
var n = GetRedDotCount(RedDotIds.MailSys);
```

## 四、已读

```csharp
ConsumeRedDot(key);                 // 只清该节点自身（打开邮件后把这一条熄灭）
ConsumeRedDotWithChildren(key);      // 连同整棵子树（「全部已读」）
```

清完之后聚合会自动向上重算，父节点随子节点一起熄。

## 五、存档（框架不落盘，交给你自己的存档）

红点态**跨帧持久**，但框架不写文件 —— 需持久化时导出/恢复：

```csharp
// 存盘
var states = new List<RedDotState>();
RedDotManager.ExportState(states);          // 只导「自有值」，聚合值可重算
saveData.redDots = states;

// 读档（注册完树之后）
RedDotManager.ImportState(saveData.redDots);
```

`RedDotState` 是 `[Serializable]` 的 `{ int Id; int Count; bool Flag; }`，可直接进你的存档结构。

## 六、调试

菜单 **`HYC Framework/Tools/Red Dot Viewer`**：只读列出节点层级、自有值、聚合值、子节点数。
非 Play 模式下通常为空（注册发生在运行时引导）。

## 七、坑

1. **不要用 `EventMessage` 承载红点态**——它是单帧消息，红点要跨帧。需要的话在系统里转成 `Mark`。
2. **父节点没注册时，子节点的「亮」不会冒泡到不存在的父**；注册顺序建议自顶向下。
3. **`override OnViewOpen/OnViewClose` 必须调 `base`**——红点绑定与退订挂在基类上。
   （`OnViewOpen` 漏调 base 有兜底：首次 `OnUpdate` 会补绑一次；`OnViewClose` 漏调会漏退订。）
4. **红点只在主线程读写**（无锁），不要在 Job 里调。
5. **`Badge` 默认是组件所在物体**；挂在「整行根节点」上会把整行隐藏掉。
6. **树是静态内存**：切场景/重登时如果重建了注册，先 `RedDotManager.Clear()` 再重新 `Register`。
