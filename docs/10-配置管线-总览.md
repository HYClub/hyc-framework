# 10 · 配置管线（Config）总览

## 职责

把 Excel / 模板定义的配置表，在**生成期**烘焙成不可变 Blob，**运行期**以世界无关的静态表提供无分配查询。

一句话：**编辑期是 ScriptableObject + 生成的代码，运行期只有一个 Blob 指针。**

---

## 全链路

```
① 配置模板 ConfigTemplate        定义表结构与字段
        ↓  （Editor：代码生成）
② 生成的 C# 类 [CfgAsset]        blittable struct，命名空间 HYC.Framework.Config.Generated
        ↓  （Editor：数据编辑器填数据）
③ 配置资产 .asset                每行一个数据条目
        ↓  （Editor：导出）
④ BlobAssetReference<BlobRoot<TRow>>
        ↓  （Bootstrap：注册）
⑤ ConfigManager 静态表
        ↓  （运行期：查询）
⑥ 玩法系统 / UI 直接 Get<T>(id)
```

---

## 核心类

| 类 | 位置 | 职责 |
| --- | --- | --- |
| `ConfigTemplate` | Runtime | 表结构模板（本身也是一个配置资产 `模板/配置模板`，可在数据编辑器里重新打开再生成） |
| `ConfigTemplateField` | Runtime | 单个字段定义：类型、列表、导出目标、检查规则、客户端/服务端导出设置 |
| `ConfigManager` | Runtime | 运行期静态表，按行类型注册与查询 |
| `ConfigBlobTable<TRow>` | Runtime | 单张表（内部持有 `BlobArray<TRow>`） |
| `BlobTable` | Runtime | Blob 构建/读取辅助 |
| `IConfigIdProvider` | Runtime | ID 分配策略（`LocalConfigIdProvider` / `NetworkConfigIdProvider`） |
| `ConfigGenerator` | Editor | 由模板生成 C# 类 |
| `ConfigExportService` | Editor | 把数据烘焙成 Blob 并导出（客户端/服务端可分开） |
| `ConfigValidator` | Editor | 校验（`HYC Framework/Tools/Validate Config`） |

## 运行期查询 API

```csharp
// 注册（Bootstrap / A1 阶段做一次）
ConfigManager.Register(myTable);                 // ConfigBlobTable<TRow>

// 查询
if (ConfigManager.TryGet<FashionRow>(1001, out var row)) { /* ... */ }
var row2 = ConfigManager.Get<FashionRow>(1001);  // 找不到返回 default
bool exist = ConfigManager.Contains<FashionRow>(1001);
var all = ConfigManager.GetAllRows<FashionRow>();   // BlobArray<TRow>，表未注册返回 default
bool has = ConfigManager.Has<FashionRow>();

// 物化托管包装（带缓存，避免重复装箱/构造）
var vm = ConfigManager.Materialize<FashionVM, FashionRow>(1001, r => new FashionVM(r));

// 清空（切场景/重进游戏时）
ConfigManager.Clear();   // 会对 IDisposable 的表调用 Dispose
```

### 要点

- **泛型参数是行类型 `TRow`，约束 `unmanaged`**——行必须是 blittable 结构体。
- **`Get` 找不到不抛异常**，返回 `default`；需要区分"没这条"时用 `TryGet` / `Contains`。
- **`Materialize` 有对象缓存**，`Register` 时会 `Clear()` 掉——注册全部完成后再开始查询，避免缓存被中途清掉。
- **不需要 World 句柄**，UI 层可以直接查。

## 模板（ConfigTemplate）字段

| 字段 | 说明 |
| --- | --- |
| `displayName` | 显示名，支持 `分类/名称`，如 `装备/时装` |
| `className` | 生成的 C# 类名，如 `FashionConfig` |
| `lastGeneratedClassName` | 上次生成时的类名，用于检测改名并触发改名处理（`HideInInspector`） |
| `baseTemplate` | 基类模板，生成的类继承它；基类字段以只读展示 |
| `iconBuiltInName` | 内置图标名（`EditorGUIUtility.IconContent`） |
| `iconCustom` | 自定义图标（项目内 `Texture2D`），优先级更高 |
| `fields` | 字段列表 |

字段细节（类型、导出设置、检查规则）见 [11-字段类型与导出设置](./11-字段类型与导出设置.md)。

## 注意事项 / 坑

1. **`TRow` 必须 blittable**——字符串字段要选 `BlobString` 或 `FixedString` 导出模式（见 11 篇），否则烘焙会失败。
2. **`Materialize` 缓存会被 `Register` 清空**——引导期注册完所有表之后再开始查询。
3. **`GetAllRows` 返回 `BlobArray<T>` 引用**，不要长期持有跨 Blob 生命周期；表未注册时返回 `default`（`Length` 为 0，遍历前先 `Has<T>()`）。
4. **改了模板的 `className` 再生成**会走改名处理流程，原有数据资产要确认是否跟着迁移。
5. **导出目标**（Client / Server / Both）决定字段进哪一侧产物，改字段的 `exportTarget` 后需要重新导出。
