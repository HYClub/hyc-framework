# 95 · CI 与本地验证

> 本篇回答一个问题：**改了框架代码，怎么在提交前确认没改坏？**
>
> 分两层，能力与代价差很多，务必分清：
>
> | 层 | 跑什么 | 需要什么 | 能发现什么 | 不能发现什么 |
> | --- | --- | --- | --- | --- |
> | **闸门层**（本地/CI 每次都跑） | `scripts/verify-gate.sh` | bash + git + python | 文档索引过期、tag 与包版本脱节、漏 `.meta`、菜单中文化 | **编译错误、运行期行为** |
> | **Unity 层**（本地跑 / CI 手动） | Test Runner EditMode | Unity 2022.3.35f1c1 | 编译错误、55 个 EditMode 用例的行为 | 使用方工程里的集成问题 |

---

## 一、闸门层（推荐每次提交前跑）

```bash
bash scripts/verify-gate.sh
```

输出全绿即通过，退出码 0；任一项失败退出码 1。CI 上每次 push / PR 自动跑。

它守四类**静默腐化**——这类问题的共同特征是**Unity 编译发现不了**，
但会让后来查代码的人（或 AI）按错误信息去找根本不存在的文件：

| # | 检查项 | 抓的是 |
| --- | --- | --- |
| 1 | `100-文件与类索引.md` 声明的文件数 == 磁盘实际 | 新增/删除 `.cs` 后忘了更新索引 |
| 2 | 同上，类型声明数 == 实际 | 同上 |
| 3 | 索引各分组标题的文件数之和 == 总声明数 | 索引内部自相矛盾（改了总数没改分组） |
| 4 | 新增 `.cs` 都有 `.meta`；没有孤儿 `.meta` | 漏提交 `.meta` → Unity 重新生成 GUID → 引用全丢 |
| 5 | 最新 tag 的版本 == `package.json` 的 `version` | 发版打错 tag（历史上 5 个 tag 都写着 `1.0.0`，见 CHANGELOG 勘误段） |
| 6 | 包内主菜单路径全英文 | 违反菜单英文化约定（`Samples~/` 下 3 个中文项是有意例外） |

### 为什么第 1~3 项要剥离注释才能数类型

统计"类型声明数"时，**必须先剥离注释与字符串字面量**，否则 XML 文档注释里的
`<c>class Foo</c>` 会被计进去。

这个坑踩过两次：`FileIndexAuditTests` 与 `verify-gate.sh` 的第一版都中招，
一度报出 387 而实际只有 362（虚高 25）。现在两者都走同一套剥离逻辑
（单趟词法扫描：注释 / 字符串 / 逐字字符串 / 字符字面量）。

### 为什么闸门要单独存在，而不是"跑一遍测试就行"

Unity 测试也能做第 1~3 项，但跑测试要开Unity、可能几分钟，
而**提交前最需要的恰恰是那个 3 秒出结果的检查**。
另外 `FileIndexAudit` 刻意不碰任何 `UnityEditor` API，就是为了
"即使 CI 拿不到 Unity 许可，它仍能在纯 .NET 环境作为兜底闸门运行"。

## 二、Unity 层（EditMode 测试）

### 本地跑

1. 用 Unity **2022.3.35f1c1** 打开任意一个引用了本包的工程
   （SnowBros / TD 都行，它们都是 `file:` 引用，改框架即时生效）。
2. 菜单 **Window → General → Test Runner**。
3. 切到 **EditMode** 页，点 **Run All**。

> ⚠️ 注意：包自己的 `Tests/Editor/` **必须先被宿主工程识别**才会出现在 Test Runner 里。
> `HYC.Framework.Tests.Editor.asmdef` 带 `defineConstraints: ["UNITY_INCLUDE_TESTS"]`，
> 该约束在 Editor 下自动满足；但如果宿主工程装了自定义 asmdef 引用规则，需确认
> `HYC.Framework.Runtime` / `HYC.Framework.Editor` / `HYC.Framework.Tests.Editor`
> 三者构成完整的 `autoReferenced` 链。

### 目前 55 个用例覆盖什么

| 契约 | 用例数 | 钉住的是什么 |
| --- | --- | --- |
| `AttributeKey` FNV-1a 哈希 | 5 | 名称→哈希的稳定性（含空串 / 中文 / 超长名） |
| `ConfigBlobTable` 查询语义 | 7 | 命中 / 未命中 / 类型不匹配 |
| 公开API 签名快照 | 1 | 对外接口增删改会被 diff 出来 |
| 索引文档自检 | 3 | 与 `verify-gate.sh` 第 1~3 项同源 |
| 代码生成写盘 | 7 | 内容未变不重写（免无谓重编译）；换行差异视为变化 |
| BT 运行态释放 | 6 | 清理入口对"从未注册 / 已释放"实体安全且幂等 |
| 存档三条本分保证 | 16 | 原子写、坏档不覆盖、格式版本不误读 |
| 本地化原子提交 | 10 | `Reload` 失败 ⇒ 现有一字不动 |

⚠️ 两个测试类通过**反射**直接摆 `LocalizationManager` / `SaveManager` 的静态字段
（这两处没有注入 / Reset API）。代价写在代码注释里：
**`LocalizationManager` 新增静态字段时必须补进 `TrackedFields`**，否则用例会跨用例污染。

⚠️ 写涉及日志的用例时：`Log.Error` 走 `Debug.LogError`，
Unity 测试框架遇到**未声明**的 Error 会直接判失败——必须显式 `LogAssert.Expect`。

## 三、CI 现状与开启 Unity 层

`.github/workflows/gate.yml` 有两个 job：

| job | 状态 | 说明 |
| --- | --- | --- |
| `gate` | **启用** | 跑 `verify-gate.sh`，Ubuntu + Python 3.12，无需 Unity |
| `unity-tests` | `if: false`（停用） | 需要 Unity 许可密钥 |

### 为什么 Unity 层默认停用

Unity 的**个人版许可绑定桌面激活，不提供 CI 密钥**；本仓库是公开仓库，
Actions 上拿不到可用的 batchmode 许可。强行开启只会得到一个必红的 job。

这不代表放弃，而是**先把不依赖许可的部分全做掉**（闸门层），
等真的需要时再按下面步骤开启。

### 开启步骤

1. 在 Unity Hub 对 2022.3.35f1c1 申请/获取 `.ulf` 许可文件，
   用 `base64` 编码后存为仓库 secret `UNITY_LICENSE`。
2. 存 `UNITY_EMAIL` / `UNITY_PASSWORD` / `UNITY_SERIAL` 三个 secret。
3. 把 `gate.yml` 里 `unity-tests` 的 `if: false` 改成 `if: true`。
4. 首次跑建议用 `workflow_dispatch` 手动触发，确认绿了再放开push 触发。

CI 会先跑 `ci/make-test-project.sh` 生成一个**最小壳工程**
（因为本仓库是 UPM 包，没有 `ProjectSettings/`，Unity 打不开），
再交给 `game-ci/unity-test-runner` 跑 EditMode。

壳工程的依赖版本从 `com.hyc.framework/package.json` 的 `dependencies` 读取，
不在脚本里硬编码；Unity 版本以包根的 **`.unityVersion`** 为单一真源
（`2022.3.35f1c1`），并与 `package.json` 的 `unity` 字段（`2022.3`）交叉校验——
版本猜错的后果是"编译报一堆看不懂的 API 错误"，比直接失败难查得多。

## 四、改完代码后该跑什么（速查）

| 你改了什么 | 至少要跑 |
| --- | --- |
| 只改了文档 | `bash scripts/verify-gate.sh`（索引项会兜住计数漂移） |
| 新增 / 删除 / 改名 `.cs` | `verify-gate.sh` + **同步更新 `100-文件与类索引.md` 与 `README.md` 的计数** + 记得带 `.meta` |
| 改了 Runtime 代码 | 上述 + Unity 里跑 EditMode 全套 |
| 改了任何公开 API | 上述 + 跑 `PublicApiSnapshotTests`（会 diff 出接口变化，确认是有意的） |
| 要发版 | `bash scripts/verify-tag-version.sh`；打 tag 后再跑一次确认 |

## 五、踩坑记录

### 5.1 `verify-gate.sh` 第一版把类型数报成 387

纯 `grep` 不剥离注释 → XML 文档注释里的 `<c>class Foo</c>` 被计入。
修法见「为什么第 1~3 项要剥离注释才能数类型」。

### 5.2 Git Bash 的 `/e/...` 路径喂给 Python / Unity 会失败

Git Bash 靠 MSYS 做路径转换，但 `python.exe` 与 `Unity.exe` 都是**原生 Win32 程序**，
收不到这个转换。表现为：

- `json.load(open('/e/.../package.json'))` → `FileNotFoundError`（而 `cat` 同一个文件正常）
- `manifest.json` 里写 `"file:/e/Work-SD/..."` → Unity 报找不到包

修法：喂给 Python 的路径先 `cd` 进去再用相对路径；
写给 Unity 的路径在 MINGW/MSYS 下用 `pwd -W` 转成 `E:/...`。

### 5.3 反向验证比正向验证重要

闸门脚本第一版"全绿"，但那是**因为它什么都没检查**——
`orphan_meta` 的循环体因为 `bad` 是在 `while` 里执行的，
第一次注入测试时用的是"移走 `.meta`"（变成"缺 `.meta`"）而不是
"造孤儿 `.meta`"（有 meta 无 cs），所以孤儿分支从未被真正触发。

**教训：每个检查项都要先注入一个错误、确认退出码非 0，再恢复。**
只跑"正着过"证明不了检查是活的。当前四项检查均已双向验证。
