# 52 · 存档存储（Save）

## 它是什么

`HYC.Framework.Save.SaveManager`：把一个**可序列化对象按类型写盘、按类型读回**。就这一件事。

它和配置（Config）是对称的两半：

| | 配置 | 存档 |
| --- | --- | --- |
| 数据形态 | blittable `struct` | 普通 `class` / POCO |
| 可变性 | 不可变 Blob，生成期烘焙 | 可变，运行期读写 |
| 谁写 | 编辑器管线 | 玩家 / 运行期逻辑 |
| 存储位置 | `StreamingAssets/ConfigBlob` | `Application.persistentDataPath/Save` |

---

## 架构

```
Save<T>(data) / Get<T>()
        │
        ▼
ISaveSerializer          ← 可换：Newtonsoft（默认）/ JsonUtility
        │
        ▼
SaveEnvelope             ← { formatVersion, typeKey, timestamp, payload }
        │
        ▼
原子写 .tmp → 换名        ← 写一半崩不会留下半截文件
        │
        ▼
persistentDataPath/Save/<类型全名>.dat
```

**它不关心这些事**，因为它们是表现层 / 玩法层概念，不是存储概念：

- 有没有"存档槽"、有几个档
- 列表界面长什么样、每档显示什么摘要
- 什么时候该自动保存

想要三个存档，就自己存列表——`Save(new List<PlayerProgress> { p1, p2, p3 })`；
或者自己定义不同的类型。框架不知道"槽"是什么。

---

## 关键类

| 类型 | 位置 | 说明 |
| --- | --- | --- |
| `SaveManager` | `Runtime/Save/SaveManager.cs` | 静态入口，namespace `HYC.Framework.Save` |
| `SaveOptions` | 同上 | `RootPath`（默认 `persistentDataPath/Save`，可覆盖便于测试）、`Serializer` |
| `SaveEnvelope` | 同上 | 文件外壳，带 `formatVersion` / `typeKey` / `timestamp` / `payload` |
| `ISaveSerializer` | `Runtime/Save/SaveSerializer.cs` | 序列化抽象 |
| `NewtonsoftSaveSerializer` | 同上 | 默认实现，支持 Dictionary / 多态 / 顶层 `List<T>` |
| `JsonUtilitySaveSerializer` | 同上 | 零依赖备选，有三条硬限制（见下） |

命名空间：`HYC.Framework.Save`。依赖 `com.unity.nuget.newtonsoft-json@3.2.1`（已写进 `package.json`）。

---

## 用法

```csharp
using HYC.Framework.Save;

[Serializable]
public class PlayerProgress
{
    public int level;
    public int coins;
    public Dictionary<string, int> levelStars;   // Dictionary 只有 Newtonsoft 支持
}

// 存
SaveManager.Save(new PlayerProgress { level = 3, coins = 120 });

// 取：不存在时返回 null
var p = SaveManager.Get<PlayerProgress>();

// 取：不存在时新建一个（不自动写盘，什么时候落盘仍由调用方决定）
var p2 = SaveManager.GetOrCreate<PlayerProgress>();

// 判断 / 删除
bool has = SaveManager.Has<PlayerProgress>();
SaveManager.Delete<PlayerProgress>();
SaveManager.DeleteAll();
```

换序列化器或改存储根路径：

```csharp
SaveManager.Init(new SaveOptions
{
    Serializer = new JsonUtilitySaveSerializer(),
    RootPath   = Path.Combine(Application.temporaryCachePath, "SaveTest")
});
```

开发期想直接打开存档文件看内容：

```csharp
SaveManager.Init(new SaveOptions { Serializer = new NewtonsoftSaveSerializer(prettyPrint: true) });
```

## 坑

1. **`Get<T>()` 每次都读盘，没有内存缓存。** 别放在每帧循环里，取一次存成局部变量。
   这是设计取舍：不缓存就没有生命周期、没有失效问题、没有 `Clear()`。

2. **坏档会被改名成 `.corrupt_<时间戳>`，不会被覆盖。** 存档解析失败时框架先备份再返回 `default`。
   静默覆盖等于玩家进度凭空消失且无从追查——这是存储层的本分，不是可选项。

3. **类型就是键，所以给类改名或换命名空间 = 老存档读不到。**
   文件名的键是 `typeof(T).FullName`。真要改名时写一次性迁移代码，框架不做这个。

4. **同一个类型只能存一份。** 想存多份就存 `List<T>`，这也正是默认选 Newtonsoft 的原因——
   `JsonUtility` **顶层不能是 `List<T>`**。

5. **`JsonUtilitySaveSerializer` 的三条硬限制**：不支持 `Dictionary`、不支持多态
   （基类引用存子类会丢字段）、顶层不能直接是 `List<T>`。用之前先确认数据不触碰这三条，
   否则会静默存出 `{}`。

6. **`GetOrCreate<T>()` 不会写盘。** 它只是在内存里给你一个新对象，落盘时机由调用方决定。

7. **不是线程安全的。** 在主线程调用。文件写入本身不是原子的跨进程操作，多进程/多实例同时写同一个目录会打架。

8. **iOS 上 `persistentDataPath` 默认会被 iCloud 备份**，大存档可能触发审核问题；
   需要 `UnityEngine.iOS.Device.SetNoBackupFlag(path)` 时由使用方自己处理，框架不做。

9. **自动保存时机不由框架决定。** 移动端切后台被杀会丢档，使用方需要自己在
   `OnApplicationPause` / `OnApplicationFocus(false)` 里调 `Save`。
