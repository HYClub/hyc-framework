│  配置树       │                                              │
│  （TreeView） │   ┌ 分组1 ┐┌ 分组2 ┐┌ 分组3 ┐                 │
│              │   │ 字段…  ││ 字段…  ││ 字段…  │                 │
│              │   └──────┘└──────┘└──────┘                 │

│              │                            [保存] [导出]      │

- 左树宽默认 280，中间分隔条可拖动（最小 128）。
- `Ctrl+S` = 保存全部。
- 工具栏出现 `保存*`（带星号）表示有资产未保存。
- 右下角圆点是 **ID 构造器状态**：绿=已连接、黄=连接中、红=不可用（悬停看 IP/端口）。

### 操作

| 操作 | 说明 |
| --- | --- |
| 左键选树节点 | 右侧切换编辑器（每个资产一个编辑器实例） |
| 搜索 | 过滤树；`↑/↓` 在结果间跳转 |
| **新建配置** | 打开 `ConfigCreateWindow`，落在该类型的**类型文件夹**（窗口内「创建位置」实时显示落点） |
| **创建模板** | 直接建一个 `ConfigTemplate` 资产并选中，落在 `配置模板` 文件夹 |
| **模板▾** | 列出所有模板，点击跳转选中；底部还有"打开配置根目录" |
| 右键（树） | 创建配置 / 创建目录 / 重命名 / 复制 / 删除 / 拖拽移动；文件夹右键按内容动态列出导出项（见下） |
| **设置** | 打开 `ConfigDataSettingsWindow` |

### 类型文件夹（自动归置）

新建的配置 / 枚举 / 模板**一律落到 `配置根目录/<类型名>/`**，文件夹不存在则自动创建：

| 资产 | 文件夹 | 名字来源 |
| --- | --- | --- |
| 配置（`ConfigBase` 派生） | `根目录/<类型短名>/` | `[CfgAsset("角色/角色配置")]` 的**最后一段**，与数据树 `[角色]` 前缀同源 |
| 枚举定义 | `根目录/枚举/` | 固定名 `ConfigAssetLayout.EnumFolderName` |
| 配置模板 | `根目录/配置模板/` | 固定名 `ConfigAssetLayout.TemplateFolderName` |

规则（`Editor/DataEditor/ConfigAssetLayout.cs` + `ConfigAssetMoveGuard`）：

- **创建时自动归置**：所有创建入口（`ConfigAssetFactory` / 配置创建器 / 数据树 / 工具栏）都走这里；显式传 `folder` 的旧式调用仍然尊重。
- **用户结构不干预**：类型文件夹内建子文件夹、把资产手动拖进子文件夹、重命名，一律放行。
- **移出给不建议提示**：已归置资产被移到类型文件夹**外面**时，`AssetModificationProcessor.OnWillMoveAsset`（`AssetMoveResult.FailedMove`）拦截并弹「不建议移动」对话框——含「仍然移动」覆盖选项与「取消」接受拦截（**Project 窗口拖拽与数据树拖拽都会弹窗**，不再静默失效；数据树内由 `MoveAsset` 触发守护、用 `GuardPrompted` 标记避免重复弹窗）。
- **存量资产不受限**：一直在根目录直下或用户自建目录里的历史资产，移动是自由的。

### 文件夹右键的动态导出菜单

GenericMenu 的菜单路径按 `/` 拆子菜单（Unity 官方行为），所以「导出」是**真子菜单**。右键文件夹时按内容实时统计：

```
导出 ▸                          ← 真子菜单（有可导出配置时才出现）
  角色配置（12 个）              ← 每种配置类型一项，N = 该文件夹内资产数
  装备配置（5 个）
  ──────────                    ← AddSeparator("导出/") 子菜单内分隔线
  导出全部                      ← = 保存并导出文件夹内所有配置
保存导出所有枚举（3 个）          ← 顶级动态项（有枚举才出现）
保存并生成所有模板代码（4 个）    ← 顶级动态项（有模板才出现；模板是生成代码，不进导出子菜单）
```

- 每项 N 与 `ConfigExportService.ExportFolder` **同一过滤规则**（排除 `ConfigTemplate`、排除命名空间不在 `ConfigDataSettings.Namespace` 内的资产）实时统计。
- 按类型导出走 `ExportAll` 整类型导出——Blob/JSON 产物一类型一个文件，**不能**逐资产导（会互相覆盖成只剩最后一个）。
- 三类内容皆无时列一条禁用提示，不再出现对模板文件夹不适用的「保存并导出内部所有」。

## 二、项目设置（ConfigDataSettings）

全部存 **HYCSettings 资产**（`Assets/HYC/HYCSettings.asset`，随工程进版本控制，多人协作共享同一份设定）：

| 设置 | 默认值 | 说明 |
| --- | --- | --- |
| `RootFolder` | `Assets/ConfigData` | 配置根目录，**必须在 Assets 内**（选错会弹窗拒绝） |
| `OutputDir` | `Assets/HYC/Generated/Config` | 生成的配置类输出目录（生成代码统一收口在 `Assets/HYC/Generated/` 下，见 `GeneratedPaths`） |
| `Namespace` | 派生：`{root}.config` | 生成类命名空间；root 在 HYC Settings → CodeGen 配（留空=项目公司名→`Default`），BT 自定义节点另落 `{root}.BT.Nodes` |
| `EditorDir` | `Assets/HYC/Generated/Config/Editor` | 生成的 `XxxConfigEditor` 输出目录 |
| `ClientExportDir` | `Exports/Client` | 客户端导出目录 |
| `ServerExportDir` | `Exports/Server` | 服务端导出目录 |
| `SideTypeIsStruct` | `false` | true = 字段平铺成 struct；false = 保留继承链的 class |
| `ClientFormat` | 0 = JSON | 1 = Blob |
| `ServerFormat` | 0 = JSON | — |
| `BlobOutputDir` | `Assets/StreamingAssets/ConfigBlob` | Blob 产物位置（在 StreamingAssets 内才能打包带走） |
| `BlobLoadPath` | `ConfigBlob` | 运行期相对 StreamingAssets 的加载子路径 |
| `IdProviderType` | 0 = 本地 | 1 = 局域网 ID 服务器 |
| `IdServerIp` / `IdServerPort` | `127.0.0.1` / `8920` | 局域网模式地址 |

`EnsureRootFolder()` 会自动逐级创建根目录（含缺失的父级）。

## 三、ID 构造器

每个配置资产都有一组 `{ID (long), GUID (string)}`，由 `ConfigIdService` 统一发放。

```csharp
public struct ConfigId { public long id; public string guid; }
```

| 提供者 | 说明 |
| --- | --- |
| `LocalConfigIdProvider` | 本机生成；`LoadExistingIds()` 扫描已有资产避免撞号 |
| `NetworkConfigIdProvider` | 连局域网 ID 服务器发号，保证多人协作唯一 |

### 生成规则（`ConfigId.Generate()`）

```csharp
var g = Guid.NewGuid();
var id = BitConverter.ToInt64(g.ToByteArray(), 0);   // 取 Guid 前 8 字节
if (id != 0) return new ConfigId { id, guid = g.ToString() };
// 4 次都是 0（极小概率）→ 退化成 DateTime.UtcNow.Ticks
```

⚠️ **`id == 0` 被视为"未分配"**——`FindIssues` 会把它报成问题。

### 读写方式

`ConfigIdService` 用**反射**访问资产上名为 `ID` 和 `GUID` 的字段（`Public | Instance | FlattenHierarchy`）。生成的配置类必须有这两个 `public` 字段，否则 `TryReadId` 返回 false，该资产不参与查重。

### 程序化创建（AI / 脚本唯一入口）

**任何代码或 AI 创建配置资产，必须走 `ConfigAssetFactory`，禁止直接 `ScriptableObject.CreateInstance` + 手填 `ID`/`GUID`。**
手填的 ID 绕过了发号服，本地模式下可能不撞车而溜进导出，引发跨工程 / 跨机 ID 冲突。

```csharp
// 泛型
var a = ConfigAssetFactory.Create<MyConfig>("Boss01");
// 非泛型（AI 不一定有编译期类型）
var b = ConfigAssetFactory.Create(typeof(MyConfig), "Boss02");
// 批量
var list = ConfigAssetFactory.CreateMany(typeof(MyConfig), "Mob", 10);
// 之后填字段
EditorUtility.SetDirty(a);
AssetDatabase.SaveAssets();
```

`ConfigAssetFactory` 内部与「配置创建器」UI 同源：确保根目录 → `[CfgAsset(Unique=true)]` 去重 →
`ScriptableObject.CreateInstance` → `AssetDatabase.CreateAsset` → `ConfigIdService.RequestIdSync()` 派发 `{ID,GUID}` → 落盘。
任一环节失败（发号服不可用 / 唯一类型已存在 / 文件冲突 / 派发失败）会整体回滚已创建资产并抛异常。

`CreateMany` 的编号位宽按数量自动算（`_001 … _NNN`）；唯一类型不支持批量。

> 一个配置类型「可多个（`Multiple`）」还是「全工程唯一（`Single`）」称为**实例基数**，代码层就是 `[CfgAsset(Unique=true)]` 这一个布尔。`Single` 的完整强制点与词汇定义见 [10-配置管线-总览](./10-配置管线-总览.md) 的「配置实例基数」一节。

> ⚠️ **禁止手填 `ID`/`GUID`**：必须由 `ConfigIdService`（发号服）经 `ConfigAssetFactory` 或「配置创建器」UI 派发。`ConfigBase` 的 `ID`/`GUID` 字段已带 `[Header]` 注释警示。手填的 ID 绕过发号服，可能在本地不撞车却与团队冲突；导出前查重会拦 `id==0`/重复项。详见 `AGENTS.md`。

## 四、导出前查重

`ConfigExportService.ExportSingle` / `ExportFolder` / `CleanAndExportAll` 都会先调
`ConfigIdService.EnsureUniqueBeforeExport(assets, context)`：

```
FindIssues(assets)
  ├─ id == 0 或 guid 为空  →  "未分配 ID/GUID（请重新派发）"
  ├─ id 与之前某资产相同    →  "ID {id} 与 \"{名字}\" 重复"
  └─ guid 与之前某资产相同  →  "GUID 与 \"{名字}\" 重复"
  ↓  有问题
三选一弹窗：
  [重新派发并继续]  → Reissue() 逐个重新发号 → SaveAssets → 继续导出
  [取消导出]       → return false
  [仍然导出]       → return true（你自己负责）
```

弹窗最多列出前 8 条，超出显示 `... 共 N 处问题`。

⚠️ **重新派发会改掉资产的 ID**——引用了旧 ID 的地方要一起改。

⚠️ **`CleanAndExportAll` 的查重排在清理旧 blob 之前**：用户取消查重弹窗时不能留下
「旧产物已删、新产物未写」的空窗。

⚠️ **批模式（CI）下 `DisplayDialogComplex` 不渲染**：`EnsureUniqueBeforeExport` 检测到
`Application.isBatchMode` 时改为逐条 `LogError` 并中止导出——静默取消只会让 CI 看到
「导出失败」而看不到原因。

## 五、导出

```csharp
ConfigExportService.ExportSingle(asset, client: true, server: true);
ConfigExportService.ExportFolder(folder, true, true);
ConfigExportService.ExportAll(typeof(FashionConfig), true, true);
```

机制是**定位并实例化生成的导出类**（不走静态反射）：

- 先 `FindExportType(configType)` 找 `{Namespace}.Editor.{TypeName}Export`——注册表优先
  （生成的 `XxxExport` 静态构造里 `ConfigExportService.Register` 填入），未注册才做一次性
  全 AppDomain 扫描（按 `FullName` 全名匹配，只比短名会命中其它工程的同名类）。
- 再 `Activator.CreateInstance(exportType, configType)` 实例化，调
  `ConfigBaseExport.ExportCore(asset, client, server)` / `ExportAllCore(client, server)`。
- 为什么不走静态反射：继承链上同名静态方法会让 `GetMethod` 产生歧义
  （`AmbiguousMatchException`）；实例化后按继承链自动命中最派生 override。
- 旧版生成的 `XxxExport` 是 `static class`（IL 层面 abstract+sealed、不可实例化），
  `IsAbstract` 会识别并提示「请执行 Regenerate All Config Code 重新生成」。

### 检查与中止语义

导出前逐资产走 `CheckData` 链（`ConfigBaseExport.ExportCore` / `ExportAllCore`）：

- **只有 Error 级中止导出**；Info/Warning 照常开错误窗口展示，但不拦截数据产出
  （与 SD 导出前置检查语义一致）。判定入口 `ConfigBaseExport.HasBlockingError`。
- **批模式（CI）下错误窗口不渲染**：`BuildErrorWindow.Report` 检测 `Application.isBatchMode`
  后改走 Console（Error→`LogError` / Warning→`LogWarning` / Info→`Log`），保证 CI 能捕获原因。
- **批量路径先全量检查、再统一写盘**（三种产物形态一致）：第 N 行检查失败时不会留下
  前 N-1 行的部分产物。纯检查（不落盘）的入口见 [七·2](#2-数据检查生成的-xxxconfigcheck)。
- **零检查项默认静默**：没有任何提示／警告／错误时导出**不弹任何窗**（导出频繁，不打扰）。
  需要每次都拿到反馈时，在 **HYC Settings →「配置」→「导出后总是汇报检查结果」** 勾选——
  开启后导出结束会弹一句「检查完成：未发现问题」。**一次用户操作最多一个框**：
  `ConfigExportService` 的三个顶层入口（单实例 `ExportSingle` / 文件夹 `ExportFolder` /
  全量 `CleanAndExportAll`）用 `BuildErrorWindow.BeginExportOperation` / `EndExportOperation` 闩锁包住，
  逐类型、逐资产的检查不会重复弹；导出本身失败（如目录无效、根本没进检查）也不弹，避免谎报通过。
  该开关只管交互模式，**批模式（CI）不受影响**。

### 三条继承链（框架基类 ↔ 生成产物）

| 链 | 框架基类（随包预编译） | 生成产物 |
| --- | --- | --- |
| 主类 | `ConfigBase`（ID/GUID） | `XxxConfig : ConfigBase` |
| 侧类型 | `ConfigBaseClient` / `ConfigBaseServer`（ID/GUID） | `XxxClient : ConfigBaseClient` / `XxxServer : ConfigBaseServer`（只声明自身字段） |
| 导出 | `ConfigBaseExport`（导出管线） | `XxxExport : [基类配置的导出类 :] ConfigBaseExport`（只填钩子） |

- 侧类型 `From` 平铺赋值全部导出字段：继承字段经派生引用可直接访问，无需调用基类 `From`；
  ID/GUID 随继承自动进入 JSON 导出产物。

### 生成文件禁改头（`GeneratedCodeFile`）

所有生成产物（主类 / 侧类型 / Check / Editor / BlobBuilder / BlobSystem / Export / 枚举）顶部都套四行壳：

```csharp
// <auto-generated>
// 此文件由 HYC Framework 代码生成器自动生成，请勿手工修改——任何改动都会在下次生成时被覆盖。
// This file is auto-generated by the HYC Framework code generator. DO NOT EDIT.
// 如需变更，请修改生成源（配置模板 / 数据资产）后重新生成。
// </auto-generated>
```

- 写盘统一走 `Editor/GeneratedCodeFile.cs`（包内最底层）：套壳 + 内容未变不重写（免无谓重编译）。
- 壳内**不含时间戳 / 路径**等易变信息——否则每次生成内容都不同，「未变不重写」失效。
- 要改字段请改**配置模板**再重新生成（`HYC Framework/Config/Regenerate All Config Code`），别手改生成物。
- 导出钩子：`CheckData`（基类链各自查自身字段，`base.CheckData` 向上链，不重复报错）/
  `CreateClientDto` / `CreateServerDto`（一次 `From` 整链投影）/ `ClientIsBlob` /
  `WriteClientBlob`（Blob 分支天生类型相关，留在派生类）。
- Blob 结构体 `CfgXxx` 是 struct（blittable、不能继承），保持平铺内联 ID/GUID——正确形态。
- 多级链示例：`EliteConfig : MonsterConfig` → `EliteConfigExport : MonsterConfigExport :
  ConfigBaseExport`，A 层导出逻辑放 `MonsterConfigExport`，C 层只补自己的字段。
- 约定：框架级基类模板（`generateCode=false`）必须在框架内提供同名侧类型/导出基类，
  否则生成代码 CS0246（报错自明）。

`ExportFolder` 的筛选：
- `t:ScriptableObject`，在指定目录下；
- **排除 `ConfigTemplate`**；
- 要求 `type.Namespace.StartsWith(ConfigDataSettings.Namespace)`；
- 按类型去重（`HashSet<Type> done`），**一种类型只导出一次**（走 `ExportAll`）。

⚠️ 没生成代码 → `Debug.LogWarning($"未找到 {TypeName} 的导出类（请先生成代码）")`，返回 false。

## 六、右侧编辑器

选择逻辑（`ConfigDataContainer.GetEditor`）：

1. 用 `TypeCache.GetTypesWithAttribute<CfgEditorAttribute>()` 建立 `资产类型 → 编辑器类型` 映射（**只缓存一次**）；
2. 没匹配的 → 用 `NormalConfigEditor`（通用反射绘制）。

自定义编辑器：继承 `BaseConfigEditor<T>` 并标 `[CfgEditor(typeof(T))]`。

### BaseConfigEditor&lt;T&gt; 提供

- **分组页签**：从 `[Group]` 特性（`GUIType.Groups`）读分组；`Groups.Count > 1` 时顶部显示 toolbar 开关，**可同时开多组并排**（宽度均分 `viewW / count`）。
- 每组独立滚动；字段由 `GUIDrawer.DrawField(mTarget, field)` 绘制。
- **字段条件显示**：生成类字段带 `[CfgVisibleWhen]`（模板「关联参数」生成）时，`DrawField` 先求值——目标字段满足全部条件（AND）才绘制，不满足整行跳过；目标字段丢失 / 类型不符视为满足（保持显示）。详见 [11 篇·四·B](./11-字段类型与导出设置.md)。
- **底部预览条**：默认高 80，可上下拖动（钳制在 30 ~ 页高）。
- **右下角两个按钮**：
  - `保存` → `ApplyModifiedProperties` + `SetDirty` + `SaveAssetIfDirty`
  - `导出` → `ApplyModifiedProperties` + `ConfigExportService.ExportSingle(obj, true, true)`，成功弹 `已导出` 通知

⚠️ 页签开关状态存在 `static Dictionary<GUIType, bool[]>`，**跨资产、跨窗口共享**——开了一组，切到同类型的其它配置也保持开着。

## 七、校验

### 1. 结构校验（`HYC Framework/Config/Validate Config`）

`ConfigValidator.ValidateAll()` 遍历 `ConfigRegistry.AllTypes`（即所有已注册的行类型），逐个 `ValidateStruct`：

| 检查 | 级别 | 文案 |
| --- | --- | --- |
| 缺少 `[BlobGenerate]` | Error | `struct lacks [BlobGenerate] attribute` |
| 字段是 class / interface | Error | `field is a class/reference; cfg structs must be blittable` |

**白名单**（允许出现在配置结构里）：
`string`、`Vector2`、`Vector3`、`Vector4`。

⚠️ 这个白名单**偏宽松**——`string` 在 Blob 里其实不合法（必须 `BlobString`/`FixedString`），这里放行了。**真正的 blittable 检查发生在烘焙时**，见 [99 篇](./99-Blob-与数据约定.md)。

⚠️ `ValidateAll` 只看 `ConfigRegistry.AllTypes`——**必须先 `Register` 过才校验得到**；编辑器里没跑过引导流程的话列表是空的，会直接输出 `No issues found.`

结果只打到 Console（Error 用 `LogError`，其它 `LogWarning`），`Issues` 静态列表保留最后一次结果。

### 2. 数据检查（生成的 XxxConfigCheck）

数据层面的检查结果用 `CheckError` 表示：

```csharp
public class CheckError {
    public Object Asset;         // 出错资产
    public string Group;         // 分组（用于 TreeView 归类）
    public CheckErrorLevel Level;// Info / Warning / Error
    public string Message;
    public string FieldName;     // 出错字段名（可空，用于定位高亮）

由 **生成的 `XxxConfigCheck`** 收集（规则来自模板字段上的 `notEmptyCheck` / `notZeroCheck` / `rangeCheck`，见 [11 篇](./11-字段类型与导出设置.md)），交给 `BuildErrorWindow.OpenWindow(errors)` 展示。每条错误的 `Asset` 携带出错资产（生成码传 `data`，非 null）——单击导航据此定位；「数据为空」分支 `data` 本身为 null，无资产可定位。

### BuildErrorWindow

```
[🔍 搜索]                    [N info][N warn][N error]   ← 三个可点的过滤开关
├── 分组名                     ← CheckError.Group，空则显示 "???"
│   ├── ⓘ 消息
│   ├── ⚠ 消息
│   └── ⓧ 消息

- 按 `Group` 分组，图标取 `console.infoicon.sml` / `warnicon.sml` / `erroricon.sml`（计数为 0 时用 `.inactive.sml` 灰版）。
- **`BuildErrorWindow.Report(errors, context)` 是统一报告入口**：交互模式开窗；**批模式（CI）走 Console**——`EditorWindow` 在 batchmode 下不渲染，开窗无意义，错误必须落日志才能被 CI 捕获。零检查项直接返回（不打扰）；导出路径与全量检查都走它。
- **单击错误项 → 自动打开数据编辑器并定位**：`ConfigDataWindow.FocusField(asset, fieldName)` → 树里选中该资产 + `ConfigDataContainer.RequestHighlight(asset, fieldName)`。`Asset` 为 null 的条目（类型级结构问题、未生成导出类的类型）点击无反应。
- 高亮持续 **1.5 秒**（`IsHighlighting` 判断 `timeSinceStartup - start < 1.5`），闪烁提示。

### 全量数据检查（`HYC Framework/Config/Check All Config Data`）

`ConfigCheckService.Run()`（菜单 pri 6；数据编辑器工具栏「检查」按钮）：扫描配置根目录下全部配置资产，按类型实例化生成的导出类走 `ConfigBaseExport.Check` 链收集全部错误——**不落盘任何产物，纯检查**。适合导出前预检与 CI。

- 除模板字段规则外含 **ID/GUID 查重**（只读报告；重新派发对话框是导出前交互，不在这里弹）。
- ProgressBar 逐类型进度 → 交互模式 Dialog 概览（错误/警告/提示计数）→ 开错误窗口看明细（**无错误也开窗**，让 Info/Warning 有地方看）；批模式走 Console。
- 语义与 SD 一致：只有 Error 级算失败，Info/Warning 仅展示。

### 3. 模板导出可行性校验（生成前拦截）

模板（[11 篇·四·C](./11-字段类型与导出设置.md)）在「生成代码」前会静态判定每个字段的导出组合是否真的能导出——**不靠捏样例试跑**，直接复用代码生成器的类型解析：

- **客户端（Blob）不可导**：资源/对象/Gradient/曲线/Rect 系/层遮罩/配置引用整对象/Decimal/Char 等用「直接导出」会落到 `default: int` 兜底，生成编译报错的 Blob。
- **服务器（JSON）不可导**：「直接导出」且类型是 Unity 对象或不可 JSON 序列化的类型（资源/对象引用族 + Color / Color32 / Gradient / AnimationCurve）。Rect / Bounds 等结构 Newtonsoft 能序列化，只拦客户端那一侧。这些类型在服务器导出下拉里已强制**只给「不导出」一项**（默认即不导出），从源头杜绝服务器 JSON 自引用崩溃；运行期导出亦加容错（自引用 / 无法序列化成员自动跳过并告警）。

两条都会让「生成代码」按钮经 `ConfigTemplateCodeGen.Validate` 直接返回失败（**硬拦截**，错误信息即红字内容）。模板编辑器里则通过顶部红字 `tplErrors` + 字段页不可导侧 Popup **红底** 提前暴露，并给出改「资源名 / 路径 / AA地址 / 转字符串」的建议。「保存模板」不受影响（草稿可存，生成前必修）。

`CollectExportFeasibilityErrors` / `GetExportFeasibility` 为唯一判定入口；类型归类统一在 `Runtime/ConfigFieldTypes.cs`（增删资源类型改那里），另需同步 `UnityTypeName` 的类型映射。

## 八、注意事项 / 坑

1. **改了「生成代码命名空间 root」（HYC Settings → CodeGen）/ `OutputDir` 后必须跑一次 `HYC Framework/Config/Regenerate All Config Code`**：该菜单现在覆盖**全部**生成路径——模板（主类 / Client / Server / Check / Editor / Export / Blob 三件套）+ 枚举，并在末尾清理旧命名空间残留生成文件（只删带「自动生成」头、命名空间不在当前 root 派生范围的 `.cs`，手写文件不碰）。不重生成则 `FindExportType` 按新命名空间找不到导出类（有全程序集兜底，但可能匹配到同名旧类）；只跑旧版局部生成则会留下旧命名空间孤儿文件，批量 CS0246。
2. **`ExportFolder` 一种类型只导出一次**——它调的是 `ExportAll`（整表），不是逐资产。想单独导一个用 `ExportSingle`。
3. **右键"复制"资产会复制 ID**——现已由 `DuplicateIdGuard` 在复制后**自动重派发**（配置走 `ConfigIdService`、天赋树走 `treeId`），应用层无需记忆「别复制」；如需手动兜底，用 `HYC Framework/Config/Reissue Duplicate IDs` / `HYC Framework/Talent/Reissue Duplicate Tree IDs`（复用导出前查重同款逻辑）。
4. **ID 状态点只有局域网模式有意义**：`ProbeAsync` 里 `if (p is LocalConfigIdProvider) return;`，本地模式永远是红灯但功能正常。探针每 **5 秒**一次，且仅在非播放状态跑。
5. **`NextId()` 是进程内种子 + 计数器**（`DateTime.UtcNow.Ticks + counter`），**重启编辑器会重置**，只适合临时用法；正式发号走 `ConfigId.Generate()` / `RequestIdSync()`。
6. **保存按钮做了两件事**：`SetDirty` + `SaveAssetIfDirty`；而工具栏的"保存（全部）"是遍历 `CollectConfigAssets` + `FindAssets("t:ConfigTemplate t:ConfigEnumDefinition")` 统一 `AssetDatabase.SaveAssets()`。模板/枚举不在 `CollectConfigAssets` 的命名空间过滤内，所以单独扫了一遍。
7. **`ConfigDataContainer` 的编辑器映射只构建一次**（`mEditorMap` 静态），新写的 `[CfgEditor]` 类要**重开编辑器域**（改脚本触发编译）才生效。
8. **`BuildErrorWindow` 的 `ShowLevel` 是静态数组**，过滤状态跨窗口保留。
9. **`readOnly` 字段在数据编辑器里置灰**：模板字段勾选「只读」后，生成类带 `[ReadOnly]`，该字段输入被禁用。这只影响手改，**不影响自动发号与导出**；详见 [11 篇](./11-字段类型与导出设置.md)。改了模板的只读后要让效果生效，游戏工程需重新生成配置代码。

## 九、模板 → Excel 导出（Project 窗口右键）

**入口**：Project 窗口右键 `ConfigTemplate` 资产 → `Export Excel`（`CONTEXT/ConfigTemplate/Export Excel`，`Editor/DataEditor/ConfigTemplateExcelExporter.cs`）。

**行为**：弹面板选落点（默认与模板资产同目录、按 `className` 命名）→ 生成 `.xlsx`，**有数据逐行填入，无数据只出 3 行表头**（空模板）。框架级模板（`generateCode = false`，如 ConfigBase）拒绝导出并说明原因。

### 表结构（3 行表头，与策划填表格式一致）

| 行 | 内容 | 取值规则 |
| --- | --- | --- |
| 第 1 行 | 中文显示名 | 字段 `description`，空则回落字段名 |
| 第 2 行 | 英文字段名 | 字段 `name`；首列固定 `ID`、末列固定 `GUID` |
| 第 3 行 | 类型 | 与生成代码同款类型名（`int` / `Vector3` / `Sprite` / 枚举类名 / 引用短名 / `BehaviourTree` / `LocalizedKey` / `Addressable` / `AudioEvent`），列表加 `[]` 后缀 |
| 第 4 行起 | 数据 | 配置根目录下**精确匹配** `className` 的配置资产，按 `ID` 升序 |

### 单元格写入规则

- **数值族**（int / long / float / double / short / byte / uint / decimal / `BehaviourTree` 的 treeId）与 `ID` 写**数值单元格**；其余一律文本。
- **列表**用 `|` 连接各元素（导入侧同款分隔符）。
- **配置引用**（`Reference`）写目标资产的 `ID`——与运行期 `ConfigRowRef` 的对账键一致。
- **资源引用**（Sprite / GameObject / AudioClip 等）写**资产名**。
- **结构体**（Vector / Color / Rect / Bounds / Quaternion…）逐分量、逗号 + 空格分隔，浮点用 `"R"` 不变量文化格式（避免逗号小数点与分隔符混淆）。
- **Gradient / AnimationCurve 无法在 Excel 中表达**，写空（已知限制，往返会丢，需回数据编辑器补）。
- 反射读取个别字段失败不中断整表：该格留空 + Console 点名告警。

### 设计取舍

- **只含本模板自己的字段**：基类模板的字段由基类自己的表负责，不并进派生表（与「一个模板一张表」的归属一致）。
- **派生类型的资产不归本表**：`t:className` 过滤后仍精确比对 `GetType().Name`，派生资产归派生模板。
- **ID/GUID 两列是框架列**：`ID` 为业务主键（对账用），`GUID` 仅备份，不参与对账。
- **落点在 Assets 内会自动 `AssetDatabase.Refresh()`**；表名按 Excel 规则清洗（禁 `[]:*?/\`，最长 31 字符）。
- 新增 `ConfigFieldType` 成员时，本文件 `TypeDisplayName` / `ElementText` 两个 switch 必须同步（AGENTS.md「新增 ConfigFieldType 需同步」铁律）。

## 十、Excel → 配置导入窗口

**入口**：`HYC Framework/Config/Import Excel...`（pri 7，`Editor/DataEditor/ConfigExcelImportWindow.cs`）。

**动线**：选/拖入 `.xlsx`（窗口支持拖拽）→ 多 sheet 时切 sheet → 定模式 + 命名 + 字段草拟 → 校验通过后执行。
表头三种格式自动识别（与导出写出格式互为逆操作，判定逻辑在 `ConfigExcelReader`）：

| 格式 | 判定 | 表头取法 |
| --- | --- | --- |
| `typed3` | 第 2 行全是标识符 **且** 第 3 行全是已知类型串 | 中文=第 1 行、英文=第 2 行、类型=第 3 行 |
| `en2` | 第 1 行全是标识符 | 英文=第 1 行（中文回落同名）、类型按首个数据值推断 |
| `cn1` | 兜底 | 中文=第 1 行（兼作英文名，经标识符清洗）、类型推断 |

### 框架列约定

- 英文字段名为 `ID`（大小写不敏感）的列识别为**主键列**（草拟表显示 `K`），不生成字段，模式③按它对账。
- `GUID` 列识别为框架列（显示 `G`），导入时忽略。

### 字段草拟表

每列一行：中文名 / 英文字段名 / 类型（46 项下拉，同模板编辑器集合）/ 列表开关 / 主键开关。
`Enum` / `Reference` 类型选中后出现**类名输入框**（枚举定义类名 / 配置类短名），
即时校验存在性（不存在标红 `enum?` / `cfg?`）。表头第 3 行认不出的类型串标 `!` 留待手改——
**不静默按 String 吞掉**。无类型行时按首个非空数据值推断（Bool / Int|Long / Float / String）。

### 模式（执行策略拆独立文件，本窗口只做解析 + 预览 + 校验）

| 模式 | 语义 | 实现状态 |
| --- | --- | --- |
| New Template + Configs | 新建模板资产 + 每个数据行一个配置资产 | ✅ `ConfigExcelImporter.ExecuteNewTemplate` |
| Update Template + Configs | 按字段名合并进既有模板（增/删/改类型），再按主键对账配置行 | ✅ `ConfigExcelImporter.ExecuteUpdateTemplate` |
| Configs Only (by ID) | 不动模板，按主键 ID 对账配置行（新增/更新/跳过/孤儿） | ✅ `ConfigExcelImporter.ExecuteConfigOnly` |

命名行的 Display Name 在模式③置灰（不动模板）；**Class Name 三模式都可编辑**——模式②③
靠它定位目标模板。校验实时进行（重名 / 空名 / 类名不可解析 / 缺主键列 / 类名被占用或不存在 /
主键列重复 ID），错误进 HelpBox（超 6 条其余落 Console）。三模式校验全过后「Execute」按钮才可点。

### 模式①执行流（两段式落地）

根本矛盾：**新模板的 C# 类在编译前不存在**，`ConfigAssetFactory` 拿不到类型、建不了数据资产。
因此执行分两段（`ConfigExcelImporter`）：

1. **本段**（点击 Execute，编辑器域内完成）：建模板资产（默认基类 `ConfigBase`）→
   先挂 `ConfigExcelPendingImport` 载荷资产（className + 字段定义 + 全量数据行）→
   再 `ConfigTemplateCodeGen.WriteFile` 生成代码。代码生成失败也**保留模板与载荷**——
   用户修好字段后点模板编辑器的「生成代码」即可继续，不丢数据。
2. **编译后段**：`[InitializeOnLoad]` 的 `ConfigExcelPendingApplier` 在每次编辑器域加载时
   扫描载荷资产；目标类已编译出来即逐行建配置资产（`File.Exists` 幂等跳过，支持部分应用后重试），
   完成后删除载荷；类还没出来则继续等待下次域加载，不报错、不丢失。

### 模式②执行流（模板合并 + 行对账）

1. **合并模板**（`ExecuteUpdateTemplate`）：按字段名把 Excel 草拟并进既有模板——存量字段
   **原地更新**（保序，避免无谓重排引发重编译），Excel 新增的追加，Excel 没有的移除。
   改类型/删字段会打 Warning（存量资产数据可能不转换 / 变孤儿数据）。有实质变更
   （增/删/改类型/改中文名——description 进 `[Header]`）才重新生成代码；**先挂载荷再生成**，
   生成失败保留可修（同模式①次序）。
2. **对账配置行**（`ReconcilePending`，模式②③共用）：先建一次 ID → 资产路径索引（整表只扫一遍），
   然后逐行——
   - **C1 新增**：Excel 的 ID 在工程中不存在 → 建资产（ID 仍走发号服发新号，不采用 Excel 里的旧号）；
   - **C2 更新**：ID 命中存量资产 → 逐字段覆写（GUID 不动）；
   - **C3 跳过**：主键缺失/无效/资产类型不匹配 → 跳过并告警；
   - **C4 孤儿**：工程内存量资产中 ID 不在 Excel 里的 → **默认保留并报告**；执行栏的
     「Delete orphans」开关（默认关，模式①置灰）打开才删除。
   - 无主键列时退化为**按资产名对账**（首个字符串字段值 / `类名_序号`，与模式①命名规则一致）。

模板有变更时域内还是旧版类（重编译未发生），必须等编译后由 applier 用新类对账；
零变更时目标类已是当前版，立即对账并删载荷。

### 模式③执行流（仅对账，不动模板）

`ExecuteConfigOnly`：模板零接触，只按主键 ID 对账配置行（C1-C4 语义同模式②，无主键列时
窗口校验直接拦下——模式③必须有 ID 列）。目标类已在域内（模板未变、无需重编译）→ 立即对账；
类还没编译出来（如全新检出、生成代码从未编译过）→ 挂载荷等编译后由 applier 对账。

**ID 策略**：模式①的 ID **一律走发号服**（`ConfigAssetFactory` 派发），Excel 的 ID 列只是
框架列、不手填（AGENTS.md 铁律）；模式②③按 ID 对账时它才是查询键。

**配置资产命名**：取首个字符串字段的值（如 `Name` 列），否则 `类名_序号`。
单元格 → 字段值的解析规则：列表按 `|` 拆分；数值族 `Convert` + 不变量文化；Bool 接受
`true/false/1/0/yes/no`；Enum `Enum.Parse`（忽略大小写）；Reference 按 ID 找配置资产；
资源引用按资产名找（同名取第一个精确类型匹配）；结构体逐分量解析（与导出侧
`ElementText` 格式互为逆操作，容忍外层括号）。

### 已知边界

- 预览限前 200 行（IMGUI 性能），完整数据在执行时全量处理。
- `Gradient` / `AnimationCurve` 单元格导出即写空，导入同样无法还原（需回数据编辑器补）。
- 资源引用列写的是**资产名**，导入按名解析（同名歧义时取第一个，执行时按 key 去重告警——
  告警不打断创建，统一在应用结束时落 Console）。
