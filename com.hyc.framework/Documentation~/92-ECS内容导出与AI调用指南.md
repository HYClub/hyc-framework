## 零、一句话

这个模块把 **ECS 内容归档的导出、增量合并、Diff、分阶段热更新发布** 做成两件事：
给人用的 `EditorWindow`，以及给 AI / CI 用的 **`ContentExportCLI` 公共静态入口**。

AI **不要**去驱动窗口、不要点按钮、不要解析 Unity Console 文本。
正确姿势只有一条：**写 `cli-request.json` → `-executeMethod` 调无参静态方法 → 读 `last-report.json`**。

## 一、架构与心智模型

### 1.1 三层文件结构（理解这个才不会导错）

```
SourceFolder（BuildContent 的构建产物目录，本工具只从这里开始）
   │  RemoteContentCatalogBuildUtility.PublishContent(source, temp, contentSetFunc)
   ▼
发布目录 TargetFolder
   ├── <hash[0]hash[1]>/<hash>          内容文件，按文件字节 Hash128 命名，只追加不覆盖
   ├── <hash[0]hash[1]>/<hash>          full catalog（权威清单：RemoteContentId → RemoteContentLocation）
   └── catalogs.bin                     固定名「指针 catalog」，只有 1 条记录指向 full catalog
```

- 官方 `PublishContent` 每次只遍历**本次构建目录**，产出一份**本次全量快照**，**没有合并上一版的逻辑**。
- 运行期 `DefaultContentLocationService` 先读 `catalogs.bin`，再按它指向的路径取 full catalog，
  再按 full catalog 里的 `RemoteContentLocation` 去下载内容文件。
  ⇒ **CDN 上有文件、但 catalog 里没有那条记录 = 孤儿文件，运行期永远不会被请求**。
- 因此「只导一部分」的正确性不能靠"只 Publish 一部分然后直接覆盖 catalog"，
  必须把本次快照与上一版 full catalog **合并**。本模块的 `ContentCatalogMerger` 就是干这个的。

### 1.2 固定逻辑 ID / 不固定物理路径

- 逻辑 ID：官方 `new RemoteContentId(relPath)`，`Hash` 由构建产物的**相对路径**算出，
  是 catalog 的 join key。路径稳定 ⇒ ID 稳定。
- 物理路径：`Hash128.Compute(文件字节).ToString()` 取前两位做子目录，形如 `a1/a1fd...`。
  内容变了 ⇒ 文件名变了 ⇒ 旧 hash 文件仍保留，在线客户端与回滚都不受影响。
- **唯一允许覆盖的是 `catalogs.bin`**；内容 hash 文件与 full catalog 一律只追加。

### 1.3 合并与四分类 Diff

`Merge(baseline, current, removedKeys)` 按 `RemoteContentId.Hash.ToString()` 归并：

| 情况 | 处理 |
| --- | --- |
| 本次有、基线无 | Added，追加 |
| 本次有、基线有（内容 hash 不同） | Changed，覆盖 |
| 本次有、基线有（内容 hash 相同） | Unchanged，覆盖同一值 |
| 基线有、本次无、且不在 `RemovedKeys` | Kept，**保留**（这是"只导一部分"不把其他资源弄丢的关键） |
| 基线有、且 ID 在 `RemovedKeys` | Removed，从 catalog 真删条目（**不删物理文件**） |

条目集合变化后 `ContentSets[].Ids` 存的是 `RemoteContentLocations` 的**下标**，
所以 `RebuildSets()` 会整体重算，不能直接复用旧下标。

### 1.4 依赖闭包边界（重要）

remote catalog **不含依赖边**。依赖信息只存在于 `RuntimeContentCatalogData.Dependencies`
与构建期 `BuildResultsCatalogDataSource.GetDependencies(ContentFileId)`。
本版本不重建依赖闭包：共享 hash 文件发生变化时，未重建的条目仍指向旧 hash 文件
（旧文件保留 ⇒ 不会 404，但内容可能不一致）。需要严格一致时，把依赖它的条目一并纳入本次导出范围。

### 1.5 一次导出的顺序

```
布局自检 → PublishContent 到临时目录 → 读本次 catalog → 与基线合并
→ 追加新 hash 文件到发布目录 → 写新 full catalog → 最后切 catalogs.bin
```

**`catalogs.bin` 永远是最后一步**：先让所有内容文件与 full catalog 就位，
再原子地把指针切过去，避免出现"指针指到一个还没上传完的 catalog"。

## 四、AI / CI：Unity CLI 调用（本文核心）

### 4.1 为什么需要 `ContentExportCLI`

Unity 的 `-executeMethod` 只认**程序集里 `public static void`、无参数**的方法，
且 batchmode 下不能打开 `EditorWindow`、不能弹 `EditorUtility.DisplayDialog`。
所以 EditorWindow 不是可自动化的接口；本模块专门提供了 `ContentExportCLI`
（`public static class`，命名空间 `HYC.Framework.ContentExport.Editor`），
把每个动作包成一个无参静态方法，并用**文件**传参 / 回传结果。

### 4.2 三步约定

```
① 写 <工程>/Assets/HYC/ContentExport/cli-request.json   （请求，可为空 {}）
② Unity.exe ... -executeMethod HYC.Framework.ContentExport.Editor.ContentExportCLI.<命令>
③ 读 <工程>/Assets/HYC/ContentExport/last-report.json   （结构化结果）
```

- 请求文件缺失 / 解析失败 ⇒ 回落到默认请求 + HYC Settings 的项目级配置，只打 Warning，不中断。
- **每次调用都会重写 `last-report.json`**（包括 `Help`），并在 Console 打一行 `[ContentExport] ...`。
  AI **判定成败只看 `report.Success` 和 `report.Errors`，不要去 parse Console 文本**。
- 请求 / 报告均为 UTF-8 **无 BOM** 写入；读侧 `TrimStart('\uFEFF')` 容忍 BOM。

### 4.3 命令行示例（Windows / Unity 2022.3.35f1c1）

```bat
"C:\Program Files\Unity\Hub\Editor\2022.3.35f1c1\Editor\Unity.exe" ^
  -batchmode -quit -nographics ^
  -projectPath "E:\Work-SD\SnowBros" ^
  -executeMethod HYC.Framework.ContentExport.Editor.ContentExportCLI.ExportAll ^
  -logFile -
```

> 前提：宿主工程已引用 `com.hyc.framework` 包（本模块在 `HYC.Framework.Editor` 程序集里，
> 只在 Editor 下编译）。`-executeMethod` 在项目加载/编译完成后执行，脚本没编译过就调不到。

### 4.4 命令表

前缀统一为 `HYC.Framework.ContentExport.Editor.ContentExportCLI.`

| 命令 | 作用 | 关键请求字段 |
| --- | --- | --- |
| `Help` | 列出全部命令与请求/报告文件路径 | — |
| `VerifyLayout` | 镜像布局自检；漂移时重写 `.g.cs` 并触发重编译 | — |
| `WriteStatus` | 输出 Groups 条目数、当前版本、发布记录数、基线 catalog 条数、布局状态 | — |
| `ExportAll` | 全量导出（Scope=All） | `Version`、`SwitchPointer` |
| `ExportSelected` | 只导 `groups.json` 里 `Included=true` 的条目 | `Version` |
| `ExportGroup` | 只导指定文件夹及其子文件夹 | `NodeId`、`Version` |
| `ExportEntry` | 只导单个条目 | `EntryId`、`Version` |
| `DryRunDiff` | 算差异但不切指针、不写发布记录 | `Scope`、`Version`（会被清空） |
| `SwitchPointer` | **分阶段发布的「上线」一步**：把 `catalogs.bin` 指向指定 full catalog | `FullCatalogRelativePath` |
| `Rollback` | 按业务版本回滚 `catalogs.bin` | `RollbackVersion` |

`Scope` 可写 `all` / `selected` / `group` / `entry` **覆盖命令自带范围**；
留空则用命令默认范围；非法值静默回落，不打断 CI。

### 4.5 `cli-request.json` 字段（`ContentExportCLIRequest`）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `Scope` | string | 见上；默认 `""` |
| `NodeId` | string | `ExportGroup` / `Scope=group` 时的 `ContentExportGroupNode.Id` |
| `EntryId` | string | `ExportEntry` / `Scope=entry` 时的 `ContentExportGroupEntry.Id` |
| `SourceFolder` | string | 覆盖构建产物目录；相对路径按**工程根**（`Assets` 的父目录）解析 |
| `TargetFolder` | string | 覆盖发布目录 |
| `Version` | string | 业务版本号，写进 `releases.json`；`DryRunDiff` 会强制清空 |
| `Channel` | string | 渠道，仅作记录 |
| `DefaultSetName` | string | `contentSetFunc` 匹配不到规则时的兜底 content set |
| `SwitchPointer` | string | `"true"` / `"false"`，覆盖 HYC Settings 的同名开关 |
| `FullCatalogRelativePath` | string | `SwitchPointer` 用，形如 `a1/a1fd...` |
| `RollbackVersion` | string | `Rollback` 用，`releases.json` 里的 `Version` |
| `RemovedKeys` | string[] | 要真删的 `RemoteContentId.Hash.ToString()`（即 Diff 的 `Key`），**不是名字也不是路径** |

最小请求：

```json
{
  "Scope": "group",
  "NodeId": "g-ch1",
  "Version": "v1.0.1",
  "SwitchPointer": "false"
}
```

### 4.6 `last-report.json` 字段（`ContentExportReport`）

| 字段 | 含义 |
| --- | --- |
| `Command` / `Timestamp` / `Success` / `Message` | 本次命令、时间、成败与摘要 |
| `LayoutFingerprint` / `LayoutMessage` | 官方字段树指纹与自检说明 |
| `CatalogPath` / `FullCatalogRelativePath` / `EntryCount` | 新 full catalog 的绝对路径、发布目录内相对路径、条目数 |
| `Added` / `Removed` / `Changed` / `Unchanged` | 四分类 Diff 计数 |
| `NewHashFileCount` / `NewHashFiles` | 本次追加的内容 hash 文件（**上传 CDN 的清单**） |
| `OrphanFiles` | CDN 上有、catalog 未登记的文件（保留供回滚，别删） |
| `Steps` / `Log` / `Errors` | 步骤、运行日志、异常堆栈 |

### 4.7 典型流程（AI 照着做）

```
1. 写 cli-request.json（最小可只写 {}）
2. VerifyLayout        → Success=true 才继续；false 且 LayoutMessage 提到"重编译"⇒ 等 Unity 编译完重跑本步
3. WriteStatus         → 确认 Groups / 基线 catalog / 当前版本
4. DryRunDiff          → 看 Added/Removed/Changed/Unchanged 与 NewHashFiles，确认范围没导错
5. 按 NewHashFiles + FullCatalogRelativePath 把文件上传到 CDN（本工具不负责上传）
6a. 一键上线：把 SwitchPointer 设 true，跑 ExportAll / ExportSelected / ExportGroup / ExportEntry
6b. 分阶段上线：SwitchPointer=false 导出 → 上传 → 跑 SwitchPointer（FullCatalogRelativePath 填第 4/6 步返回值）
7. 出问题时 Rollback（RollbackVersion 填 releases.json 里的旧版本）
```

> `SwitchPointer` 与 `Rollback` 都只改 `catalogs.bin`，**不动任何内容文件**，所以回滚是安全的。

### 4.8 batchmode 行为

- `Application.isBatchMode == true` 时不弹 `DisplayDialog`、不打开 EditorWindow；
  布局不一致直接按「提示 → 重写镜像」处理，日志进 Console 与报告。
- 菜单入口 `ContentExportMenu.OpenWindow()` 在批模式下只打 Warning 并 return，
  提示改用 `-executeMethod ContentExportCLI.*`。
- UI 工具栏按钮内部也是调 `ContentExportCLI`，所以点按钮同样会写 `last-report.json`。

## 六、坑（逐条都是源码里的真实约束）

1. **布局自检没有独立菜单**，导出前隐式执行。不一致只有「提示 → 确定 → 更新」一条路径，
   没有「忽略 / 取消」分支。原因：官方 `RemoteContentCatalogData` 是 internal，
   本模块用镜像 struct 解释 Blob 内存，而 `TryRead` **不校验 `sizeof(T)`**，布局漂移会静默读错。
2. **镜像更新后必须重跑命令**：重写 `.g.cs` 需要 Unity 重编译，当前 AppDomain 里仍是旧镜像类型，
   所以本次导出会主动终止并给出「Unity 重编译后请重新执行」。
   AI 看到 `Success=false` + 这条 `Message` 时**不要改代码**，等编译完成后重跑即可。
3. **旧 hash 文件一律不删**：在线客户端、缓存命中、回滚都靠它。只有 `catalogs.bin` 允许覆盖。
4. **`catalogs.bin` 最后切**：导出默认 `SwitchPointer=true`；分阶段发布必须显式设 false，
   等 CDN 传完再调 `SwitchPointer` 命令。
5. **`DryRunDiff` 不是纯只读**：它仍会跑 `PublishContent`、追加新 hash 文件、写新 full catalog 到发布目录；
   只是**不切 `catalogs.bin`、不写发布记录**。别把它当"零副作用预览"。
6. **`contentSetFunc` 返回 `null` 是跳过**，不是"归属默认组"。范围外的文件根本不会进本次 catalog。
7. **URL 根必须一致**：`RemoteUrlRoot` 只是记录，不参与文件生成；
   运行期 `ContentDeliveryGlobalState` 拼出的 URL 根必须与它一致，否则 catalog 里的相对路径全会 404。
8. **本工具不调用 `BuildContent`、不上传 CDN**：假定构建产物已在 `SourceFolder`，只写本地发布目录。
   上传是外部流程，清单取自 `report.NewHashFiles` + `report.FullCatalogRelativePath`。
9. **依赖闭包不在 remote catalog 里**：只导子集时，未重建条目继续指向旧 hash 文件；
   共享 hash 内容变化需要把所有依赖它的条目一并纳入导出范围（见 §1.4）。
10. **`RemovedKeys` 用的是逻辑 ID hash**（`RemoteContentId.Hash.ToString()`），写名字或路径不会生效。
11. **AI 别解析 Console**：Console 只有一行摘要，结构化信息全在 `last-report.json`。
12. **沙箱禁 C# 编译**：本模块所有 Unity API 均已对照 `com.unity.entities@1.0.16` 源码与
    2022.3.35f1c1 安装目录 XML 取证，但**真正编译与真实 catalog 往返必须在 Unity 里验证**。

## 七、本版本边界（不要过度解读）

| 项 | 本版本状态 |
| --- | --- |
| `NamingTemplate` / `PinLogicalId` / `LastHash` / `AssetPath` / `Address` | **声明式元数据**，供窗口展示与构建脚本消费；本版本**不重写构建产物文件名**。原因：`RemoteContentId` 由官方 `PublishContent` 按产物相对路径算出，改名会换 ID、破坏内容间引用。固定命名应在 `BuildContent` 阶段保证输出路径稳定 |
| `Channel` / `RolloutPercent` / `CompatibleSince` | 只写入 `releases.json` 作为发布记录，**没有灰度下发引擎** |
